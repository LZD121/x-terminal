<objective>
Repair the read path this build actually uses, after the upstream drifted under it: bare `x-terminal` (the Following feed) and `/` search are refused today, and the refusal is a request-shape rejection this client causes rather than a session or network problem.

Purpose: two measured drifts, both invisible to an operation-id refresh. (1) Three operations now demand variables the client does not send — `HomeLatestTimeline`/`HomeTimeline` and `UserTweets` refuse `422 GRAPHQL_VALIDATION_FAILED must be defined path:["variable",…]` until `includePromotedContent` (and, for `UserTweets`, `withVoice`) are present; the same is true of `TweetDetail`, whose complete required set is not yet known and has to be measured. (2) `SearchTimeline` answers `404` with a zero-byte body over GET and `200` with real results over POST, with the same query id, the same variables, the same features, the same field toggles and the same headers — so the *wire method* is now a per-operation property. `doctor --refresh-ids` cannot see either, and it should not: `go run ./cmd/x-opsgen --live` reports `+0 added, ~0 updated, 104 unchanged` against the current bundle, and the ids this build holds match it.

Rule the whole plan implements: send exactly the variables and the method a measurement supports, and make every such claim cite the measurement that put it there. No invented key, because an invented key is a claim about the upstream's contract that nothing here measured.

Output: the per-operation wire method in the request builder, the measured variable sets at the four read call sites, a `doctor --probe` that names the variable the upstream is asking for (today it prints the remedy sentence "fix the variables or features it names" without ever being able to print the name), an amended audit arm that keeps the POST honest, the amended RUNBOOK repair section, and the dated measurement record.

Scope note: this is a post-milestone repair, not a roadmap requirement. It touches the read/transport seam only. `domain.Source` and every screen stand unchanged: no signature in `internal/domain`, `internal/tui`, `internal/render`, `internal/screen`, `internal/text` moves.
</objective>

**Where the method lives, and why it lives there.** The per-operation method goes in `internal/xweb/graphql.go`, one table, because that file already owns "the request that was measured" — its `graphQLRequest` doc comment states the header set the measurements settled on, exactly like this. It does **not** go in `internal/xweb/volatile/registry.json`, and the reason is mechanical: the bundle `cmd/x-opsgen` mines carries only `{queryId, operationName, operationType, metadata}` — no method — and `Registry.Merge` replaces a whole entry with what the bundle carries while `Write` marshals the `Operation` struct, so a hand-written method field would be silently dropped the next time anyone runs `x-terminal doctor --refresh-ids`, reverting `SearchTimeline` to the GET that answers `404` with a zero-byte body. It does not go in `pins.json` either: a pin is an override the operator writes, and the shipped build has to search without one. It does not become a config key, a flag or a second mechanism: one table, one reader, in the one file that builds requests.
