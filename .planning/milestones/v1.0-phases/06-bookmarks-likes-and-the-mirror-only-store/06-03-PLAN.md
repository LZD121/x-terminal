<objective>
Land the walk and its headless caller: the incremental sync that stops at the first page with no unknown ids, the full re-list that marks rows absent instead of deleting them, the run record every later reader depends on, the mirror's owner, and the `sync` verb that makes all of it usable without a terminal.

Purpose: SAVE-04 is a rule about what a sync may not do (delete) and a rule about what it must do (stop early), and both are properties of one function that takes a fetcher and returns a result. The verb is the phase's tracer for the walk: it drives the same `Begin`/`Step`/`Abandon` the pane's `r` will drive, so the two can never diverge into two meanings of the word sync.

Output: the walk in `internal/store/sync.go` with its tests, the viewer read on the adapter, `config.SavedDBPath()`, and `internal/cli/sync.go` registered as one row in the command table.

Phase goal (ROADMAP, quoted): "The user reads their own bookmarks and likes from the active session and can open that mirror on disk with the network down — while the timeline stays structurally unable to reach disk."
</objective>

  <files>internal/store/sync.go, internal/store/sync_test.go</files>

  <action>
The walk, driven one page at a time, so the caller owns progress and the stop and the store owns the transaction and the run row.

`internal/store/sync.go` gains:
- `type SavedFetcher interface { Saved(ctx context.Context, kind domain.SavedKind, c domain.Cursor) (domain.PostPage, error) }` — declared here, by the code that calls it, exactly as `internal/xsource.GraphQLer` is: the walk must not import the adapter or the transport, and a fake fetcher is what makes the whole walk testable with no socket. `*xsource.Adapter` satisfies it as it stands (plan 02's method).
- `const pageCap = 40` — the bound a full re-list walks to when the list does not end first (the walk is otherwise bounded by the end of the list, by the session budget at the transport, and by the caller abandoning it). Name it in one place with a comment saying it is a cap and not a target.
- `type run struct { st *Store; fetch SavedFetcher; kind domain.SavedKind; full bool; started time.Time; cursor domain.Cursor; pages, added int; seen map[domain.PostID]bool }` implementing `domain.SyncRun`, with `Step` and `Abandon` as below, and the `Mirror` type that starts runs:
  `type Mirror struct { st *Store; fetch SavedFetcher; viewer Viewer }`, `func NewMirror(st *Store, fetch SavedFetcher, viewer Viewer) *Mirror`, `var _ domain.Mirror = (*Mirror)(nil)`, with `Page` and `Status` delegating to the store's reader and `Begin(ctx, kind, full) (domain.SyncRun, error)` opening a run.
- `func (m *Mirror) Begin(ctx, kind, full)`: reads the session's own account through `viewer.Viewer` (Task 2 wires the owner rule; Task 1 opens the run and lets the caller step it), records `started` from a package-level `var now = time.Now` (frozen in tests), and returns the run.
- `func (r *run) Step(ctx context.Context) (domain.SyncProgress, error)`: if the run is already done, return its last progress with no request; otherwise fetch one page at `r.cursor` through the fetcher, and on a fetch error record the run's own row with `StopFailure` (leaving the last-success row alone) and return the error unchanged. On success: build `[]domain.SavedItem` from the page's posts with `Kind: r.kind`, `SortIndex` from the post's own position (the page's order is the sort order: use the post id's index in the page, or the upstream sort index if the adapter carries one — state the choice in the comment), `FirstSeen`/`LastSeen` at `r.started`, `Present: true`; call `st.Upsert` and add the returned count to `r.added`; mark every id in the page seen; advance `r.cursor` to the page's `Next`; count the page.
  Then decide `Done` and the stop reason in this order: `Next` empty -> `StopEndOfList`; `added == 0` for the page just written and `!full` -> `StopNoUnknownIDs` (the incremental rule: the first page that adds nothing new ends the walk); `pages >= pageCap` -> `StopPageCap`; a repeated cursor (`Next` already used) -> `StopStalled`. When done, finish the run: for a full walk call `st.MarkAbsent(ctx, kind, r.started)` and carry its count into both the result and the final progress, then `st.RecordRun` with the run's `domain.SyncResult`; for an incremental walk record the run with no mark and an absent count of zero. Return `domain.SyncProgress{Kind, Pages, Added, Absent, Full: r.full, Done: true, Stop}` — the final progress carries the run's own outcome, so the pane needs no second call.
- `func (r *run) Abandon(ctx context.Context, stop domain.StopReason) error`: the caller's own early stop — a popped frame, a spent budget, a stalled cursor it saw first — records the run row with that reason and marks nothing absent (an abandoned full walk is not a completed one, and marking rows on it would report as "gone from x.com" what was merely not walked).

`internal/store/sync_test.go` — the tracer's own end-to-end walk with a fake fetcher (a slice of pages plus a call counter, defined in this test file):
- a two-page walk: page one carries two posts, page two carries one known and one unknown; the run adds 3, `Step` reports `Done` with `StopNoUnknownIDs` after page two only if it added nothing — assert the exact stop the pages produce, and assert `Page` returns the posts newest-first with the mirror's own cursor;
- an incremental walk whose first page adds nothing stops after exactly one fetch (call count 1) with `StopNoUnknownIDs`;
- a walk that reaches the end of the list stops with `StopEndOfList` and the reader's `Next` is empty;
- the run's row is in `sync_runs` after each walk with its pages, items, absent and stop reason, and `Status().LastSuccess` moved for a successful walk and did not for a failed one.

Avoid: a second walk implementation, a stop condition decided by the caller that the run can see for itself, a step that writes a page it could not decode, and any clock read inside the run other than the injected `now`.

`internal/xsource/user.go` gains `func (a *Adapter) Viewer(ctx context.Context) (domain.User, error)`: one `GraphQL` call naming the `Viewer` operation with no variables, parsed with the same `ParseUser` `whoami` already uses, returning the account the session belongs to. The adapter's doc comment says what it is for: the mirror records whose list it holds, and the sync is the only caller. (`internal/cli/whoami.go` keeps its own direct call; this plan does not touch it.)

`internal/store/sync.go`:
- `type Viewer interface { Viewer(ctx context.Context) (domain.User, error) }` — the store declares the one read it needs of the session's identity, and the adapter satisfies it.
- `Mirror.Begin` now uses the viewer: it makes exactly one `Viewer` read per run (the cost is one request per sync, visible on the budget line like every other request), and then:
  - `Status().Owner` empty (a mirror that has never been synced): `SetOwner(user.ScreenName)` and continue;
  - the owner equal to the session's handle: continue;
  - a different handle: refuse before any page is fetched, returning `ErrWrongOwner` — an exported sentinel declared in this file, carrying both handles in its message — so the caller can render the `wrong account` capability state with the mirror's own words (06-UI-SPEC.md's capability table). One request is spent, no page is walked, no row is touched, and the offline read keeps working — only the sync is refused.
  A viewer error is returned unchanged (it is already a named state) and no run row is written, because no run started.
- The stops Task 1 did not exercise: a page cap reached mid-walk finishes the run as a *successful* walk (`StopPageCap` counts as success for the last-success row, because the walk did reach its bound and marked the rows it did not see — say so in the comment), and a repeated cursor ends the walk as `StopStalled` rather than looping. A `Step` after `Done` is a no-op that returns the last progress and issues no request.

`internal/store/sync_test.go` adds:
- the never-delete rule at the walk's level, which is the phase's load-bearing claim: seed the mirror with three rows for `Bookmark` (two of which the fake fetcher's full walk returns), run `--full` to the end, and assert (a) the third row is still in the file — count it through the test's own read-only handle — (b) `Page` no longer returns it, (c) `Status().Absent` is 1, (d) the run's `Absent` count is 1 and its stop is a successful one, and (e) a later incremental walk that fetches a page carrying that post again returns it to `present = 1` and the reader shows it again;
- a post that disappears upstream is not rendered: after the full walk, the reader's page has exactly the two posts the walk saw;
- the page cap: a fake fetcher that always answers with one new post and a non-empty next cursor stops at `pageCap` pages with `StopPageCap` and the mirror holds exactly `pageCap` posts;
- a fetch failure mid-walk: page one lands, page two fails; the run records `StopFailure`, `Page` still returns page one's posts, the run's row is in `sync_runs`, and the last-success row is unchanged;
- `Abandon` after one page: the run row says `StopAbandoned`, `Absent` is 0, and no row was marked;
- the owner rules: a fresh mirror records the viewer's handle as its owner; a second run with the same viewer proceeds; a run with a different viewer is refused with an error naming both handles, the fetcher's call count does not move (no page was fetched), and `Status().Owner` still reads the first handle.

Avoid: an owner check that runs after a page is fetched, a mark-absent on an abandoned walk, a page cap that is also the incremental walk's stop, and any place that deletes a row.

`internal/config/config.go` gains `func (c Config) SavedDBPath() string`: `saved.db` under `DataDir`, beside `PinsPath()` and `NoticePath()`, empty `DataDir` returning the empty string exactly as those two do. The path lives here for the reason those two do: the verb, the pane and (in Phase 8) `doctor` must not be able to disagree about where the mirror is.

`internal/cli/sync.go` — the verb's body, composed the way `feed.go` and `whoami.go` are:
- Flags: `--full` (a full re-list instead of the incremental walk), `--kind bookmarks|likes` (one kind; absent means both), `--json` (one JSON object per kind instead of the lines), `--quiet` (nothing on success; diagnostics still go to stderr). An unknown flag or a `--kind` that is neither word prints the usage to stderr and returns `ExitUsage`.
- Composition: `config.Load()` (warnings to stderr, never into stdout's data), `session.Load(cfg.SessionPath)`, `newAPIClient` (the package's existing seam), the store opened at `cfg.SavedDBPath()` through a package-level `var openMirror = func(path string, fetch store.SavedFetcher, viewer store.Viewer) (*store.Mirror, io.Closer, error)` so a test can drive the whole verb with a fake fetcher and a temp file and no network, and the adapter built over the client (`xsource.New(client)` satisfies both the fetcher and the viewer).
- The walk: one `Begin`/`Step` loop per kind, sequential, never concurrent — the limiter's floor is per account, and two walks at once would only spend the budget in a different order. A step error ends that kind's walk and is reported as the kind's outcome (the named state from the classifier, through the same mapper the pane uses); the process then continues to the next kind only if it is a *different* kind and the error is not a process-wide stop (a soft ban, a spent budget or a stopped session ends the verb for both kinds). Exit code 0 when every kind's walk stopped successfully, 1 otherwise.
- Output, per kind, on stdout: the kind's word (`bookmarks`/`likes`), the pages walked, the items added, the rows marked absent, the stop reason in `domain.StopReason`'s own words, and the mirror's path — the shape `doctor` prints its facts in (a label column and a value column), one line per kind, plus the mirror's path once. `--json` prints one object per kind with the same facts as fields. Never a post body, never a handle the mirror holds, never a cookie, never the session summary.
- `internal/cli/cli.go`: one new row in the `commands()` table — `{Name: "sync", Usage: "sync     fill the saved mirror from x.com (--full re-lists, --kind picks one list)", Run: Sync}` — and nothing else in that file.

`internal/cli/sync_test.go`: the verb driven end to end with a temp data directory, a fake fetcher and a fake viewer, with `openMirror` replaced:
- the incremental case: the fake serves one page of two unknown posts and a second page that adds nothing; assert the fake's call count is 2, stdout names `bookmarks`, `2` items, the stop reason and the file's path, and exit code 0; assert the file now exists and a second run of the verb (same fake) adds nothing and exits 0;
- `--full`: a fake that serves three pages and then an end-of-list, with one seeded row absent from the answers; assert `3 no longer saved`-shaped facts on stdout (the absent count), exit 0, and the seeded row still in the file;
- a failing fetch: exit 1, the kind's named state on stderr, and stdout carrying no post text — assert by grepping the captured stdout for the fixture's text, which must not appear;
- the owner refusal: a second viewer with a different handle exits 1 with both handles named and the fake fetcher's call count unchanged;
- `--kind likes` with a fetcher whose `Likes` arm returns the registry's unknown-operation error exits 1 with the named state and does not touch the bookmarks rows;
- `--quiet` prints nothing on success and `--json` prints one object per kind whose fields are the same facts.

Avoid: a second sync path (the verb must call `Begin`/`Step`/`Abandon` and nothing else), a post body in any output, a concurrent walk, and any flag that changes what a sync *means* rather than which one it is.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the verb's stdout/stderr -> a pipe or a log | the mirror's contents and the session must not cross here |
| the session's account -> the mirror on disk | a session for a different account must not silently mix two lists |
| the network walk -> the user's file | pages arrive from an untrusted upstream and are written |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-08 | Information disclosure | `internal/cli/sync.go`'s output | high | mitigate | The verb prints presence facts only — kind, pages, items, absent, stop reason, path — and its test greps the captured stdout for a fixture post's text and for a session-shaped value, both of which must be absent |
| T-06-09 | Tampering | the full re-list | high | mitigate | A row is never deleted: `MarkAbsent` is the only thing a full walk does to rows the walk did not see, the test counts the table's rows through a second handle before and after, and `grep -c 'DELETE' internal/store/*.go` is asserted to be 0 |
| T-06-10 | Denial of service | a walk that never ends | medium | mitigate | The walk is bounded four ways — the end of the list, the page cap, the session request cap at the transport, and the caller's `Abandon` — and a repeated cursor ends it as `StopStalled` instead of looping |
