`internal/xsource/capture_test.go`: one new gated case, `TestCaptureBookmarks`, opt-in exactly as Phase 4's harness is (`X_TERMINAL_CAPTURE=1`, otherwise `t.Skip` with that reason). When it is set it builds the client the way `internal/cli` does (`config.Load` -> `volatile.Load(cfg.PinsPath())` -> `session.Load(cfg.SessionPath())` -> `xweb.NewClient(cfg)`), issues exactly one `GraphQL` call naming the operation `Bookmarks` with the request variables Task 1 fixes below, asserts the call count is one, rewrites the viewer's own account id and handle (read from the loaded session) to the fixed placeholders `0` and `redacted`, replaces every post body with synthetic text of the same length, writes the body to `internal/xsource/testdata/fixture-bookmarks.json`, and rewrites that file's provenance row (bytes, sha256, capturedAt from the injected clock, and a `redaction` sentence naming both rewrites). If no live session is available the fixture is written as a synthetic body in the recorded envelope shape and its provenance row says `source: "synthetic"` and why — the decoder and the fake are driven the same way either way, and the summary records which happened.

`internal/xsource/testdata/provenance.json`: the same document Phase 4's harness maintains (one row per fixture: operation, capturedAt, bytes, sha256, source, sourceFile, redaction, notes, plus the variables the request carried). Extend it; do not write a second provenance file. The Bookmarks row's `notes` records the request variables and what the answer's entry kinds were, so a later reader can tell a shape change from a decoder bug.

`internal/xsource/saved.go` — the adapter's read, deliberately thin:
- `const ( opBookmarks = "Bookmarks"; opLikes = "Likes" )` with a doc comment saying both are names rather than ids for the reason `home.go` already gives: an id is valid only until x.com ships a new bundle, and an operation the registry does not have is a typed error from the client's lookup, never a fallback.
- `func (a *Adapter) Saved(ctx context.Context, kind domain.SavedKind, c domain.Cursor) (domain.PostPage, error)`: picks the operation name from the kind (`domain.Bookmark` -> `opBookmarks`, `domain.Like` -> `opLikes`), issues one `GraphQL` call with the request variables the capture recorded (a count of 20, the cursor as a string with an empty one for page one, and whatever the recorded request carried beside them — the variables are the measured request, not a guess), parses the body with the same timeline parser `Home` uses, and returns `domain.PostPage{Posts, Next, Requested, FetchedAt: now()}`. A non-success answer is passed through unchanged: the transport has already classified it into a typed `*xweb.APIError` that names its state, and re-wrapping it here would put this package between the caller and the sentence the user needs.
- A kind this build does not know is a named error naming the kind, not an empty page.
- `var _ domain.Source = (*Adapter)(nil)` in `home.go` now covers the new method: if the port's shape and the adapter's disagree, the package fails to build.

`internal/xsource/saved_test.go` — driven by the recorded body with no socket:
- the fixture decodes to a page whose posts are in the answer's order, with non-empty ids, handles and text, and whose `Next` is the cursor the answer carried (the same "bottom cursor from the last item" semantics the home timelines use);
- the request the adapter built carries the operation name `Bookmarks`, a count of 20 and an empty cursor for page one, and a non-empty one for the page after it: assert on the variables the fake `GraphQLer` recorded, so the test proves the request and not only the response;

- an error from the caller's `GraphQLer` comes back unchanged (identity, not a re-wrap).

Avoid: a query id literal anywhere in the package (the registry is the only place one lives), a second HTTP path, a decoder branch that special-cases the saved lists, and a fixture without a provenance row.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| x.com -> `internal/xsource` | an untrusted payload carrying the viewer's own identity and the exact set of posts they saved |
| the local session file -> a checked-in fixture | the viewer's identity must not cross into the repository |
| the user's `pins.json` -> the registry | hand-written data decides which operation id is requested |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-05 | Information disclosure | `internal/xsource/testdata/*.json` | high | mitigate | The capture rewrites the viewer's account id and handle to fixed placeholders and replaces post bodies with synthetic text of the same lengths; the provenance row records both rewrites; the fixture test asserts the real handle and every captured body are absent under `testdata/`, and no cookie value can appear because the harness never writes the request headers |
| T-06-06 | Spoofing | the `pins.json` overlay | medium | mitigate | A wrong pin cannot be mistaken for an empty list: the wrong-id arm asserts the named stale-operation state with a non-nil error, and an operation the registry does not hold is refused before a request is issued (call count zero) |
