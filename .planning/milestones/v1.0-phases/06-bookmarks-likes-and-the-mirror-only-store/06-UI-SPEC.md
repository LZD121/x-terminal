# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This document is an extension of `.planning/phases/02-following-timeline-in-the-pane/02-UI-SPEC.md`.** That
file is the design authority: the block layout, the width model and `A4`–`A7`, the colour ladder and
`A1`–`A3`, the status line's field mechanics, the frame stack, the help overlay, the `keys` subcommand and
the golden-frame discipline are **unchanged and binding here**. This file states only what Phase 6 changes,
adds, or must amend. A convention that is not restated is inherited, not re-opened.

**Authority above this file:** `06-CONTEXT.md` (the phase's implementation decisions, written after this
contract was first drafted and reconciled against it on 2026-10-14) and `03-CONTEXT.md` (the cover seam).
Where this contract deviates from `06-CONTEXT.md`, the deviation is named inline with its reason. There is
one, in `## The Status Line`, and it is about which field carries a fact.

## Design System

**Notes.**

- **A saved frame is the same list over a different read.** `b` and `l` push a `screen.List` frame whose
  kind is `Bookmarks` or `Likes`; the reducer, the pagination trigger, the stall rule, the dedupe, the
  anchor and the frame restore are Phase 2's, unchanged. What differs is where the pages come from — the
  mirror, always (`06-CONTEXT.md`: "The pane never fetches on open") — and that a sync is a key away.
- **Every user-visible string is still a named constant in `internal/render/copy.go`**; every
  cover-respellable literal is still a `MarkerSet` field. This phase adds two `MarkerSet` fields (the sync
  field's two forms) and no other string source.
- **No new environment branch.** The colour rung, the `$TMUX` width dispatch and the `NO_COLOR`/`TERM=dumb`
  rules are read once at start-up exactly as Phase 2 defined. This phase reads no new variable.
- **`sync` is a verb, and the pane's `r` is the same operation.** `x-terminal sync [--full]
  [--kind bookmarks|likes]` is the headless path (`06-CONTEXT.md`); its output is CLI text with its own
  presence-facts shape, and it is **not** screen copy: no string in this contract is the verb's output, and
  no string from it appears on the line. The one thing they must agree on is what a sync *is* — the walk
  described in `## The Status Line` — so that pressing `r` and running the verb can never mean two
  different things.

## Spacing Scale

**No new layout value.** Phase 2's table stands: `xs` = 1 cell (the selection column), `sm` = 2 cells (the
body indent, the quote prefix, the status-line field separator), `md` = 16 cells (the identity column, the
help key column), `lg` = 1 blank row (the block separator). `xl`/`2xl`/`3xl` stay reserved and unused.

The new work uses: `xs` (the `>` of a mirrored row — a mirror row is ordinary and gets no second mark),
`sm` (the state block's third line, at the body indent; the status line's new field separator), `md` (the
identity column of a mirrored row, which fits every legal handle), `lg` (the separator between mirrored
blocks).

Exceptions: none beyond Phase 2's two.

| Destructive confirmation | none — this phase performs no destructive action, and `SAVE-04` forbids the mirror from deleting a row: a full re-list marks rows `present = 0` instead |

**The status line's vocabulary** (see `## The Status Line` for the field order and the drop rule):

| Field | Copy |
|-------|------|
| `state` | Phase 2's classifier states, unchanged, **plus** the three capability states below |
| `remedy` | Phase 2's remedy column, unchanged, plus the three capability remedies below |
| `notice` | Phase 2's notices plus the sync strings above |
| `list` | `following` / `for you` (unchanged) plus `bookmarks` / `likes` |
| `synced` (**new field**) | `never synced`, or `synced {stamp}`; see below |
| `position` | `{selected}/{loaded}` plus `+` while the mirror holds rows that are not loaded |
| `budget` | unchanged; never dropped (`OPS-02`) |

**The `synced` value's resolution falls with age**, so that the field answers "is this current?" without the
reader doing arithmetic, and stays short enough to survive at 80 columns:

| Age of the last successful sync | Value | Cells |
|--------------------------------|-------|-------|
| today | `synced 15:04` | 12 |
| earlier this year | `synced Jan 02` | 13 |
| an earlier year | `synced Jan  2006` | 16 |
| no successful sync ever | `never synced` | 12 |

`[INFERENCE]` the year form's exact spelling; it reuses Phase 2's own stamp vocabulary (`Jan 02  2006`) with
the day dropped, and the planner fixes it against the stamp formatter. Nothing here is relative: no `2h ago`,
no `today` — Phase 2 rejected relative stamps and this field keeps that rule while losing only the
*precision* that a staleness question does not need. The frame stays a pure function of state, width and the
injected clock (`A5`).

**The three capability states** are not classifier outcomes — they are facts about this build and this
machine — so they get their own closed table rather than a `domain.FailureKind`: that taxonomy is closed to
the classifier and the reachability check, and widening it would let a "we never dialled" state pose as a
"we dialled and this happened" one. They print in the same two slots, with the same separator, and obey the
same stickiness rule as failures.

| `state` | `remedy` | When |
|---------|----------|------|
| `bookmarks unavailable` / `likes unavailable` | `doctor --pin, then restart` | the list's operation id is not in this build's registry: no request was made and none can be. The pin file is read at start (`internal/cli/doctor.go`), which is why the remedy names the restart |
| `wrong account` | `delete saved.db to re-point it` | the session's account is not the mirror's owner (`06-CONTEXT.md`: the mirror records `meta.owner`). The offline read keeps working; only a sync is refused |
| `mirror unreadable` | `move saved.db aside, then sync` | `saved.db` exists and cannot be opened or read (corrupt, locked, a schema from a newer build) |

**One deviation from `06-CONTEXT.md`, deliberate.** The peer decision
says the never-synced and last-sync-failed cases are carried by the `notice`. This contract puts them in the
`synced` field and in the state pair instead, because the notice is the **first** field dropped: at 80
columns a frame with a failure state has fewer than 20 cells left for it, so a never-synced or
long-stale mirror would be *silent* exactly when a user is looking at rows that are days old. The
information is the same; only its field changes, and every value the peer named still appears (`never
synced` is the field's value, `{n} no longer saved` and the sync outcomes stay in the notice because they are
genuinely news).

**The unverified surface, said honestly.** The research records the likes endpoint as `[UNVERIFIED]`
(`.planning/research/SUMMARY.md`, `FEATURES.md`), and `06-CONTEXT.md` makes the call a measurement, not an
argument. The screen never editorialises about it: it states the presence fact it actually has (an empty
answer, or no operation id, or the classifier's own word for what came back) and the repair. Anything else —
"this endpoint may not exist" — would be the app guessing at X's behaviour in a sentence the user cannot act
on, which `doctor`'s "presence facts only" rule (`OPS-03`) exists to prevent.

## Screen Grammar

### A saved-item row is a timeline row

**The row does not change.** A block from `bookmarks` or `likes`, read from `saved.db`, is rendered by Phase
2's block layout character for character: head row (`{handle:16} {stamp:12}`, then markers at two-space
spacing), body at the 2-cell indent wrapped to `min(W-3-2*depth, 96)`, `attachment: …`, `> ` for quotes, one
blank row between blocks, `>` plus reverse video on the selected block. `06-CONTEXT.md` states the rule
directly — "a bookmarked post looks exactly as it does in the timeline, because it is the same post" — and it
is also the correct reading of the content/presentation split:

1. **A bookmark is a post.** A row that looked different would be a claim about the post, and `REND-01`
   forbids that class of chrome. The core value — nothing on screen may look like social media — is served
   better by a saved row that is plain text than by a saved row with a bookmark mark on it.
2. **The distinguishing facts belong to the frame.** Which list and how fresh the mirror is are facts about
   the read, and the read is described by the status line; putting them on the row would repeat a word
   twenty times.
3. **It keeps the split honest.** The row stays a function of the `domain.Post` and the `Grammar`; if it
   depended on which list it sits in, every block would carry a second input and `P1` would have a second
   axis to prove.

### Where the frame's provenance is shown

`06-CONTEXT.md` decides the read model, and this contract takes it as given: **a saved frame reads the mirror
on open and issues no request**; the network is read only by a sync (`r`, or the `sync` verb), and after a
sync completes the frame re-reads the store so that what is on screen is exactly what is on disk. The
consequences for the screen, all of them testable:

- **A row that came from the network is unrepresentable on a saved frame.** Not "not rendered" — the walk
  writes to the store and the frame reads the store, so there is no code path that puts a fetched page into a
  saved frame's list. That is the strongest form of "No frame renders a saved row as though it came from the
  network" (`06-CONTEXT.md`).
- **The network read is visible while it happens**: `syncing, {n} new` in `notice` while the walk runs.
- **The mirror's age is a field**: `synced {stamp}` / `never synced`, present on every saved frame, muted,
  written from the last successful run in `meta`. This is the answer to "is this list current?" and it is the
  one fact a saved frame carries that no other frame does.
- **The last sync's failure is the state pair**, Phase 2's own vocabulary, unchanged: `rate limited`, `no
  route to x.com`, `endpoint retired`. The field keeps the *last success*'s stamp while the state says why
  there is nothing newer — the two together are the whole truth, and neither is droppable before the other.
- **A failed page changes nothing on disk** (`06-CONTEXT.md`): the rows stay, the state goes to the line.
- **Nothing on the frame says "mirror" beyond that field.** No badge, no banner, no per-row mark, no
  different separator: the list reads like the timeline it is.

### The state block: one new line, in one new case

Phase 2 renders a failure with nothing to show as a two-line block: the state word as the head line, the
classifier's own remedy sentence as the body. On a saved frame whose mirror holds no rows there is a **second**
question — "where are my bookmarks, then?" — whose answer is a different fact with a different remedy, and it
must not displace the first:

```
{state word}
  {the classifier's remedy sentence, verbatim}
  nothing is mirrored for bookmarks yet - press r to sync it
```

The third line renders **only** when the state is a network failure *and* the mirror held no rows for that
list. It is demanded by `SAVE-03` (the mirror is what makes the list readable with the network down) together
with `SAVE-01`/`SAVE-02`'s honesty rule, which is Phase 2's "the pane never lies about what it is showing":
without it, a failed sync of a list that was never mirrored renders exactly like a failed sync of a list that
is merely empty. It is a third line inside Phase 2's state block, at the body indent — not a new row shape,
not a header row (Phase 2 removed those on purpose and nothing here needs one back), and not a notice field,
because the fact is not news, it is the condition of the screen in front of the user.

**The empty frame, when no request has failed.** A mirror that has never been synced has no failure to
report (nothing was dialled), so the pane shows the ordinary empty state with a body that says what is
missing and what to do: `no posts in bookmarks` + `nothing is mirrored for bookmarks yet - press r to sync
it`. A mirror that *has* been synced and holds no rows shows the same heading with Phase 2's body, `this is an
empty read that succeeded - press r to refresh` — which is true: the read (of the store) succeeded and
returned nothing. The two are distinguished by the `synced` field and by the body line, and neither is a
failure state, because neither is one.

**The likes case that cannot be resolved.** An empty successful answer for `likes` is ambiguous — empty, or
no longer served — and the pane does not resolve it (`06-CONTEXT.md`). It renders **one line and no body**:
`no likes, or the list is no longer served`. One line, because the ambiguity is about the emptiness itself;
a second line saying "an empty read succeeded" would resolve the very thing the line exists to leave open.
Bookmarks do not need the hedge: that operation is registered from a pinned external source and an empty
answer is read as "no bookmarks".

### What does not change

The grid (`H` rows of exactly `W` cells, pane rows 1..H-1, status line row H, selection column 1, no title
row, no header, no footer, no box, no rule, no logo, no version string, no hint line); the absence list (no
avatars, no display names, no `@` sigils, no engagement counts, no icons, no emoji, no inline images, no
printed URLs — Phase 7 owns those); the quote prefix and its depth cap; the truncation mark; the measure and
its cap; the empty/loading/failure blocks for every other list; the frame stack.

## The Status Line

One row, always the last row, always present, never wrapped. Phase 2's field order gains one field, inserted
after `list` so that the fields answering "what am I reading, and how current is it?" sit together:

```
{state}  {remedy}  {notice}  {list}  {synced}  {position}  {budget}
```

- **The new field is `synced`.** Present on every saved frame and on no other frame: `never synced`, or
  `synced {stamp}` in the resolution-falls-with-age form. The word (`synced`) and the never-form are
  `MarkerSet` literals (`Markers.Sync`, `Markers.SyncNever`), so a cover spells them its own way; a test
  asserts every grammar has both non-empty. A test also asserts no frame of a timeline, search or profile
  list contains either word.
- **Drop order: `notice`, then `position`, then `list`, then `synced`** — then truncation at `W` with `~`.
  `state`, `remedy` and `budget` are **never** dropped, exactly as Phase 2 says, and the new field is dropped
  last of the four, so a frame only loses its provenance statement when the alternative is truncating the
  budget.
- **Cost and thresholds.** The field is 12–16 cells plus its separator. At 80 columns the four fields that
  survive any realistic failure pair (`state`, `remedy`, `synced`, `budget`) are 32 cells of state plus
  remedy, 13 of field and 27 of budget, plus three separators — **78 cells** for the common offline pair —
  and 89 for the widest ones (`auth or signer rejected` + `add a transaction id`), where the field is the one
  that goes. That is the compromise below.

**Named compromise (extends Phase 2's).** At 80 columns, a saved frame keeps both `list` and `synced` only
while `state` + `remedy` together are 27 cells or fewer; it loses `list` first (at 28, keeping `synced`) and
the field too at 35, after which the line carries the failure and the budget and nothing about the mirror's
age. `no route to x.com  check the proxy` is 32, so `synced Jan 02` survives and `bookmarks` does not, as the
80-column frame shows; a shorter pair (`rate limited  no retry`, 20) keeps both; `session expired  copy the
cookie again` (36) drops the field. This is Phase 2's own priority order applied to one more field, and the
alternatives were rejected for Phase 2's own reasons: the state words are the classifier's and may not be
shortened, and the budget copy is `OPS-02`'s wording (`200 requests, 12 rate-limited`, not `200 req / 12`).
What survives in every frame regardless is the pair a user needs to act on — why the last sync failed, and
how much budget is left.

**Which state prints when a frame has one of its own.** The capability states belong to a list, not to the
process: while a frame whose list has one is the top frame, that state prints, and the process-wide sticky
failure is not displaced from the app — it reappears when a frame it belongs to is on top again. The reason
is Phase 2's own rule: showing `no route to x.com` beside the likes screen would claim that the likes list
was attempted, which is precisely what did not happen.

**Stickiness.** Unchanged in kind, extended in scope: a state stays until an action of its own frame
succeeds. For a capability state that means a read of that list after the pin lands (which needs the restart
the remedy names), or a sync that succeeds after the account is re-pointed; nothing else clears it. No timer
clears anything, and this phase adds no timer: the sync below is a chain of page arrivals, not a clock.

**The sync, in this one line.**

- `r` on a saved frame is **the sync**, with Phase 2's key and Phase 2's meaning ("fetch newer, keep the
  place"): read the newest page, upsert its items into the mirror, and ask for the next page while every page
  so far carried at least one id the mirror did not already hold for that kind. It stops at the first page
  that adds nothing new (`SAVE-04`; page one always costs a request and the common case is exactly one), at
  the end of the list, at a failure (the state and remedy pair, unchanged, and the walk does not retry past a
  failure whose `Retry` is false), at the page cap that bounds a full re-list, at the session request cap
  (`budget spent`, `xweb.ErrRequestCap`), or when the user pops the frame — in which case the request already
  in flight lands and **no further page is requested**.
- Progress and outcomes are the `notice` field: `syncing, {n} new` while walking, then `{n} new posts` /
  `no new posts`, `mirror complete` at the end of the list, `sync stopped (cursor stalled)` when the walk ends
  without either (a repeated cursor or a page that contributed nothing while claiming entries — Phase 2's own
  stall rule, reported instead of looped), and `{n} no longer saved` after a full re-list that marked rows
  absent.
- **A full re-list marks, never deletes** (`SAVE-04`): after walking to the end, rows the walk did not see
  are `present = 0`. They do not render as if they were still saved, and their count is said out loud —
  hiding a row the user once saved without saying how many are hidden is the same class of lie as rendering
  an empty list for a failure.
- The frame re-reads the store when the walk ends, so the count in `{n} no longer saved` and the rows on
  screen are read from the same state.
- `r` while any request is in flight is a no-op (Phase 2's debounce, unchanged), so key repeat cannot burst a
  walk, and a key whose action cannot apply reports one honest line and issues no request (`06-CONTEXT.md`):
  `r` with no session is Phase 2's own `no session file` state, `b` with an empty mirror is the empty-state
  block, `l` with a missing operation id is the capability state.
- The cost of a cold mirror is visible where every cost is visible: the budget line rises while the walk
  runs. No new cap is introduced beyond the page cap the peer decision names, and the walk cannot outlive the
  process's cap.

## Named compromises

Each of these is a cost this contract accepts, with the requirement or the arithmetic behind it.

1. **At 80 columns a saved frame can lose `synced`, and always loses `list` before it.** The arithmetic and
   the rejected alternatives are in `## The Status Line`. The field survives in the common offline frame
   (`no route to x.com  check the proxy`, 78 cells with it) and goes only in the widest failure pairs.
2. **The never-synced and last-sync-failed cases live in the `synced` field and the state pair, not in the
   `notice`.** The phase's one named deviation from `06-CONTEXT.md`; the reason is that the notice is
   dropped first and these are the two facts that matter most when the line is under pressure.
3. **A saved frame's rows are always the mirror's rows.** Even a byte-identical row that came back from the
   network in the same walk is re-read from the store, so the frame can never claim live data. The cost is
   one extra store read per completed sync, and the gain is that "renders a saved row as though it came from
   the network" is not merely untested but unrepresentable (`06-CONTEXT.md`'s own wording).
4. **A saved post that upstream has removed still renders its stored text.** The mirror is a copy of what the
   user saved, it never re-validates, and the frame says how old it is. This is the honest reading of "read
   the mirror with the network down", not an oversight.
5. **Hidden rows are counted, not listed.** `present = 0` rows are hidden and their count is a notice
   (`{n} no longer saved`); a key to reveal them is deferred (`06-CONTEXT.md`). A notice can be dropped at
   narrow widths, and the count is the only surviving evidence — so the *pane* never claims a completeness
   the mirror cannot promise: the list is what the mirror holds, and the field says how old it is.
6. **A catch-up walk can spend many requests.** Its bound is the first page that adds nothing new, the end of
   the list, the page cap, a failure, the session cap, or the user popping the frame. Its cost is on the
   budget line, its progress is in `notice`, and no second cap is invented for it.
7. **Nothing on screen proves the timeline never reached disk.** A badge would be chrome that `REND-01`'s
   absence list forbids, and an assertion is weaker than the code, the tests and the file itself. The evidence
   is named in `## Content / Presentation Split`.

## Keymap Contract

Phase 2's table, its one-source rule (`REND-05`), the help overlay and the `keys` subcommand are unchanged.
This phase adds **two rows and no others**:

| Keys | Action | Help text (rendered verbatim) | Group |
|------|--------|-------------------------------|-------|
| `b` | `bookmarks` | `open bookmarks` | lists |
| `l` | `likes` | `open likes` | lists |

- **Two keys, not a toggle**, and the reason is the table: `t`'s help text is one literal, `switch between
  following and for you`, and a key whose meaning depends on the frame on top would need two rows for one
  binding or a sentence the table cannot hold. Two destinations, two literals, and the likes list is directly
  reachable — which matters because it is the list that may not exist (`SAVE-02`). `t` keeps its Phase 2
  meaning and does not switch between bookmarks and likes.
- Both keys **push a frame** (`REND-06`): `q`/`esc` pops back to the exact list, selection and scroll the
  user left, with zero new requests — Phase 2's four restore observables hold verbatim, and the golden test
  `list@position -> b -> q` must byte-compare equal to `list@position`. `06-CONTEXT.md` states the same rule
  in its own words ("`q`/`esc` returns to what the user was reading, at the row they left").
- **`r` keeps its row and its help text** (`fetch newer posts, keep the place`). On a saved frame its
  behaviour is the sync described in `## The Status Line`. A second help literal for the same key was
  rejected: the table is one row per binding and the help overlay has no context to switch on.
- **No key reads the mirror by hand and none forces a network read on open.** The mirror is what a saved
  frame *is*; a "refresh the view from disk" key would be a second way to change what the screen reads, and
  the phase's honesty rests on there being only one.
- Nothing else is bound here. Media, links and the clipboard are Phase 7's rows, and a key that collides
  with a cover key is resolved in the cover's favour (`06-CONTEXT.md`, Phase 4's rule).

## Content / Presentation Split

Phase 2's split stands, including `P1`–`P3`. This phase extends it in three places.

### New content (`internal/domain`, never a string the renderer prints)

| Item | Owner | Notes |
|------|-------|------|
| `SavedItem` (`Kind`, `Post`, `SortIndex`, `FirstSeen`, `LastSeen`, `Present`) | content | `06-CONTEXT.md`'s shape, a new file in this package. `Kind` is checked to `bookmark`/`like`; `Present` is the `SAVE-04` flag; the post's render-ready snapshot is what makes the offline read worth having |
| `ListKind` — `Following`, `ForYou`, `Bookmarks`, `Likes` | content | which list a frame shows. `HomeKind` stays the home pair; the saved pair is a sibling, and the list's *word* remains where Phase 2 already put it (`HomeKind.String()`'s precedent, extended) |
| the last successful run (`time`, stop reason, kind) and the mirror's owner | content | read from `meta`; the screen consumes two of them — the stamp for the `synced` field and the owner for the `wrong account` refusal |
| the hidden-row count | content | the `{n} no longer saved` count, from the store, never re-derived by the frame |

Store rules the screen depends on (`06-CONTEXT.md`, with two things this contract adds):

- **The write API accepts `SavedItem` and nothing else.** A timeline post cannot be written because no
  function accepts one (`SEC-02`), and the schema-allowlist test plus the import-boundary scan keep it true.
- **The snapshot must carry the author's account id, not only the handle.** The cover aliases an account by a
  deterministic function of its id (`DSGT-07`, `03-CONTEXT.md`), so an offline read under a cover can only
  alias a row correctly if the id is on disk; storing the handle alone would force the cover to print a real
  handle (`DSGT-06`) or to invent a second alias for the same account (`DSGT-07`). `[INFERENCE]` that the id
  is all the alias function needs.
- **No counts.** `REND-01` and `06-CONTEXT.md` agree: a saved list is not a leaderboard, so the store carries
  no engagement numbers, and an unprintable column on disk would be a liability with no buyer.
- **A `present = 0` row never renders** as a live row; the count is the notice, not a marker on the row, and
  the reveal key is deferred.

### Presentation (`internal/render`)

| Element | Owner | Notes |
|---------|-------|------|
| `Markers.Sync` (`synced`) and `Markers.SyncNever` (`never synced`) (**new fields**) | grammar | the field's words, so a cover can call it a cache it its own fiction; one literal per grammar, both non-empty, asserted |
| the stamp formatter for the field | presentation | the resolution-falls-with-age rule; the same formatter family as the post stamp, so one place decides how this program spells a time |
| the `{n} no longer saved` count and the sync notices | presentation | constants in `render/copy.go`; they are news, and news is not cover-respelled because a cover's news is the same news |
| the capability states' words | presentation | constants in `render/copy.go`, **normal-mode-only**: they name `doctor`, `saved.db` and a path, and a cover must not render them (`DSGT-09`). Under a cover a frame carrying one shows the cover's own empty or unavailable state instead — see the seam note below |

### The cover seam (`03-CONTEXT.md`, Phase 3)

**Expressible at a cost of three items, and the third is the one to watch.**

1. Two `MarkerSet` fields (`Sync`, `SyncNever`) — one literal each per grammar, trivially within the seam.
2. The mirror's rows need no new seam at all: they are `domain.Post` values, so `Identity`, `Stamp` and
   `Markers` cover them, and `P3` holds (`b`, `l`, paging and `r` behave identically under a cover, with
   unchanged keys — `DSGT-08`).
3. **The capability states and the classifier's states both print `x.com`, `doctor` and a file path in
   normal mode.** Under a cover those words are leaks (`DSGT-09`: nothing may reveal the real product or its
   purpose). Phase 3 already has to solve this for the classifier's own state words (they contain
   `no route to x.com`), so this phase's three capability states **join that mechanism rather than inventing
   one**: whatever Phase 3 calls the cover-respellable state vocabulary, these three enter it, and a test
   asserts that under each cover no frame contains `x.com`, `doctor`, `saved.db` or `pins.json`. If Phase 3's
   seam turns out to cover only post and marker literals and not the status line's state words, the cost is
   three new literals per grammar plus that scan — small, but it must be planned rather than discovered.

If none of this could ride the seam, the cost would be a cover-visible English word baked into the plain
grammar's copy plus a per-screen special case for the saved frames — the failure mode `03-CONTEXT.md` names
as the reason the cover must be a renderer mode. Nothing else about the phase touches the seam.

### The privacy promise, on screen

**Nothing on screen makes the timeline-can-never-reach-disk promise visible, and nothing should.** A badge
("nothing here is stored") is chrome that Phase 2's absence list forbids, it can only *assert* rather than
*prove*, and an assertion a bug could falsify is worse than no assertion: it invites trust that has to be
earned in code. The guarantee is carried where it can be checked:

1. **structurally** — the write API takes only `SavedItem`, the schema allowlist fails on any unlisted table
   or column, the import-boundary scan proves no timeline/thread/search file may import `internal/store`, and
   a behavioural test runs a full session and inspects the data directory for stray files (`06-CONTEXT.md`'s
   three legs plus its mechanised inspection);
2. **on the frames** — no timeline, search or profile frame contains the `synced` field's words, asserted
   byte-wise over the golden corpus;
3. **on disk** — `saved.db` holds exactly the two saved lists and stays inspectable with the `sqlite3` CLI
   (`.tables`, `.schema`), which is the v1 answer to "prove it" and a line for Phase 8's runbook, not for the
   status line.
