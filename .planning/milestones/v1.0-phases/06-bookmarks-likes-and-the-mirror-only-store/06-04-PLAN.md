The walk in the pane, and the corpus that makes every claim above a stored frame.

`internal/tui/update.go` — `r` on a saved frame:
- The key is Phase 2's `ActionRefresh` and its meaning on a saved frame is the sync. It is gated exactly as Phase 2 gates a refresh: a sync already running, a page in flight, or a process-wide stop (`Deps.Failure`'s stopped state) is a no-op that issues nothing; `r` with no session is Phase 2's own `no session file` state.
- The loop: `Saved.Begin(context.Background(), kind, false)` in a command -> `syncStartedMsg` carrying the run; then one `Step` per command -> `syncStepMsg{Progress}`; each progress sets the notice to `syncing, {n} new` with the run's own running count; when `Progress.Done` the frame's sync state is finished from that same progress (its `Absent` is the count the mark returned), and the frame re-reads the mirror from page one (`Saved.Page(kind, "")`), *replacing* its rows with what comes back — so what is on screen is exactly what is on disk (06-CONTEXT.md: "the pane renders from the mirror after a sync, not from the bytes that just passed through it"). The notice becomes `screen.NoticeFor(progress)`; the `synced` field is re-read from `Saved.Status` in the same round trip, so the count in `{n} no longer saved` and the rows on screen come from one state.
- Popping the frame while a walk runs calls `Abandon(ctx, domain.StopAbandoned)` from a command: the page already in flight lands and is written, no further page is requested, and the run row says abandoned.
- A step error: `SavedError` first (`CapWrongAccount`, `CapMirrorUnreadable`), else `Deps.Failure`; the rows on screen stay exactly as they were (a failed page changes nothing on disk and nothing on screen beyond the line).
- A capability state, once set on a frame, is cleared only by an action of that frame that succeeds (a read after the pin lands, a sync that succeeds after the account is re-pointed) — no timer, and nothing else clears it. While the frame is on top its capability prints; the process-wide failure reappears when a frame it belongs to is on top again.
