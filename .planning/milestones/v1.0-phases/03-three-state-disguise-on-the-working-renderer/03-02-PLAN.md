<objective>
Wire the disguise into the running program: a new `internal/term` package that owns every terminal-side effect,
the keymap rows and the covered help wording, the two persisted config keys, the three-state model with focus
handling in the shell, and the composition root that reads the start-up state and restores the window name on
exit.

Purpose: the pure half (03-01) is inert without this one. It is also the half where the phase's hardest
constraint lives — the clear is a subprocess and the shell may not run one — so the work here is mostly about
putting I/O behind exactly one new package and one command per effect, and proving the order rather than
asserting it.

Output: `internal/term`, the new `internal/keys` rows, `internal/config`'s display keys and writer, the
three-state model in `internal/tui`, the extended import-boundary test, and the wired `feed` verb.

Requirement: DSGT-01, DSGT-02, DSGT-03, DSGT-04, DSGT-05 and DSGT-11 are this plan's `requirements` entries.

Phase goal (ROADMAP, quoted): "The user can wear the feed as work-software output or replace the pane with a
one-key panic frame — identities aliased, nothing on screen naming the real product — and step back without
losing their place."
</objective>

**Why this package exists, and why the entry carries the frame.** The UI-SPEC's ordering table requires the
frame's cells, then ED 3, then the title to be one write. Two facts about the pinned toolkit settle how that is
possible, and both were checked in `charm.land/bubbletea/v2@v2.1.0` rather than assumed: the renderer parses
the view's content into cells (`cursed_renderer.go`, the `flush` path's styled-string conversion), so an escape
sequence appended to the content is consumed by the parser and never reaches the terminal; and the renderer's
write happens on the program's ticker (`tea.go`, the renderer goroutine: the output buffer is flushed, then the
frame), while a command's result is delivered by the event loop — so no write of ours can be *guaranteed* to
land after the frame's paint. The entry is therefore one self-contained byte string, written once: each frame
row at its own absolute column 1, then ED 3, then the title. The panic state's `View` also returns the frame,
so a repaint or a resize after the entry still shows it; the second paint is byte-identical cells and is the
price of a provable order, which is recorded in the package's own comment.

**`internal/term/term.go`.**

- `func Entry(frame, title string) string` — the pure builder. For each row of the frame: the absolute cursor
  move to that row's column 1, then the row; then the ED 3 sequence (its own named constant, spelled
  `ESC [ 3 J`, which is what the probe measured; the library has no constant for it); then the title's OSC 2
  through `charmbracelet/x/ansi`'s own setter. Per-row positioning, and no newline after the last row, is
  deliberate: a row padded to the pane's full width leaves the terminal's wrap pending and a trailing newline at
  the last row would scroll the frame's first row off the pane.
- `type Sink struct { Out io.Writer; Env func(string) string; Run Runner }` where
  `type Runner func(name string, args ...string) ([]byte, error)`; the real values are the program's own output
  file, `os.Getenv` and an `exec.Command(...).Output` wrapper. A test supplies a recorder for each.
- `func (s Sink) EnterPanic(frame, title string) ` — **one** `Write` of `Entry(frame, title)`, then the tmux
  work below. Every error is swallowed: the frame is painted and ED 3 was written, and printing an error would
  be a worse leak than the missing clear. Nothing is returned for the shell to read.
- `func (s Sink) SetWindow(name string) ` — the window name follows the title in every state; it is the tmux
  rename alone, and a no-op when there is no pane.
- `func (s Sink) WindowName() string` — the name to restore, read once at start-up
  (`display-message -p '#W'`), trimmed; empty on any failure, which the caller treats as "nothing to restore".

**`internal/term/tmux.go`** — the decisions, separable from the doing, because they are what the table-driven
tests drive:

- `func Pane(env func(string) string) string` — `$TMUX_PANE`, or empty. Empty or unset means "there is no tmux
  history to clear": **no subprocess is started, nothing is reported, no error is surfaced**. The app never
  guesses a pane. `$TMUX` set with `$TMUX_PANE` empty is the same case.
- `func ClearHistoryArgs(pane string) []string`, `RenameWindowArgs(pane, name string) []string`,
  `WindowNameArgs() []string` — the three commands the UI-SPEC names, each in one place, `-t` always an
  explicit pane.
- The sink's tmux work is `clear-history` first, then `rename-window`, only when `Pane` is non-empty. A run of
  the whole sequence happens under the same one command the shell dispatches, and after the entry write.
- `[INFERENCE]`-free note to keep in the comment: the app does **not** enable tmux's server-wide
  `focus-events` option and does not read it; a user who wants focus-driven panic turns it on themselves.

**The transitions** (`update.go`) — the UI-SPEC's `## Screen Grammar` table, T1 to T13, each implemented once
and each returning the command its side effects need:

- `m`: normal → immersive wearing the remembered style; immersive → normal. Writes `display.state` (through
  `Persist`, from a command) and sets the state's title and window name.
- `c`: normal → immersive in the next style; immersive → the next style in place. Writes `display.state` and
  `display.cover`; the rows on screen do not move — the same list, the same selection and the same anchor, a
  different grammar.
- `1`–`4`: immersive in that style, from either of the two non-panic states; writes both keys.
- `ctrl+p`: from normal or immersive → panic, running the sequence below; from panic → back to the state it was
  entered from, restoring that state's title and window name and writing **nothing** to the config.
- **Entering panic** (key, blur, or the start-up state once the first pane size is known) is one function, used
  by all three callers: set the state, remember where it came from, and return a single `tea.Cmd` that builds
  the frame with `render.PanicFrame(w, h)` and the title with the panic constant and calls
  `Term.EnterPanic(frame, title)` — the write and the two tmux subprocesses are inside that one sink call, so
  the required order (frame's cells, then the clear, then the title, then the multiplexer's history and the
  window name) is the sink's own order and is what task 1's tests pin. Nothing is cancelled: an answer that
  arrives while panicked is absorbed by the ordinary path, because panic is a render state and not a network
  state. No request is issued to enter or to leave.
- **Panic is an overlay, and it swallows.** While panicked exactly two bindings exist: `ctrl+p` leaves and
  `ctrl+c` quits. Every other key — including `q`, `esc`, `?` and every movement key — is consumed with a
  no-op, so an accidental `esc` can never uncover. The help overlay does not open while panicked.
- **Focus**: the view enables focus reporting; `tea.BlurMsg` enters panic when not already panicked (a second
  blur while panicked does nothing, so the entry runs once), and `tea.FocusMsg` is a no-op in every state.
  A terminal that reports no focus simply never sends the message: the model never enters panic by itself and
  nothing on screen claims it will. Both limitations (no focus reporting; tmux's focus-events default) are
  recorded in the code's own comment, not faked.
- Quit: the bottom-frame `q`/`esc` and `ctrl+c` paths are Phase 2's, with one addition — the model is in a
  state whose title must be restored, which the composition root does after the program returns.

**The frames** (`view.go`) — the composer is not touched, only what it is given:

- Panic: the whole terminal is `render.PanicFrame(w, h)` — no status line, no help, no list, whatever the model
  underneath holds. The title is the panic frame's own name.
- Immersive: `render.Blocks(posts, style.Grammar, ...)` in place of the plain grammar, the same scrolled rows
  and the same anchor, the covered status fields (`Cover` set to the active style), the covered help wording
  when the overlay is open, and the covered empty and loading copy — the same code path, different values.
- Normal: Phase 2's frame byte for byte, including the plain status fields with `Cover` at its zero value.
- The title is a function of the state in every state — the plain reader's own name, the active style's own
  name, or the panic frame's name — set on the view, so the untitled stand-in Phase 2 left behind is gone.

**The wiring** (`internal/cli/feed.go`): build the sink (`term.Sink` over the program's output, the process
environment and the real process runner), read the tmux window name once before the program starts, pass the
config's display state and cover style (resolved through `tui.StateOf` and the render package's style lookup,
with the defaults when the value is unknown — the reader already warned), and pass `Persist` as a closure over
the config path and `config.SetDisplay`. After the program returns, restore the tmux window name from the
recorded one when there was one; a bare terminal's title is cleared by the toolkit itself, because the view set
one, which is why no query for a pre-existing title is needed or attempted. Nothing else in this verb changes:
the session, the registry, the transport and the limiter are untouched.

**Tests** (`state_test.go`, plus the shared shell helper in `tui_test.go` gaining the new fields):

- `TestStateTransitions`: one table for T1–T13 — the state before, the key, the state after, and which effects
  were requested (the entry, which title, which window name, which persist call) — with the persist assertions
  being the point: `m`, `c` and `1`–`4` write, and **no** panic entered by a key or by blur writes anything.
- `TestPanicEntersInOneFrameAndLeavesExactly`: `ctrl+p` from each non-panic state paints the panic frame in the
  very next render (asserted on the rendered frame, not on a field), a second `ctrl+p` restores the previous
  state, and the frame rendered after the round trip is byte-identical to the one before it — the model-level
  half of the restore claim, with the request count read from the fake source's own counter and asserted
  unchanged.
- `TestPanicSwallowsKeys`: every action of the table except the two bindings is a no-op while panicked, the
  help overlay does not open, and a late answer is still absorbed.
- `TestBlurPanicsAndFocusDoesNotRestore`: blur from each state enters panic once (a second blur does not run the
  entry twice), focus never leaves panic, and focus in a non-panic state changes nothing.
- `TestTheEntryIsCommandedNotCalled`: the model performs no terminal call in `Update`; the states that enter

- `TestImmersiveIsTheSameList`: for a loaded list, scrolling, the anchor, the selection and the request count

- `TestStartupStateIsTheConfiguredOne`: `New` with `panic` renders the panic frame first and commands the entry
