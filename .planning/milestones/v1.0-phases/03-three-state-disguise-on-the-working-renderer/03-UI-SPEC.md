# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **This file extends `02-UI-SPEC.md`; it is not a second design language.** Phase 2's grid, width model,
> keymap table, colour ladder, status line and Content/Presentation split are inherited verbatim. Where
> this file adds to one of them it says so in a row, and the regression test for every addition is that
> the **plain** frames stay byte-identical to Phase 2's golden frames.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | `none` — no CSS design system; a Go terminal program |
| Preset | not applicable |
| Component library | `charm.land/bubbletea/v2` v2.1.0 (runtime only) + `charmbracelet/x/ansi` v0.11.9 (SGR, width) — no widget library, unchanged from Phase 2 |
| Icon library | `none` — ASCII glyphs only; no emoji, no Nerd Font, no box-drawing characters; covers add no glyph class |
| Font | the terminal's own monospace cell; the program sets no font, size, weight or line height, in any state |

**Notes.**

- **Code-seam status at the time of writing (2026-10-14).** `internal/text` exists and was read: `Width`,
  `Wrap`, `Pad`, `Truncate` with the `$TMUX` method dispatch. `internal/render`, `internal/keys`,
  `internal/screen` and `internal/tui` **do not exist in the tree yet** — Phase 2 was in flight. This
  contract is therefore written against the seams `02-UI-SPEC.md` *fixed* (the `Grammar` value, the
  marker set, the keymap table, the golden-frame harness), and the one place where Phase 2's `Grammar`
  cannot express covers is named and extended in `## The Four Covers`. If Phase 2 landed a field this
  file deletes (`HandleCols`) or renames (`Identity`'s return type), the change is one struct field and
  its call sites; a golden frame is the acceptance test either way.
- **New package this phase adds: `internal/term`.** It owns every terminal-side effect panic needs —
  the `ESC[3J` write, the title `OSC`, and the three `tmux` subprocesses (`clear-history`,
  `rename-window`, `display-message -p '#W'`). It is a *sink*: the shell hands it values, it returns
  nothing the renderer reads. The Phase 2 AST boundary test is extended so that `internal/term` is the
  **only** package in the module that may import `os/exec`; `internal/tui` may call it through the
  effect/Cmd boundary but may not import `os/exec`, `net/http`, `database/sql`, `internal/xsource` or
  `internal/store`, exactly as before.
- **`internal/render` stays pure**, and that is a load-bearing property of this phase, not a style
  choice: **the alias function lives there, so a package that cannot write cannot write an alias
  table.** It may import `time` (to *format* an injected instant) but must never call `time.Now`, and
  must not import `os`, `io`, `path/filepath`, `math/rand` or `hash/maphash` (a seeded hash would break
  `DSGT-07` silently).
- **No registry, no third-party design assets.** Nothing is fetched, installed or themed at runtime in
  any state.
- **Every user-visible string is a named constant**: Phase 2's `internal/render/copy.go`, plus
  `internal/render/cover.go` for the covers' literals and the alias word lists, plus
  `internal/render/panic.go` for the panic frame. A reviewer must be able to read this phase's entire
  visible output in three files, and no cover may build a sentence by concatenation outside a grammar
  template.

## Spacing Scale

**Declared exception (unchanged): the medium has no pixel grid.** The unit is the **cell** and the
**row**. Values are the 4-multiple anchors of the standard scale with the cell values this layout uses.

| Token | Value | Used as | Usage |
|-------|-------|---------|-------|
| xs | 4 | 1 cell | the selection column (column 1 of every row, in every state); the handle-to-stamp separator |
| sm | 8 | 2 cells | the body indent; the quote prefix per nesting level; the covered body indent (servicelog, internal, quoted blocks); the per-line `| ` gutter (ci, body indent 0); the status line's field separator; the cover marker/timestamp columns |
| md | 16 | 16 cells (plain) / **20 cells (covers)** | the identity field: plain `{handle:16}`, covers `{handle:20}` |
| lg | 24 | 1 blank row | the block separator (plain, gitlog only) |
| xl | 32 | 4 cells | the git commit message indent (git's own convention) and the ci/panic field columns |
| 2xl | 48 | — | reserved; unused |
| 3xl | 64 | — | reserved; unused |

Exceptions, stated rather than implied:

- `xs` renders as **1** cell and `sm` as **2** cells (Phase 2's exception, unchanged): an 80-cell row
  cannot afford 8-cell gutters.
- The cover identity field is **20** cells, not 16. The alias function's longest possible single token
  is 18 cells (`mirror-buffer-99`: role ≤ 6 + `-` + noun ≤ 8 + `-` + 2 digits), so 20 leaves two spare
  and `text.Pad`'s `~` truncation stays a defensive path rather than a routine one. 20 is a multiple
  of 4, so the standard scale's own rule holds.
- The panic frame's columns are 0, 8 and 40 — the `ok`/package/duration fields of a `go test` line with
  the package field 32 cells wide. All three are multiples of 4, and none is computed from the
  content's length (see `## The Panic Frame`).
- No layout value anywhere in this phase is fractional, percentage-derived, or derived from the
  content's length. The one content-derived width Phase 2 forbade stays forbidden: a cover may not size
  a column from the longest alias in the frame.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | the terminal cell (not settable) | regular | 1 row (1.0) |
| Label | same cell | regular | 1 row |
| Heading | n/a — no state renders a heading; a heading is a banner (`REND-01`) | — | — |
| Display | n/a | — | — |

- **Zero font sizes, zero font families** — the program cannot set them. There is exactly **one** text
  attribute in the whole surface: **reverse video (SGR 7)** for the selected block, in every state.
- **Covers add no attribute**: no bold, no underline, no dim, no second weight. A cover's emphasis is
  column position and its own literal marks (a leading ISO timestamp, `commit `, `[hh:mm:ss] `, a
  `REQ-` token), which is exactly what the plain grammar does with its 16-cell identity column.
- **The panic frame carries zero SGR bytes** — not even reverse video. It is a screen of terminal
  output; real output is not styled, and a static frame that emits nothing but text is also the
  cheapest possible frame to write when someone is walking up. Asserted in `V5`.
- Line length is capped in every state (see `## Screen Grammar`): a 120-column pane never produces
  120-cell body lines.

## Color

The ladder, roles and shares are Phase 2's and are **not re-declared here**: 60% default foreground
(body), 30% `muted` (stamps, markers, status line, help key column), ≤10% `state` / `state-stop`
(**only** the state word of the status line), selection = SGR 7. Degradation rungs, `NO_COLOR` and
`TERM=dumb` behave exactly as Phase 2 specifies.

What this phase adds:

| Rule | Statement |
|------|-----------|
| No new role | A cover introduces **no** colour role, no background paint, no new attribute. The same three roles exist; only their occupants change (a cover's timestamps and markers are `muted`, its text is default, its status line is Phase 2's). |
| Accent stays reserved | `state` / `state-stop` remain reserved for the status line's state word, in both covered states. A cover may not use the accent for anything — not its record ids, not its gutters, not the panic frame. |
| Panic is monochrome | The panic frame emits no SGR at all, at every rung, including `truecolor`. Its golden frames must contain zero `ESC` bytes. |
| A1 still holds | Strip every SGR sequence from a covered frame and it must still be unambiguous: the `>` selection mark, every marker literal and the aliased identity are all characters. A cover whose meaning lives in its colour is a defect. |
| A3 still holds | In rung `mono`, a cover's fields stay delimited by punctuation or column position (key=value pairs, `commit `/`Author:` labels, `| ` gutters, table columns). |

## Copywriting Contract

Phase 2's table stands. **Under a cover, the strings below replace the plain ones; nothing else about
the status line changes** (see `## The Status Line Under a Cover`).

| Element | Copy (covered — every style) |
|---------|------------------------------|
| Primary action (unchanged action, re-worded help) | `r` — `poll for new records, keep the place` |
| Empty state heading | `no records in this view` |
| Empty state body | `the read succeeded and found nothing - press r to refresh` |
| Loading, first page | `loading records...` |
| Loading, older page (`notice`) | `loading older records` |
| New items (`notice`) | `{n} new record` / `{n} new records` / `no new records` |
| End of walk (`notice`) | `no older records (cursor stalled)` |
| Pane too narrow | `widen the pane to at least 60 columns` (unchanged — it names no product) |
| Truncation mark | `~` (unchanged, all five grammars) |
| Tombstone | per style, see `## The Four Covers` — never a blank row |
| Panic frame | no copy in the product's voice at all; it is terminal output (`## The Panic Frame`) |

**The two status-line changes, and only these two:**

| # | Change | Why it is not a lie |
|---|--------|---------------------|
| 1 | `no route to x.com` renders as **`no route to upstream`** in every covered state. The remedy stays `check the proxy`, verbatim. | The state still says a failure happened and which one; only the proper noun is replaced by the same referent's generic name. It is a rename, not a claim. |
| 2 | Any string the cover did not author — the classifier's pane sentence for a failure (`xweb.Outcome.Remedy()`) and any `netcheck.Result.Detail` — passes through a fixed substitution: the literal host `x.com` and any `*.x.com` become **`upstream`**, case-insensitively. | Same reason: the sentence is the classifier's, unaltered except for the proper noun, and no covered frame may contain the hostname. Asserted in `V2`. |

**One residual leak, named rather than hidden.** The remedy column is the classifier's own instruction
to *this user* and is rendered verbatim. Two of its rows name this program's own plumbing
(`doctor --refresh-ids`, `write the session file`, `copy the cookie again`). Re-voicing them was
rejected: the user has to be able to act on the remedy, and a remedy in the cover's vocabulary would be
an instruction that does not work. An observer reading over the user's shoulder sees a tool with a
`doctor` subcommand — nothing about the product, and nothing about the account. This is a deliberate
residue and a reviewer should accept it as one.

**Covered list names** (the status line's `list` field; the only per-style copy besides the covers'
own literals):

| Style | `following` renders as | `for you` renders as |
|-------|------------------------|----------------------|
| plain | `following` | `for you` |
| servicelog | `stream=in` | `stream=all` |
| gitlog | `branch=main` | `branch=next` |
| ci | `queue=ci` | `queue=next` |
| internal | `view=mine` | `view=all` |

Each pair is a *rename of the same referent*: the same two lists, in the same order, with the same
behaviour. The field remains droppable in Phase 2's declared drop order, and the longer covered names
cost **two more lines** at 80 columns (named in `## The Status Line Under a Cover`).

## Screen Grammar

### The three states

`normal`, `immersive`, `panic`. The **cover style** is a fourth value (`servicelog` | `gitlog` | `ci` |
`internal`) that exists in `normal` too — it is remembered there, just not worn. The **help overlay** is
a pane mode, not a state (Phase 2's rule, unchanged).

| State | What fills the pane | Status line | Terminal title (and tmux window name) |
|-------|--------------------|-------------|----------------------------------------|
| `normal` | the plain reader (Phase 2, byte-identical) | Phase 2's | `x-terminal` |
| `immersive` | the same list, rendered through the active cover grammar | Phase 2's, with the two changes above | the style's own name: `svc-log` / `git` / `pipeline` / `ops-console` |
| `panic` | the panic frame, constant, full height | **none** — the frame owns every row | the panic frame's own name: `make` |

State priority is exclusive and total: `panic` > `immersive` > `normal`. Entering `immersive` does not
push a frame; it changes what the composer is given.

**Transitions — every one, with its key or event.**

| # | From | Event (key) | To | Side effects (in this order) |
|---|------|-------------|----|------------------------------|
| T1 | `normal` | `m` (`cover`) | `immersive`, last style | title + (under tmux) window name → the style's name; `display.state` written |
| T2 | `immersive` | `m` (`cover`) | `normal` | title + window name → `x-terminal` / the saved name; `display.state` written |
| T3 | `normal` | `c` (`next-cover`) | `immersive`, next style | as T1, and `display.cover` written |
| T4 | `immersive` | `c` (`next-cover`) | `immersive`, next style | in-place style switch: same rows, different grammar; title/window name follow; `display.cover` written |
| T5 | `normal` / `immersive` | `1` `2` `3` `4` (`cover-1..4`) | `immersive`, that style | as T3 |
| T6 | `normal` / `immersive` | `ctrl+p` (`panic`) | `panic` | the four-step sequence of `## The Panic Frame`; **no config write** |
| T7 | `panic` | `ctrl+p` (`panic`) | the state the panic was entered from | title + window name restored to that state's value; **no config write** |
| T8 | `normal` / `immersive` | focus lost (`tea.BlurMsg`) | `panic` | identical to T6, except that it never writes config and never renames a window it is not asked to |
| T9 | `panic` | focus regained (`tea.FocusMsg`) | `panic` | nothing. `DSGT-04`: regaining focus does not uncover |
| T10 | `panic` | any key other than `ctrl+p` and `ctrl+c` | `panic` | swallowed: no scrolling, no back stack, no help, no title change |
| T11 | `panic` | `ctrl+c` (`quit`) | process exit | the title/window name are restored as at T13 |
| T12 | any | `q` / `esc` at the bottom frame | process exit | as T13 |
| T13 | any | quit | — | under tmux: `rename-window` back to the name read at start-up. On a bare terminal: the title is cleared (`OSC 2` with an empty string), because the pre-existing title cannot be read back ([INFERENCE] no portable query exists; see `## Assumptions and Open Forks`) |

**Focus reporting.** The shell enables terminal focus reporting at start-up and turns `tea.BlurMsg`
into T8 and `tea.FocusMsg` into a no-op. `[INFERENCE]` the two message symbols in bubbletea v2.1.0 and
the enabling option; the planner confirms both against the pinned version before planning the step.
Two limitations are **recorded, not faked**:

1. A terminal that does not implement focus reporting simply never sends the message: auto-panic
   silently does not fire, and nothing on screen ever claims it will. `ctrl+p` still works.
2. Under tmux, focus events reach a pane only when the server option `focus-events` is on, and its
   default is off ([INFERENCE] on the default; the planner verifies with `tmux show -g focus-events`).
   The app does **not** turn it on for the user: that is a server-wide setting, and changing a user's
   tmux configuration from inside a reader is not this program's business. The limitation is recorded
   in the phase's notes; `ctrl+p` covers the same need by hand.

**Start-up.** `display.state` selects the state of the first frame (`normal`, `immersive`, or `panic`).
Starting in `panic` runs the same sequence after the first frame is painted — nothing above the app
may remain reachable either, since the shell line that launched `x-terminal` is above it.

### The grid under a cover

Every Phase 2 invariant holds in all three states unless a row below says otherwise:

| Invariant | Under a cover |
|-----------|---------------|
| The frame is exactly `H` rows of exactly `W` cells; a full-height repaint; no partial region left stale | unchanged |
| Row 1 .. `H-1` is the pane, row `H` is the status line | unchanged in `normal` and `immersive`; in `panic` the frame owns rows 1..`H` and there is no status line |
| Column 1 of every row is the selection column; content starts at column 2 | unchanged. A selected block's content rows carry `>`; an **intra-block blank row** (gitlog's header/message blank) is emitted with a blank selection column — a `>` on an otherwise empty row reads as a bug |
| The selection is a post id, never a row index | unchanged |
| `Wrap`/`Pad`/`Truncate` from `internal/text` are the only measurement | unchanged |
| Body measure `= min(W - 1 - BodyIndent - 2·depth - len(BodyPrefix), MeasureCap)` | generalises Phase 2's `min(W - 3 - 2·depth, 96)`; the plain grammar's values reproduce it exactly |
| No `TAB` byte is ever emitted | new and load-bearing: a tab's width is terminal state, not text, so a cover's aligned columns are spaces only |
| Nothing is emitted that the width model does not measure | unchanged |

**What a cover may change** (each is a `Grammar` field; there is no second renderer and no per-screen
copy — the composer stays one function):

| Field | Plain | Meaning |
|-------|-------|---------|
| `Head []string` | `["{handle:16} {stamp:12}{markers}"]` | the head's line templates; placeholders below |
| `QuoteHead []string` | same as `Head` | the head templates a *nested quoted* post uses |
| `QuoteAsRecord bool` | `false` | when true the quoted post renders as its own record after the quoting one |
| `MarkerPlace` | `MarkersInline` | `MarkersInline` (append to the head's last line) / `MarkersHeadLines` (one line each at the head's indent) / `MarkersBodyLines` (one line each at the body indent) |
| `PaneHeader []string` | empty | lines drawn once, as the pane's first content rows; they scroll with the content and never carry `>` |
| `BodyIndent int` | `2` | cells between the selection column and the body |
| `BodyPrefix string` | `""` | a literal prefixed to every body line |
| `MeasureCap int` | `96` | the typographic measure |
| `Separator bool` | `true` | one blank row between blocks |
| `Stamp StampFormat` | `Jan 02 15:04` / `Jan 02  2006` | the instant's format; Phase 3 adds `ISO8601UTC`, `GitDate`, `ClockSecond` |
| `Identity func(domain.User) CoverAlias` | the identity function | Phase 2's `func(domain.User) string`, widened to the alias's four projections (`## The Alias Function`) |
| `Ref func(domain.PostID) string` | `nil` | the cover's own reference token for a post; empty in the plain grammar |
| `Markers MarkerSet` | Phase 2's | the literals, as templates |
| `ShowCounts bool` | `false` | false in every grammar this phase ships (`REND-01`) |

`HandleCols` is **deleted**: the plain grammar's 16-cell column is `{handle:16}` inside `Head`, which is
the same rule applied by the same `text.Pad`. One mechanism, not two.

**Placeholders** (closed set; no conditionals, no new template language):

| Placeholder | Expands to | Empty when |
|-------------|-----------|-------------|
| `{stamp}` | the post's instant in the grammar's `Stamp` format | never |
| `{ref}` | `Grammar.Ref(post.ID)` — the cover's own token for the post | the grammar has no `Ref` |
| `{handle}` | `CoverAlias.Handle` — the style's handle-slot projection | never (falls back, `## The Alias Function`) |
| `{name}` | `CoverAlias.Name` | never |
| `{email}` | `CoverAlias.Email` | never |
| `{markers}` | the applicable relationship markers, in table order, each from `Markers` | no relationship |
| `{state}` | the style's word for the post's `Visibility` — `INFO` / `WARN` / `ERROR` (servicelog), `open` / `limited` / `closed` (internal) | the grammar renders no visibility word (plain, gitlog, ci; there the relation appears as a marker instead) |
| `{text}` | the post text, wrapped to the measure | the post has no text |

`{x:N}` pads the field with `text.Pad` to `N` cells (truncating with `~` if it does not fit); an
assembled line wider than `W-1` is wrapped with `text.Wrap` and the continuation starts at the head's
own indent, exactly as a terminal wraps a long printed line; a template line that is the empty string
is a blank row (not a dropped line); a template line whose only placeholder is empty is dropped.

**What a cover may never change:** the post text, the list order, the page boundaries, the cursors, the
selection, the anchor, the status line's row or field order, the selection column, the help overlay's
existence, or any request. This is `P3` of Phase 2, restated for covers and asserted in `V9`.

## The Panic Frame

A single constant frame. It asks nothing of the model but `(W, H)`, and it is the same frame whether it
was entered from `normal` or from any cover.

**W = 80, H = 24** (the ruler is not part of the frame):

```
         1         2         3         4         5         6         7         8
01234567890123456789012345678901234567890123456789012345678901234567890123456789
ok      corp/billing/internal/ledger    0.412s
ok      corp/billing/internal/rates     0.031s
ok      corp/billing/internal/invoice   0.208s
ok      corp/billing/internal/pricing   0.019s
ok      corp/billing/internal/pdf       0.512s
ok      corp/billing/internal/tax       0.077s
ok      corp/billing/internal/dunning   0.003s
ok      corp/billing/internal/import    0.033s
ok      corp/ledger                     0.655s
ok      corp/ledger/internal/reconcile  0.121s
ok      corp/ledger/internal/reports    0.088s
ok      corp/api/internal/auth          0.044s
ok      corp/api/internal/handlers      0.210s
ok      corp/api/internal/ratelimit     0.009s
ok      corp/jobs/internal/runner       0.121s
ok      corp/jobs/internal/schedule     0.015s
ok      corp/notify/internal/mail       0.062s
ok      corp/notify/internal/webhook    0.028s
ok      corp/config                     0.007s
ok      corp/logging                    0.005s
ok      corp/retry                      0.002s
```
(rows 22–24 are 80 blank cells; the frame is exactly 24 rows of exactly 80 cells)

**W = 120, H = 24** — the same 21 lines, byte-identical, padded to 120. The frame does **not** stretch:
terminal output does not widen because the window did, and a frame that filled 120 cells would read as
a UI rather than as output.

**What it pretends to be: a finished-or-paused test run of an internal monorepo.** Why that is
convincing, in order of weight:

1. It explains the *stillness*: `go test ./...` output is exactly the screen a terminal shows after a
   command has scrolled a screenful of results — nothing about it invites typing or waiting.
2. It is the most boring possible content: `ok` lines are the lines humans skip.
3. It explains *why there is a wall of text*: the observer's question ("what is he reading?") has a
   one-word answer ("test output") that ends the conversation.
4. It contains no identity, no prompt, no hostname, no product and no path from the user's machine.
   The fictional module `corp/...` cannot collide with a real handle or display name.
5. It makes no claim a colleague could contradict: no prompt style, no shell prompt at all (a `$`-line
   would be a claim about *the user's* prompt string), no machine name (tmux's own status bar may show
   the real one), no clock (a live clock would move, and this frame must not).
6. It is one frame: no cursor, no SGR, no animation, no blank-then-fill, nothing that can be caught
   mid-change.

At `H > 21` the blank rows below read as "a run whose output has paused" — a screen nobody waits on.
Filling them would require inventing a prompt, i.e. claiming the command finished, which the frame has
no reason to claim. At `W` below the longest line the lines wrap with `text.Wrap`, as a terminal would;
if the wrapped content is taller than `H`, the frame shows its last `H` rows (the terminal scrolled) and
adds no truncation mark. Below 60 columns the frame is replaced by the same one-line floor message the
plain reader uses.

**The sequence — ordered, and this order is the requirement.**

| # | Step | Mechanism | Ordering |
|---|------|-----------|----------|
| 1 | **paint the panic frame** | the next `View()` returns the frame; the renderer paints it as one full `W`×`H` repaint | No `tea.ClearScreen`, no `tea.Suspend`, no timer, no second frame: nothing may appear between the feed and the cover, and no intermediate empty screen may be shown |
| 2 | **clear the terminal scrollback** | `ESC[3J` (ED 3), written **after the frame's cells, in the same output write** | guaranteed by byte order inside one write. Measured on this host: it works in bare Ghostty 1.3.1 (Probe D) and does nothing under tmux 3.7c (Probe E control) |
| 3 | **clear the multiplexer's history** | `tmux clear-history -t $TMUX_PANE`, a `tea.Cmd` subprocess, dispatched only after step 1's write | the subprocess cannot be synchronous with the paint; its *dispatch* is after the write, and the guarantee holds in either landing order — clearing the history cannot push the visible pane into it, and a pane already painted over has only blank cells to leak. Steps 2≠3 are two mechanisms for one requirement because the probe shows neither covers both environments |
| 4 | **set the title** | `OSC 2 ; make BEL` written after step 2 in the same write; `tmux rename-window -t $TMUX_PANE make` dispatched in the same `tea.Cmd` as step 3 | the title is a function of the state in every state, so panic *ensures* the value rather than being the only place it is set (see the title column in `## Screen Grammar`) |

**Dependent branches, named.**

| Condition | Behaviour |
|-----------|-----------|
| `$TMUX_PANE` unset or empty | there is **no tmux history to clear**: no subprocess is started, nothing is reported, no error is surfaced. Not an error — the expected case in a bare terminal |
| `$TMUX` set, `$TMUX_PANE` empty | same as above; the app never guesses a pane |
| `tmux` missing or the command failing | the failure is **swallowed**: the frame is painted and ED 3 was written. Printing an error would be a worse leak than the missing clear, and the app never claims on screen that the clear succeeded |
| terminal ignores `ESC[3J` | **no detection is possible** (there is no portable query, and a query would add a round trip to the frame that matters most). The scrollback then keeps whatever was there and scrolling up can show it. Recorded as a limitation; the app never claims otherwise. The only recourse is running under tmux, where the clear is a command with a status |
| `$TMUX` set | the window name is renamed to the frame's name on entry and restored on exit from the name read once at start-up (`display-message -p '#W'`). A user who renames the window while panicking loses that rename — accepted |
| the frame is entered from a start-up panic | steps 1–4 run after the first frame, unchanged |
| a request is in flight when panic fires | nothing is cancelled: panic is a render state, not a network state. An answer that lands while panicked is absorbed normally |

**What panic refuses to do:** issue a request; cancel one; read a file; start a timer; animate;
suspend the program; clear the screen apart from painting the frame; leave a status line; render any
character of the feed (asserted in `V5`); contain any escape byte other than the three in the sequence
above.

## The Four Covers

**What each one is pretending to be, and how a stranger reads the screen.**

| Style (`display.cover`) | Title / window name | Pretends to be | A stranger sees | At-a-glance signature |
|------------------------|--------------------|----------------|-----------------|----------------------|

## The Alias Function

`DSGT-06` (no real handle or display name anywhere on screen) and `DSGT-07` (deterministic, stable
across restarts, **no alias table on disk**) are one function and one property:

```go
// internal/render/alias.go — pure: no I/O, no clock, no randomness, no map iteration.
func CoverAliasOf(style string, u domain.User) CoverAlias

type CoverAlias struct{ Handle, Name, Login, Email string }
```

**The fingerprint.** One fixed hash, one input rule:

```
key   := u.ID; if key == "" { key = strings.ToLower(strings.TrimPrefix(u.ScreenName, "@")) }
        if key == "" { key = "\x00anonymous" }                 // total: never an empty alias
H(p)  := FNV-1a 64-bit over the bytes of "xt-cover/v1/" + p + "\x00" + key
```

- **FNV-1a, spelled out and frozen**: never `hash/maphash` (seeded per process — it would break
  `DSGT-07` invisibly), never map iteration order, never `math/rand`, never a clock, never the current
  list or its length. The domain separator and the version segment (`/v1/`) are part of the input so a
  future change of the lists changes every alias *deliberately*, in one commit, with the golden frames
  as the diff.
- **The handle is an input to the hash and never an output.** That is what makes `DSGT-06` and `DSGT-07`
  compatible: the alias is a function of the account, but nothing of the account leaks into it.
- **Total**: an author with no id and no handle still renders a fixed alias (`svc-…`, from the
  `\x00anonymous` key), so no path can render an empty identity column.

**The projections** (all four from `H("slug", key)` and `H("name", key)`):

| Projection | Formula | Example (`aergon`, id `44196397`) | Used by |
|------------|---------|----------------------------------|---------|
| `Handle` | `ROLES[h1 mod 24] + "-" + NOUNS[(h1>>8) mod 64] + "-" + zero-padded `(h1>>16) mod 100` | `agent-rollback-70` | servicelog (`svc=`), ci (`job=`), internal (`owner`) |
| `Name` | `FIRST[h2 mod 48] + " " + SURNAME[(h2>>8) mod 64]` | `Anya Karlsson` | gitlog (`Author:`) |
| `Login` | lowercased `first.last` | `anya.karlsson` | internal (`owner`) |
| `Email` | `login` + the two digits + `@corp.internal` | `anya.karlsson70@corp.internal` | gitlog (`<…>`) |

The cover's **reference tokens** (`Grammar.Ref`) are the same shape of function over the *post* id, and
their exact formulas are in the grammar table: `seq=2805966`, `commit 51140f214ccc`, `build=4655`,
`REQ-4655`. Nothing else in a cover is derived from anything but ids and the geometry.

**The honesty rule, as a testable property.** An alias must be *readable and stable enough that the
user can still follow a conversation*:

1. **Readable**: no alias is a hash, a hex blob or an id; every alias is two dictionary words (plus a
   two-digit discriminator), and `FIRST`/`SURNAME` exist so a `git log`'s author line reads like a
   person. The user learns "the ledger guy" and keeps it for the life of the account.
2. **Stable**: across screens, sessions and restarts, one account keeps one alias per style — a
   property of the function, not of a cache.
3. **One alias per account, per style**: the *two namespaces* (machine names for servicelog/ci, person
   names for gitlog/internal) are a named compromise: each format's identity slot carries what that
   format really carries, and a `git log` whose authors are `agent-rollback-70` would be *less*
   believable, which is the one thing the cover may not be. Switching styles therefore changes the
   spelling of an identity. The alternative — one namespace everywhere — is a one-line change to the
   two projection tables if a reviewer prefers it.
4. **Unique enough in practice**: 24×64×100 ≈ 153 600 machine names and 48×64 (×100 in the email) ≈
   307 200 person identities. Two accounts can share a *displayed* `Name` (as two real people can);
   the email on the same line and the login in the `owner` column carry the discriminator. A property
   test asserts that within one frame no two accounts share a `Handle`, and that no alias equals any
   real handle or display name in the same frame's content.

**No alias table on disk — three independent proofs, because this is the phase's privacy promise:**

| # | Proof | How |
|---|-------|-----|
| P-a | structural | the function lives in `internal/render`, which `V3b` asserts imports no `os`, `io`, `path/filepath`, no `math/rand`, no `hash/maphash` and never calls `time.Now`. A package that cannot write cannot write a table, and a seeded hash cannot make an unstable one |
| P-b | behavioural | run the whole phase's suite (all four styles, a style switch, a panic round trip, a restart) against a temp config/data dir, snapshot both directories before and after, and assert **no file was created or modified** except the two documented config keys (`display.state`, `display.cover`) |
| P-c | negative | grep every file written anywhere in the phase (config, log, crash output) for the fixture aliases *and* for the fixture handles: a config file that recorded an alias→handle mapping would fail this, and so would a diagnostics dump |

## The Status Line Under a Cover

Phase 2's status line stands, field for field and drop order for drop order, with exactly the two
copy changes of `## Copywriting Contract`. It is *not* removed: `OPS-02` requires the budget in every
frame, and the user's own safety needs it — an observer reads `200 requests, 12 rate-limited` as *this
tool's* rate limit, which is coherent with every cover (a log tailer or a CI stream makes requests too).

`DSGT-09`'s "no status line" is read as **no status line in the product's voice** — no `following`, no
`post`, no product noun. The alternatives (dropping the line in covered states) are rejected because
they would blind the user to a soft ban at exactly the moment the cover is most useful.

**Worked covered status lines, 80 columns** (`used = 200`, `limited = 12`, `list = branch=main`; the
final line is the one that actually renders after the drop rule):

```
3 new records  branch=main  12/240+  200 requests, 12 rate-limited
session expired  copy the cookie again  200 requests, 12 rate-limited
rate limited until 14:32  no retry  branch=main  200 requests, 12 rate-limited
no route to upstream  check the proxy  200 requests, 12 rate-limited
operation id stale  doctor --refresh-ids  200 requests, 12 rate-limited
soft ban  stop for the session  branch=main  200 requests, 12 rate-limited
```

**Named consequence:** the covered list names are longer than `following` / `for you`, so at 80 columns
the droppable `list` field disappears in **three** lines instead of one (`session expired`,
`no route to upstream`, `operation id stale` — three states, where the plain grammar loses it only in
`operation id stale`). Above 88 columns nothing is dropped, as in Phase 2. `state`, `remedy` and
`budget` are never dropped, in either state. The alternative (shortening the covered names to
`stream=a`) was rejected: a meaningless field is worse than a missing one, and the drop rule is the
declared, tested mechanism for exactly this.

**`state` and `remedy`:** rendered from `xweb.Outcome` verbatim, with the one rename (`no route to
upstream`) and the host substitution. Every state in the closed taxonomy still has a row, a distinct
remedy and an accent colour, under every cover — so a covered failure can never render as nothing, and
the classifier's vocabulary remains the only vocabulary for failure.

**Which keys are disabled or remapped under a cover: none.** That is the whole point of `DSGT-08`: under
`immersive`, every row above behaves exactly as it does in `normal` — scrolling, pagination, refresh,
the feed toggle, `?`, `q`/`esc`, `ctrl+c` — and the only visible difference is the wording of the help
overlay. A cover is a renderer mode, and the test is `V9`: every Phase 2 golden frame has a covered
counterpart rendered from the same model with the same keys and **zero** requests.

**Under `panic`, one binding exists:** `ctrl+p` (T7). Every other key is swallowed (T10), including
`?`, `esc`, `q` and the arrows — a static frame that reacted to a key would be stranger than one that
does not, and an accidental `esc` must never uncover. `ctrl+c` still quits (T11): a hung app must stay
quittable, and quitting is what a person behind the user expects to see if they press it. `[INFERENCE]`
`ctrl+p` is free in Ghostty and passed through by tmux's default prefix (`C-b`); a terminal that binds
it would need a different single key, and the row above is the one place to change.

**The help overlay, confirmed working under a cover.** `?` opens the same modal overlay in `normal` and
`immersive`: the pane is replaced by the key table (key column 16 cells, then the help text, in table
order, no heading, no border), the status line stays, and `help`/`back` close it while every other
action is ignored. It is the one screen whose *shape* a cover does not disguise — it is a key list, and
the user asked for it — and that is a named compromise, not an oversight. Its *words* are covered. In
`panic` the overlay does not open at all.

**Persistence (`DSGT-11`).** Two keys in Phase 1's `config.toml` reader:

| Key | Values | Default | When written |
|-----|--------|---------|--------------|
| `display.state` | `normal` \| `immersive` \| `panic` | `normal` | On T1/T2/T3/T5 (`m`, `c`, `1`-`4`) only. **Never** on a panic entered by a key or by focus loss: an involuntary transition must not become tomorrow's start-up state, and no file is written while someone is walking up |
| `display.cover` | `servicelog` \| `gitlog` \| `ci` \| `internal` | `servicelog` | On T3/T4/T5 only |

An unknown value produces a warning and keeps the default, in Phase 1's established pattern (a warning
holds the key and the line, never the value). A start-up state of `panic` is accepted: the user is
allowed to choose it deliberately, and the sequence runs after the first frame.

## Assumptions and Open Forks

Stated rather than silently chosen. Every one is cheap to reverse and each names its alternative.

1. **`[INFERENCE]` The app runs on the primary screen and never enters the alternate screen.** Phase 2
   did not pin this, and `DSGT-02`'s mechanism only means what the evidence measured if the app's
   frames *can* reach the scrollback (they can, chiefly across a terminal or pane resize, and the shell
   content above the app is there before it starts). With the alternate screen, `ESC[3J` and
   `tmux clear-history` would be clearing something the app never caused. *Alternative*: enter the
   alternate screen and treat the clear as belt-and-braces.
2. **`[INFERENCE]` `tea.BlurMsg` / `tea.FocusMsg` and the focus-reporting option in bubbletea v2.1.0**,
   and the raw-output escape hatch used to append `ESC[3J` and the title to the frame's write. The
   *contract* is the order and the content; the planner confirms the three symbols against the pinned
   version before planning the step. *Alternative*: write the sequences in the view string, if the
   renderer treats them as zero-width content.
3. **`[INFERENCE]` tmux's `focus-events` defaults to off**, so auto-panic does not fire under tmux until
   the user turns it on. The app does not change a server-wide setting. *Alternative*: a start-up
   warning when `$TMUX` is set and the option is off — visible on screen, so it is a leak in the covered
   states; refused.
4. **`[INFERENCE]` the alias word lists.** The rule, the indices and the frozen order are the contract;
   the words are the implementer's discretion, and substituting them recomputes every worked example
   in the same commit.
5. **The panic frame's title is `make`, i.e. "the name of the thing on screen".** `DSGT-03` says the
   title becomes "the cover's own name". Read literally, `panic` entered from `immersive` would keep
   the *style's* name; read as it is here, the title always names what is on screen (a strictly stronger
   property: no state's title ever lies about its frame), and panic entered from `normal` still performs
   the `DSGT-03` transition. *Alternative*: one row of the title table.
6. **ED 3 deletes the terminal's whole scrollback, including the shell's own history above the app.**
   That is what `DSGT-02` asks for and the price of it: after a panic the user cannot scroll back to
   what they were doing before the app started. The alternative (selective clearing) does not exist.
7. **`panic` is never written to `display.state` by the app** (only a hand-edited file or a deliberate
   choice at start-up can produce a panic start-up), for the reason in the persistence table.
8. **A cover's markers are renames, never new facts**: `vis=limited`, `Visibility: restricted`,
   `note=partial access` and `state: limited` all denote the same `Visibility` value, and the
   `INFO`/`WARN`/`ERROR` level is a rename of it too.
9. **`[INFERENCE]` the harness can move window focus** (`hyprctl dispatch focuswindow`) to test `V8`
   end to end; if not, `V8` stays a model-level test plus the recorded limitation.
