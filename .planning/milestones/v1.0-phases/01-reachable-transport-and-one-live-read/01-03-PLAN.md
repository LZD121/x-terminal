**`registry.json`** — start from `.planning/research/x-ops-snapshot.json` (104 operations mined
from a live authenticated bundle on 2026-10-14) and reshape it into the registry schema:

```json
{
  "schema": 1,
  "provenance": {"mined_at": "2026-10-14", "source_bundle": "…", "method": "authenticated /home shell -> main.<hash>a.js"},
  "operations": {
    "Viewer": {"queryId": "TpQxQtWMTMnIAMPlMGMqNw", "operationType": "query",
                "featureSwitches": ["…"], "fieldToggles": ["…"]}
  }
}
```
Keep every operation and every feature switch from the mined file — do not prune.

**`registry.go`** — embed the JSON with `//go:embed registry.json`. Expose:
- `type Operation struct { QueryID string; OperationType string; FeatureSwitches []string; FieldToggles []string }`
- `type Registry struct` with `Lookup(name string) (Operation, error)` returning a typed
  `ErrUnknownOperation` naming the operation and telling the user to refresh or pin it.
- `func Load(pinsPath string) (*Registry, error)` merging in pins (below) with pin precedence.
- `func FeaturesJSON(op Operation) (string, error)` building the `{"switch":true,…}` map, and
  `TogglesJSON(op)` likewise — the wire format needs a JSON object, not the array.

**`pins.go`** — user pins live at `<datadir>/pins.json` as
`{"operations": {"HomeTimeline": {"queryId": "…"}}}`. `Load` overlays them over the snapshot and
records that the entry came from a pin. `func Pin(path, operation, queryId string) error` writes
one atomically (temp file + rename).

**`cmd/x-opsgen`** — the refresh tool. `x-opsgen --from-file <bundle.js> --merge` parses
`{queryId,operationName,operationType,metadata:{featureSwitches,fieldToggles}}` records and
**adds or updates only** — it must never delete an existing entry, and it must print a diff
summary (`+3 added, ~1 updated, 100 unchanged`). `x-opsgen --live` additionally fetches
`https://x.com/home` through the configured transport, finds the
`responsive-web/client-web/main.<hash>a.js` reference, downloads it and merges. It exits
non-zero with a named message if no bundle reference is found.

`registry_test.go` must assert: `//go:embed` loaded ≥100 operations; `Lookup("Viewer")` returns
the id above; an unknown name returns `ErrUnknownOperation`; a pin for `HomeTimeline` appears in
`Lookup` and is marked as a pin; a merge that would remove an entry keeps it; `FeaturesJSON` for
an operation with 2 switches yields exactly `{"a":true,"b":true}`-shaped output.

Add a **guard test** asserting no other file in the repository contains a 20+ character
base64url-looking literal next to the word `queryId` — i.e. the ids live only in this package's
data. Make the test's failure message say what to do.
  </action>

**`internal/xweb/graphql.go`** — `func (c *Client) GraphQL(ctx context.Context, opName string, variables map[string]any) ([]byte, error)`:
- Look the operation up in the registry; unknown → typed error, never a stale-id fallback.
- Build `GET https://x.com/i/api/graphql/<queryId>/<opName>` with `variables`, `features` and
  `fieldToggles` URL-encoded (use `net/url.Values`, never string concatenation).
- Headers, exactly as measured: `authorization: Bearer <web bearer>`,
  `cookie: auth_token=<…>; ct0=<…>`, `x-csrf-token: <ct0>`, `x-twitter-auth-type: OAuth2Session`,
  `x-twitter-active-user: yes`, `x-twitter-client-language: en`, a normal Chrome user agent, and
  `content-type: application/json`.
- Route through `xweb.Limiter.Do`. On a response, run `xweb.Classify`; any non-success outcome
  becomes a typed error carrying the outcome (so the UI can name it) — the body is never
  returned as if it were data.
- Provide a `Signer` seam: `type Signer interface { Header(ctx context.Context, req *http.Request) error }`
  with a `NoopSigner` implementation, and record in a package comment that two operations were
  measured working without it on 2026-10-14, so a future per-operation requirement is a
  one-line change.

**`internal/xsource/user.go`** — `func ParseUser(raw []byte) (domain.User, error)` reading the

`banner`, `id`, `has_graduated_access`; do NOT read `legacy`. Return a typed parse error naming
the missing path (e.g. `missing data.user.result.core.screen_name`) rather than returning a zero
value silently.

`retweeted_status_result` into the original post with a "reposted by" marker, and resolve text in
the order `note_tweet.text` → `legacy.full_text`.

If `internal/domain` does not exist yet, create the minimum: `type User struct { ID, ScreenName, Name, AvatarURL string }` and
`type Post struct { ID string; Author User; Text string; CreatedAt time.Time; RepostedBy *User; QuotedID string }`.

**`cmd/spike`** — a throwaway binary, documented as such in a header comment (it is deleted once
Phase 2's screens replace it). It:
1. loads config + session,
2. calls `Viewer` and prints `viewer: @<handle> (<name>)`,
3. calls `UserTweets` for the viewer's own id with `count=20` and prints, for each post,
   `@author  YYYY-MM-DD  <first 100 chars of text>`,
4. prints the request budget line and the elapsed time,
5. exits non-zero with the named outcome on any classified failure.
It must never print the cookie, and it must print nothing at all (not even a blank timeline) when
the read fails.

**`internal/cli/whoami.go`** — replace the stub: load session, call `Viewer`, print
`@handle — <name>` and, when known, the session's own status (`ct0 present`, file path). If the
session is missing or rejected, print the named outcome and exit non-zero.

**`internal/cli/notice.go`** — the first-run account-risk statement. On the first successful run
of any subcommand, print a short paragraph (5 lines maximum): the reads carry the user's real
identity; the thresholds are undocumented; a retry loop can turn a 15-minute throttle into a
24-hour block; this tool is read-only and must not be distributed. Then write a marker file
`<datadir>/notice-shown` (0600) so it never prints again. `x-terminal doctor --show-notice`
re-prints it on demand.

**Also wire the stubs:** `doctor --refresh-ids` runs `x-opsgen --live`-equivalent logic;
`doctor --pin <operation> <queryId>` writes a pin. Both were stubbed in plan 02.

**Wire `x-terminal`** to register `whoami` and make `spike` a separate binary, not a subcommand.
