<objective>
Extend `doctor` — not rebuild it — into the front door of the repair path: the mirror's presence facts read through the store's read-only path, a signer self-test line, `--probe <operation>` (exactly one request, one word), the media openers the run resolved, a `RUNBOOK.md` pointer on every failing line, and the JSON twin carrying the same facts.

Purpose: OPS-03 is "presence facts only, never a token value", and the phase's own rule is that a diagnosis which does not say where the repair is written is half a diagnosis. The existing verb is the shape to keep — one line per link, a text report and a JSON twin, non-zero when a link failed, a skipped stage not a failure — so this plan adds lines and one flag, and re-asserts the one property the whole verb rests on: no line carries a credential, in either report.

Output: `domain.MirrorFacts` and its store reader with the allowlist updated, the probe on the client, the signer accessor, the doctor's new lines and flag, and the tests that hold each new fact to being a fact.

Requirement ownership: OPS-03 is this plan's `requirements` entry. SEC-03 and the audits are plan 01's; OPS-06 and the covered re-check are plan 03's. The runbook pointer table this plan writes is asserted against the file by plan 03's test.
</objective>

**`domain.MirrorFacts` — the closed set of facts the line may carry.** In `internal/domain/saved.go`:

`type MirrorKindCount struct { Kind SavedKind; Present, Absent int }` and
`type MirrorFacts struct { Path string; Exists bool; SchemaVersion int; Newer bool; Owner string; Kinds []MirrorKindCount; LastRun time.Time; Stop StopReason }`, with the doc comment stating that there is no field for a post body, a row's contents or a per-row instant — a mirror line is a report about a file, and the type is where that stays true. `Newer` means the file records a schema version this build does not know (Phase 6's `ErrSchemaNewer` case); `LastRun`/`Stop` are the last `sync_runs` row's instant and stop reason, zero for a mirror that never ran.

**`store.ReadFacts(path string) (domain.MirrorFacts, error)` — read-only, and nothing else.**

- Opens one connection with a read-only DSN (`mode=ro` plus the `query_only` pragma), **no writer pool, no migration, no `journal_mode` read-back** — the doctor must not be able to write to the file it reports on, and the doc comment says exactly that and why (a diagnostic that repairs by accident is a diagnostic nobody can trust).
- Reads: the schema version and the owner from `meta` (Phase 6's own keys), the present and absent counts per saved kind, and the newest `sync_runs` row's `finished_at` and `stop_reason`.
- A path that does not exist returns `MirrorFacts{Path: path, Exists: false}, nil` — a presence fact, not a failure. A file recording a version newer than this build's returns `Newer: true` **with the version**, no error, so the line can say what it found. Anything else unreadable (a corrupt file, a permission problem) is a named error carrying the path and no row contents.
- Add `ReadFacts` to `internal/store/schema_test.go`'s exported-surface allowlist, keeping that test's own anti-vacuity arm (it must still find the mutators it expects, so the surface cannot pass by shrinking to one function).

**The doctor's line.** In `reportText` and `reportJSON`, one new labelled line in the existing shape (the label column is the file's own 10-cell convention), after `registry` and before `session`:

- present: `mirror     <path>  schema 1  owner @aergon  bookmarks 12 present 0 absent  likes 3 present 0 absent  last sync 2026-10-14 09:12 (no unknown ids)`;
- absent: `mirror     no mirror yet (<path>)` — and the run is **not** a failure for it;
- newer: `mirror     <path>  schema 2 (newer than this build knows - see RUNBOOK.md#the-mirror)` — a failing line, because the repair is a human act (the runbook's mirror section);
- unreadable: `mirror     <path>  unreadable: <bounded reason>  see RUNBOOK.md#the-mirror` — a failing line.
- The line must not call `store.Open` and must never hold a writer: assert by test that a mirror file's bytes and mtime are unchanged by a doctor run (the store's own read-only proof, from the other side).
- The JSON twin gains a `mirror` object with the same fields (`path`, `exists`, `schema_version`, `newer`, `owner`, `kinds` as an array of `{kind, present, absent}`, `last_run`, `stop`, and an `error` string when the read failed), bounded by the file's existing `clipped` rule. `ok` accounts for the failing shapes only.

**Tests** (`facts_test.go`, `doctor_test.go`): a store written by Phase 6's write API and read back through `ReadFacts` reports the version, the owner and the counts the writer put there; a missing path reports `Exists=false` with no error and the doctor prints the "no mirror yet" line and exits zero; a file carrying a newer version reports `Newer` with its number and the doctor exits non-zero with the runbook pointer; a corrupt file reports a reason of bounded length; a doctor run leaves the mirror file byte-identical and its mtime unchanged.

**The probe on the client (`internal/xweb/probe.go`).** `type Probe struct { Outcome Outcome; Remaining int; RemainingKnown bool; Reset time.Time; Bytes int }` and `func (c *Client) Probe(ctx context.Context, opName string, variables map[string]any) (Probe, error)`: one request through the client's own request path (so it passes the same limiter — single-flight, the floor, the session cap — and the same registry lookup for the query id and feature switches), classified by the same classifier, returning the outcome, the bytes seen and the rate-limit headers the answer carried. The body is discarded inside the method and never returned: the type has no field for it, which is the point. A non-success outcome returns the probe with a nil error and the classified outcome set (the caller prints the word); only a request that could not be built at all (an unknown operation name) returns an error.

**The signer accessor (`internal/xweb/graphql.go`).** `func (c *Client) SignerName() string` returning the name of the header the request builder adds — `none` while `NoopSigner` is in place — with the measurement in the doc comment: `UserByScreenName` and `UserTweets` both answered 200 with no transaction id at all (2026-10-14), so no operation this build reads requires one yet, and the method is what lets the doctor say so out loud instead of a reader having to trust a comment.

**The doctor's additions (`internal/cli/doctor.go`), all in the existing shape.**

- **The signer line**: `signer     none (no transaction-id header is sent; the read below is the measurement)` — the accessor's value plus one clause tying it to the authenticated read this same run performs. When the check's verdict is the signer-or-auth state, the line becomes the same fact plus `see RUNBOOK.md#signer-break` and the run is a failure as it already was.
- **`--probe <operation>`**: one more flag, parsed in the existing argument loop (which already moves its own index for `--pin`). It loads the session (a probe without a session is an error naming that), builds the client the check built, and issues **one** `Probe` for the named operation. Variables come from a table in this file, `probeVariables(op string) (map[string]any, bool)`, with one row per operation the repair path names — `Viewer` (no variables), `HomeLatestTimeline` and `HomeTimeline` (the measured `count`, empty `cursor`, empty `seenTweetIds`), `Bookmarks` and `Likes` (Phase 6's saved-list request shape) — and an operation not in the table is a usage error that names the ones it can build. Output, one line: `probe      <operation>  <state word>  <remaining>/<reset>` using the doctor's label column; `remaining` prints `unknown` when the answer carried no header, and the reset prints as an instant, never a countdown. Non-zero exit when the outcome is not the success one. `--probe` combined with `--json` prints the same facts as a `probe` object in the twin, for the same reason the rest of the verb has one. It never sweeps: one operation per invocation, and the doc comment says a repair is one request.
- **The config line gains the media facts**: the resolved `media_opener` and the two dispatches it is used for, as presence facts with no value echoed beyond the program name the user configured — `media xdg-open (images, links), mpv (video, gif)`. The phase adds no configuration key; this line reports the one the project already ships.
- **The runbook pointer table**: `runbookAnchor(state) string` plus the table mapping every failing state the report can print — each failing `netcheck.Outcome`, each failing `xweb.Outcome` the classifier can produce (through the same mapper `internal/cli/failure.go` uses) and the three mirror shapes (newer, unreadable, and the missing case, which is not a failure) — to a `RUNBOOK.md#<anchor>` string. Every failing line appends its pointer, in the text report and as a field in the JSON twin. A state with no row is a test failure in this plan (totality over the failing outcomes); whether the anchors exist in the file is plan 03's test, which reads this same table.
- Nothing else changes: the 90 s backstop, the stage ordering, the exit-code rule, the `--show-notice`, `--refresh-ids` and `--pin` bodies and the session-is-not-a-failure rule all stay exactly as Phase 1 wrote them.

**Tests** (`probe_test.go`, `doctor_test.go`): a counting transport proves `--probe` issues exactly one request and no more, including when the answer is a 429; the probe's output carries the state word and the two headers and does **not** carry a marker string planted in the stub answer's body; an operation outside the table exits with the usage code and names the table's operations; a probe without a session exits non-zero with the reason; the failing-line table is total over every failing outcome (a test that enumerates them and fails on a missing row); the media facts line prints both dispatches and neither the `$WAYLAND_DISPLAY` value nor anything about the clipboard.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the mirror file → the report | a file the user's own account wrote is read by a verb that must not write to it and must not copy its contents out |
| `--probe` → the upstream | one request per invocation, through the cap, the floor and single-flight; the thing it must never do is become a sweep or a retry loop |
| the report → wherever it is pasted | the doctor's output is designed to be quotable in a bug report, which is exactly why a token in it would be a credential in public |
