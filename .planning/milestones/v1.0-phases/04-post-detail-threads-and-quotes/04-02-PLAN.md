<objective>
Extract the walk once, widen the selection to `Target`, and build the thread frame's state on the same reducer.

Purpose: THRD-02's mechanism is the selection. Its requirement — "read inline quoted posts, and open a quote as its own conversation" — is satisfied by making a quoted post a row the cursor can land on rather than by adding a key (`04-CONTEXT.md`), and that widening is a reducer refactor plus its tests. The other two requirements' state halves land with it: the reply walk's page-by-page trigger and stall rule (THRD-01, realized here on 04-01's page values) and the three partial-thread conditions plus the place in the conversation tombstones and limited posts keep (THRD-03, printed in 04-03). Nothing here renders and nothing here performs I/O: every transition is a pure function of state, an event and the clock.

Output: `internal/screen/walk.go` with `Target`, `Walk[T, P]` and the `Request` union; the home frame and the thread frame over it; `render.Selection`; and the shell's movement, position and dispatch over Targets.

Phase goal (ROADMAP, quoted): "The user opens a post and reads its conversation — replies a page at a time, quotes inline, tombstones and unavailable replies labelled honestly."

Write `internal/screen/walk.go`: the one list's state, shared by every frame in the product. This file is the one file in the fan-out that is not append-only — Phases 5, 6 and 7 extend it in place, and one implementation of the dedupe set, the stall rule, the single-flight latch or the refresh diff is the rule this file exists to hold.

`type Target struct { ID string; Path []string }` with a doc comment saying what it is: the row the cursor is on — the row's own identity as the plain string the element supplies, plus the chain of containing posts when that row is a post quoted inside another; `Path` is outermost first and empty at top level; the same post quoted in two places is two targets. Add `func (t Target) Top() Target` returning the same row at top level (`Path` dropped), and a `String()` that names both parts so a test failure identifies the row. `ID` is a string and not a new id type: the walk keys a row by the string the element supplies and nothing above the port parses one.

`type Walk[T any, P any] struct` holding, once: the rows in list order (`[]T`), the pages absorbed, the opaque `domain.Cursor` the walk continues from, the id-keyed dedupe set (`map[string]bool`), the set of cursors already spent (`map[domain.Cursor]bool`), the cursor the in-flight page was asked with, the single-flight latch with its `loadingOlder`/`refreshPending` flags, the sticky `domain.Failure`, the count of rows the last refresh brought, the stall flag, the ids the last refresh was asked to diff against, the selected `Target`, the anchor (`int`, the selected block's head row's distance from the pane's first row — the arithmetic that computes it stays in `internal/tui`, where the pane geometry is), and the frame's id function (`func(T) string`, set at construction). No exported field.

The API, in three groups:
- construction and reads: `func NewWalk[T any, P any](idOf func(T) string) Walk[T, P]`, `Rows() []T`, `Row(i int) (T, bool)`, `Loaded() int`, `Next() domain.Cursor`, `HasMore() bool`, `Stalled() bool`, `InFlight() bool`, `LoadingOlder() bool`, `Failure() domain.Failure`, `NewRows() int`, `Selected() Target`, `Anchor() int`, `Index(id string) int`, `Holds(id string) bool`.
- the entity-blind operations a frame's reducer calls: `WithAnchor(int) Walk[T, P]`, `Select(t Target) Walk[T, P]` (a target the walk does not hold selects nothing rather than inventing a place), `SelectNear(t Target) Walk[T, P]` (the refresh's rule: hold the selection by target id, fall back to the same id's shallowest occurrence, and leave it to the caller to fall back further), `Move(seq []Target, step int) Walk[T, P]` and `SelectAt(seq []Target, t Target) (Walk[T, P], bool)` (movement walks the caller's own row sequence and clamps at both ends), `AtEnd(sel Target) bool` (the selection's block is the last loaded row and the walk has somewhere to go — a question about the walk, never about the pane), `Page(req Request, now time.Time) (Walk[T, P], Effect)` and `Refresh(req Request, now time.Time) (Walk[T, P], Effect)` — both are the only ways a request is born: they refuse when the latch is set or the failure state forbids a request at `now` (the soft ban, a rate limit whose reset has not passed), otherwise they set the latch and return `Effect{Kind: EffectPage|EffectRefresh, Req: req, Cursor: …, Head: …}` with `Head` cloned for a refresh.
- the folding the frame reducers use, unexported: `absorb(rows []T, next domain.Cursor, requested int) Walk[T, P]` (append in the answer's order, skip ids already held, count what was new, mark the cursor spent and set the stall flag exactly as Phase 2's `pageFetched` does), `refresh(rows []T, requested int, mode RefreshMode) Walk[T, P]` with `type RefreshMode uint8` and `RefreshPrepend` (Phase 2's home rule: the unseen rows are prepended, the selection, the pages and the cursor are untouched) and `RefreshReplace` (the thread's rule: this list is a ranking and re-reading it is the only honest way to make it current, so the answer's rows become the walk's rows), `pageFailed(f domain.Failure) Walk[T, P]` (sticky failure, everything else kept), and `blocked(now time.Time) bool` (moved here from `absorb.go` so the gate and the latch are one implementation).

The sealed `Request` union, in this file, append-only from here on: `type Request interface{ request() }`, `type FeedRequest struct { Kind domain.HomeKind; Cursor domain.Cursor }` (Phase 2's home read, as a value), and — added by Task 3 of this plan, because that is the task that brings the frame that uses it — `type ThreadRequest struct { Focal domain.PostID; Cursor domain.Cursor }`. The unexported method is what keeps the union closed to this package.

Also in this file, `func postTargets(posts []domain.Post) []Target`: the post row order shared by the home list and the thread frame — for each post in order, the post itself and then its quote chain (`post → its quote → the quote's quote`), each with the containing post ids in `Path`. A quoted post is therefore one step from its quoter in every list, and a post quoted twice is two rows.

`internal/screen/walk_test.go` — the walk's own tests, driven with `domain.Post` values, with no frame involved: dedupe (a repeated id is not added twice, and `NewRows` counts what was new), stall (a page that adds nothing unseen stalls; a cursor that comes back a second time stalls; a page whose cursor equals the one it was asked with does not stall by itself unless it also added nothing), single-flight (`Page` while a page is out returns `Effect{Kind: EffectNone}` and changes nothing; the matching answer releases the latch and a mismatched event does not), the gate (`blocked` true for a soft ban whose `Stopped` is set and for a rate limit whose reset is in the future, false after it), `RefreshPrepend` against `RefreshReplace` on the same rows, `Move`/`SelectAt` clamping at both ends, `AtEnd` true only for the last loaded row with a cursor and a live walk, and `postTargets` (a post with a two-level quote chain yields three targets, the quote's `Path` names its container, and the same post quoted in two blocks yields two targets).

Avoid: exporting a field, letting a frame's reducer keep a shadow copy of any of this state, a second movement or position implementation, and any use of `time.Now` (the clock is an argument).
