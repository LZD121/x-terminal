<objective>
Land the phase's read: the recorded `TweetDetail` body and its provenance, the one operation the phase adds to the read port, and the entry-grammar decoder that turns the answer's entries into the focal post, the chain above it and one page of replies.

Purpose: THRD-01's mechanism at the read layer is the page boundary — one request is one page, the page's own cursor is what the next request is made with, and the decoder never expands a cursor into a further request of its own. The walk's trigger, single-flight latch and stall rule (the same requirement's other half) land in 04-02 on top of these values; the words the thread frame prints land in 04-03. This plan is where the phase's ground truth is recorded, and it is the fiddliest work in the project, so its tests are driven by the real payload rather than by invented shapes.

Output: the fixture set with its provenance, the gated capture harness, `domain.ThreadPage`/`Group`/`GroupKind` with the `Threads` port, and `ParseThread` with `(*Adapter).Thread`.

Phase goal (ROADMAP, quoted): "The user opens a post and reads its conversation — replies a page at a time, quotes inline, tombstones and unavailable replies labelled honestly."

`internal/domain/thread.go` — the content values, declared in the consumer's terms, in a file of its own so that four phases adding four reads never edit one interface:
- `type GroupKind uint8` with `SelfThread` (zero) and `Replies`, and `func (k GroupKind) String() string` naming each in one lowercase word (`self-thread`, `replies`) for logs and tests, spelled the way `HomeKind` and `Visibility` do it.
- `type Group struct { Kind GroupKind; Posts []Post; More Cursor }` — `More` is this group's own unspent handle, empty when the group is complete. The answer's order is the group order and no caller may re-sort it.
- `type ThreadPage struct { Focal Post; Ancestors []Post; Groups []Group; Next Cursor; Requested int; Skipped int; FetchedAt time.Time }` — `Ancestors` is root → parent in the answer's own order and may be empty; `Next` is the reply walk's cursor, empty at the end of the walk; `Requested` is the count of tweet-bearing items the answer carried (focal, ancestors and group items, before any drop); `Skipped` is the count of entries the walker classified as not content, which is what makes "the entry stream grew a decoration" visible instead of invisible; `FetchedAt` comes from the caller's clock, exactly as `PostPage` does.
- `type Threads interface { Thread(ctx context.Context, id PostID, c Cursor) (ThreadPage, error) }`, documented as `Source`'s thread read: the conversation containing a post — the chain above it, the post itself and one page of its replies; an empty cursor asks for the first page and the answer's `Next` asks for the page after it. Declared here rather than added to `Source` in `source.go` for the reason `04-CONTEXT.md` records: the phases' reads must not collide in one interface, and an adapter satisfies both.
- Nothing here is a string a renderer prints, and no wire name (module kind, instruction name, cursor type, `sortIndex`) appears in this file.

`internal/xsource/detail.go` — the entry walker, reusing the tweet decoder rather than growing a second one: `postFrom`, `unwrapTweet`, `tombstone`, `countsOf` and `authorOf` in `tweets.go` are called, and `ParseTimeline`/`timelineEnvelope` are not touched.
- `const opTweetDetail = "TweetDetail"`; `func (a *Adapter) Thread(ctx context.Context, id domain.PostID, c domain.Cursor) (domain.ThreadPage, error)` builds the variables (`focalTweetId` from the id, `cursor` from the cursor), calls `a.client.GraphQL` once, decodes with `ParseThread`, stamps `FetchedAt` from the package's `now`, and — only when the request carried no cursor — refuses an answer that carried no focal post with a typed error, because a first page without the focal post is a response that answered a different question. A later page may answer without it: the screen keeps the focal post it already holds.
- `func ParseThread(raw []byte) (domain.ThreadPage, error)`: a new envelope in this file reads `data.threaded_conversation_with_injections_v2.instructions`; only `TimelineAddEntries` carries entries, and the entries are read in the answer's order. Classify each entry by its id and content, in that order of cheapness:
  - a `TimelineTimelineCursor` entry contributes its value as the page's own cursor (`cursorType` `Bottom`; any other cursor type is skipped and counted);
  - an entry whose id begins `tweet-` and whose decimal tail is the focal id is the focal post; a `tweet-` entry that appears **before** that entry is an ancestor, appended to the chain in the answer's order (root first);
  - a `conversationthread-` module is a group: `SelfThread` when its item's `tweetDisplayType` is `SelfThread`, `Replies` otherwise; the module's own `TimelineTimelineCursor` item (`ShowMore` or `ShowMoreThreads`) becomes that group's `More`; a module whose item entry id carries `-promoted-tweet-` is an advertisement and is skipped and counted;
  - a `tweetdetailrelatedtweets…` entry (the recommendation rail), a `messageprompt-…` entry and any entry whose id carries `tweetcomposer` are not content: skipped and counted;
  - any other entry is skipped and counted. The entry stream ships decorations without notice, and a skipped decoration must not become a blank row.
  Posts are built with the existing decoder: `unwrapTweet` for the visibility the result type grants, `postFrom` for the post and its quote chain (which is where a nested quote comes from, bounded by the existing `maxQuoteDepth`), `countsOf` for `Counts.Replies` (the evidence behind the third partial-thread condition, never printed) and `authorOf` for the byline. A tweet whose body, author or date moved stays a typed `ParseError` naming the path — the two rules are different on purpose: an entry class the build does not know is skipped, a post whose fields moved is refused.
  - The one visibility case that has no measured shape gets the narrowest honest rule: a result whose `legacy.withheld_in_countries` is a non-empty array is `domain.Withheld`, whether or not the result is also a tombstone. Any other unknown `__typename` stays a typed error. Record the inference in the file's comment and let the synthetic fixture be the only body that exercises it.
  - `Next` is the page's own bottom cursor when it carried one, and otherwise the first group's unspent `More` handle — either way opaque, and the screen only stores it. Do not merge cursors, do not request anything, and do not drop a cursor the answer carried.
