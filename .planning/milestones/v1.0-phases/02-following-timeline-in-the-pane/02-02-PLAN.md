<objective>
Build the one width model: `Width`, `Wrap`, `Pad`, `Truncate` in a single package, with the environment
dispatch the research measured (wcwidth under tmux, grapheme clusters in a bare terminal) and a property suite
that is the specification of agreement.

Purpose: the layout is text in a grid; every later plan in this phase and every later phase's screen measures
through this package. A second way to measure, or a wrap that disagrees with the measurement, is the defect
that makes a terminal UI look broken in a way no screenshot catches.

Output: `internal/text` with the four functions, the module's first third-party dependency
(`github.com/charmbracelet/x/ansi`), and `A4` — the agreement properties — with anti-vacuity arms.

Phase goal (ROADMAP, quoted): "The user reads their Following timeline in a terminal pane — scrolling back
through older posts and refreshing deliberately — and the pane never lies about what it is showing."
</objective>

`internal/text` — the only package in the program allowed to measure text. Stdlib plus `github.com/charmbracelet/x/ansi`.

- `width.go`:
  - `func method() ansi.Method` — unexported, and the only place in the program that branches on `$TMUX`:
    `os.Getenv("TMUX") != ""` selects `ansi.WcWidth` (codepoint/`wcwidth` semantics, which is what a
    multiplexer's grid models), otherwise `ansi.GraphemeWidth` (grapheme-cluster semantics, which is what
    Ghostty implements). The comment says exactly that, and says no other package may branch on `$TMUX` for
    width.
  - `func Width(s string) int` — `method().StringWidth(s)`. This is the only string measurement in the program.
  - Verified against the pinned version before planning, so assert these in tests as written: the ZWJ family
    `"\U0001F468\u200D\U0001F469\u200D\U0001F467"` measures 2 in grapheme mode and 6 in wcwidth mode, and
    `"日本語のテキスト"` measures 16 in both.
- `wrap.go`: `func Wrap(s string, w int) []string`.
  - Greedy on spaces; a token wider than `w` breaks at a cluster boundary; a hyphen is NEVER inserted (a hyphen
    is a claim about the text); no returned line ends with a space; `Width(line) <= w` for every line; the
    concatenation of the lines, with runs of spaces collapsed as a greedy wrap does, preserves the input's
    non-space characters in order — no loss, no duplication; `w < 1` is treated as 1; an empty input returns an
    empty slice.
  - Iterate clusters with `ansi.FirstGraphemeCluster(s[i:], method())` and advance by the cluster's byte length.
    Do NOT call `ansi.Wordwrap`, `ansi.Wrap`, or `Method.Wordwrap`: none of them breaks a token wider than the
    limit, and they return a newline-joined string whose trailing-space behaviour is theirs, not ours. This
    function is hand-written on purpose; the cluster iterator is the only shared piece.
- `pad.go`: `func Pad(s string, w int) string` — `Width(Pad(s, w)) == w` exactly; if `Width(s) > w` return
  `Truncate(s, w)` rather than a too-wide string; `w < 1` returns `""`.
- `truncate.go`: `func Truncate(s string, w int) string` — the longest prefix with `Width <= w`, cut at a
  cluster boundary, with nothing appended (the `~` mark is the caller's literal, so a truncated field can be
  told from a naturally short one). Implement it as `method().Truncate(s, w, "")` and state why in the comment:
  `ansi.Truncate` hardcodes grapheme semantics, so under tmux it would cut where `Width` does not agree.
  `w < 1` returns `""`.

`text_test.go`: unit tests for each function, at least: `Width("") == 0`; the CJK and ZWJ numbers above;
`Pad("ab", 5) == "ab   "`; `Pad("abcdef", 3) == Truncate("abcdef", 3)`; `Wrap` on a sentence with one token
wider than `w`; `Wrap(s, 0)` equals `Wrap(s, 1)`; `Truncate` on a string ending in a wide cluster returns a
prefix that is a cluster boundary (compare against the bytes of `s`). Every expected value in these tests must
be a literal string, not a recomputation through the package under test.

Avoid: caching a wrapped result anywhere, exporting anything but the four functions, and adding a `Strip` or a
colour helper here (that is `internal/render`'s).

Write `A4` as a property suite over a named corpus, in both environments, in one run.

The corpus (each entry a named case, so a failure names the string): a 15-cell handle
(`longhandle_name`), a 3-cell handle, a CJK run, a single emoji, the ZWJ family, a URL longer than 200 cells
with no spaces, a 10 000-cell body of ordinary prose, an empty string, a string of only spaces, a line of
exactly 57 cells, a line of 56 cells, and a string whose wide cluster sits exactly at each width boundary
under test.

For every corpus entry and every `w` in `{1, 2, 3, 5, 8, 57, 77, 96}`, assert:
- `Width(Pad(s, w)) == w`;
- `Width(Truncate(s, w)) <= w`;
- every line of `Wrap(s, w)` has `Width(line) <= w`;
- `Truncate(s, w)` is a prefix of `s` at a cluster boundary (`s` starts with the result, and the next byte in
  `s` is a cluster start under the active method);
- no line of `Wrap(s, w)` ends with a space.

Run the whole table twice — once with `TMUX` unset and once with `TMUX` set — by calling `t.Setenv` and
re-running the assertions, and require BOTH to hold: the properties are environment-independent, only the wrap
points move. Then assert the environment actually moved something, which is the arm that proves the dispatch is
live rather than a comment:

- `Width(<the ZWJ family>) == 2` with `TMUX` unset and `== 6` with `TMUX` set, and the two values differ;
- `Wrap(<the ZWJ family>, 4)` returns a different number of lines under the two environments, and with the
  environment set to tmux the family occupies 6 cells of the first line.

Anti-vacuity arms (a suite that would pass on a package that returned zeros must fail):
- a byte- or rune-counting measure cannot pass: assert `len("日本語のテキスト") != Width("日本語のテキスト")`
  and `len(<the ZWJ family>) != Width(<the ZWJ family>)` under both environments;
- a wrap that never breaks a long token cannot pass: for the 200-cell URL, assert that a single-token wrap
  (the naive result, computed in the test as the whole token) has a width greater than `w`, while `Wrap`
  returns every line within `w`;
- the corpus must be non-empty and every case must be exercised: count the cases and assert the count is the
  number of entries in the named table, so deleting a case fails the test rather than weakening it;
- assert `Truncate` returns a strict prefix for at least one case per environment (a `Truncate` that returned
  its input unchanged would pass the `<= w` check for short inputs alone).

Avoid: hard-coding an expected wrap layout for the family beyond the two facts above (the exact cluster widths
come from the pinned module, and a test that restates them a second time is a second source of truth);
avoiding any assertion that both environments must agree byte for byte — they must not, on wide clusters.
