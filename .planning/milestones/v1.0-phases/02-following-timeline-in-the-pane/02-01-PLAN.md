<objective>
Build the phase's read seam and list state machine: the content model, the `Source` port, the adapter that
implements it over the existing transport, a fake Source every screen can be driven from offline, and the
reducers that make pagination honest.

Purpose: five of this phase's fifteen requirements are honesty rules about the list itself (no duplicates, no
loop, no silent loss on a partial failure, no retry after a soft ban), and every later phase reads through the
same port. They are cheapest to prove here, before any pixel exists.

Output: `internal/domain` extended to the content model the UI-SPEC's Content/Presentation Split fixes,
`internal/xsource` implementing the port, `internal/fake` serving the recorded fixture, and `internal/screen`
holding the list state machine with tests that need no network, no session and no terminal.

Phase goal (ROADMAP, quoted): "The user reads their Following timeline in a terminal pane — scrolling back
through older posts and refreshing deliberately — and the pane never lies about what it is showing."
</objective>

`internal/screen/list.go`: `type List struct` holding what the UI-SPEC's frame definition lists, plus the
book-keeping the honesty rules need:
`Kind domain.HomeKind`, `posts []domain.Post` in list order, `pages []domain.PostPage`, `next domain.Cursor`,
`seen map[domain.PostID]bool`, `usedCursors map[domain.Cursor]bool`, `selected domain.PostID`,
`inflight bool`, `failure domain.Failure`, `newPosts int`, `loadingOlder bool`, `stalled bool`,
`refreshPending bool`, `headIDs []domain.PostID` (the ids the last refresh was asked to diff against).
Expose read-only accessors: `Posts() []domain.Post`, `Selected() domain.PostID`, `Next() domain.Cursor`,
`Inflight() bool`, `Failure() domain.Failure`, `NewPosts() int`, `LoadingOlder() bool`, `Stalled() bool`,
`Loaded() int`, `HasMore() bool` (`next != "" && !stalled`), and the pure lookups the shell needs to move a
selection without knowing pixel geometry: `Index(id) int`, `FirstID()`, `LastID()`, `NextID(after)`,
`PrevID(before)`, `Has(id) bool`, `AtEnd() bool` (the selection is the last loaded post and `HasMore()`).

`internal/screen/effect.go`: `type EffectKind uint8` with `EffectPage` and `EffectRefresh`, and
`type Effect struct{ Kind EffectKind; Feed domain.HomeKind; Cursor domain.Cursor; Head []domain.PostID }`. An
effect is a value; nothing here performs it.

`internal/screen/absorb.go`: the events and the rules.
- `PageRequested`: if `inflight`, if `stalled`, if `failure.Stopped`, if the cursor is empty, or if the last
  failure is not retryable yet, return no effect (a repeated key is a no-op, never a queued request). Otherwise
  latch `inflight` and `loadingOlder` and return one `EffectPage` carrying the cursor and the feed kind.
- `PageFetched(page)`: clear `inflight`/`loadingOlder`; mark the cursor used; append only unseen ids (dedupe
  keyed on `domain.PostID`) and count how many were new; set `next` to the page's next cursor and clear `failure`
  (a successful fetch is what ends a sticky state). If the page added zero unseen ids, or its next cursor equals
  the cursor just used, or its next cursor is already in `usedCursors`, set `stalled` and issue no further page
  for it — the walk ends there and the shell reports it. If `next == ""` the list is at its end.
- `PageFailed(failure)`: clear the latches, keep every post, every page and the selection exactly as they were,
  and store the failure. Nothing is cleared or replaced.
- `RefreshRequested`: if `inflight`, if `failure.Stopped`, or if the last failure is a not-yet-retryable one,
  no effect. Otherwise latch and return one `EffectRefresh` for page one carrying the currently loaded head ids
  as `Head`.
- `Refreshed(page)`: prepend the page's posts whose ids are not already seen (in the order the page carried
  them), set `newPosts` to that count, clear a now-resolved failure, and leave the selection id, the loaded
  pages and `next` untouched. A refresh that brings nothing new sets `newPosts` to 0, which the shell renders as
  the documented "no new posts" notice.
- `Select(id)`: ignore an id the list does not hold, so a prepend can never silently re-point the selection to
  another post.
- Retry gating: a not-retryable failure blocks effects until it is resolved or, for the rate-limit row, until
  `now >= failure.Reset` (take `now` as an argument to the reducer that needs it; no clock inside). `Stopped`
  blocks effects for the rest of the process, with no exception and no timer.

`internal/screen/list_test.go`, driven by `internal/fake` with its call counter:
- absorbing two pages that share three ids shows each id once and keeps list order;
- a repeated cursor sets the stall, and after it the fake's call count does not move on further `PageRequested`
  events;
- a page that adds nothing unseen sets the stall too;
- a partial failure keeps the posts and the selection and stores the failure;
- a refresh with unseen ids prepends them and reports the count, and the selected id does not change;
- a refresh with no unseen ids reports zero and does not move the selection;
- a page request while a page is in flight returns no effect and does not raise the call count;
- after a soft-ban failure the call count stays flat across `PageRequested` and `RefreshRequested` events;
- a rate-limited failure with a `Reset` in the future blocks, and the same failure with a `Reset` in the past
  allows one effect.

Avoid: any string the user reads (the words are `internal/render`'s), any file or network access, and any
timer — the stop rule is a flag, never a countdown.
