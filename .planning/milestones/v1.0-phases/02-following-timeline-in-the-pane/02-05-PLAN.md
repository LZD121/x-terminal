<objective>
Make the golden frames the view specification: generate the model corpus for every state at 60, 80, 120 and 200
columns, prove the required content and the required absences are in it, capture the same frames through a real
terminal inside tmux and in a bare Ghostty window, and assert the width properties over the whole corpus.

Purpose: REND-08 is how this project knows a width bug has not been introduced — a stored frame that a
terminal's own capture agrees with is the only check that covers wrapping, padding, cluster widths and colour
at once. It must follow the working renderer, because it pins that renderer's output.

Output: the stored corpus under `internal/render/testdata/`, the audit that keeps it adversarial, and two
capture harnesses (tmux, and a fixed-size PTY in Ghostty) whose disagreements are the bug report.

Phase goal (ROADMAP, quoted): "The user reads their Following timeline in a terminal pane — scrolling back
through older posts and refreshing deliberately — and the pane never lies about what it is showing."
</objective>

The names, at `H = 24` and the width the name carries — the UI-SPEC's list, in its order: `timeline_60`,
`timeline_80`, `timeline_120`, `timeline_200`, `empty_80`, `empty_120`, `loading_80`, `help_80`, `help_120`,

Rules the corpus must obey:
- **The environment is pinned in the test, never inherited.** Set `TMUX`, `TERM`, `COLORTERM` and `NO_COLOR`
  explicitly for every render (`t.Setenv`), because this host's non-interactive shells export `TERM=dumb` and
  `NO_COLOR=1` and an unpinned corpus would be generated differently in different shells.
- **The clock is injected**: `2026-10-14T09:12:00Z` with `TZ=UTC`, so the stamps in a stored frame never move.
- **Each frame has a tmux twin**: the frame containing any wide cluster is rendered twice — once with `TMUX`
  unset and once with it set — and the twin is stored as `<name>_tmux`. The UI-SPEC requires each environment to
  match its own stored frame because the measure switches with `$TMUX`; storing only one variant would make the
  capture comparison in tasks 2 and 3 unwinnable.
- The states come from the real code path: the timeline frames from `fake.Adversarial()` absorbed into a
  `screen.List`, the failure frames from `domain.Failure` values of the four named kinds (both with posts
  loaded and cold), the stalled frame from a list whose cursor repeated, the help frames from `keys.Rows()`
  mapped into `render.HelpRow`, and the colour frames from the same timeline state at each rung.
- Create the files with `-update` in this task, then re-run without it and require byte equality.

`corpus_test.go`:
- **The adversarial-content audit.** Read every stored frame and assert each required case is present in a
  *named* frame: a 15-cell handle and a 3-cell handle; a CJK run; a single emoji; a ZWJ family; a URL longer
  than the measure; a line that exactly fills the measure and one a cell shorter; a depth-1 and a depth-2
  quote; a quote below a longer body; a continuation pair with no blank row between them; a repost marker; a
  limited marker; a tombstone block; an attachment line with a singular noun and one with a plural; a selected
  block whose first row is not the pane's first row and one whose block is the pane's last visible row; and a
  status line carrying a failure state, a reset time and a three-digit budget.
- **The absences.** No stored frame contains an engagement count from the fixture's `Counts`, none contains a
  media URL, none contains a display name from the fixture, and the empty-state copy appears only in frames
  whose last fetch succeeded with zero posts — never in a frame carrying a failure state.
- **The width properties over the corpus**: `A7` — no row of text exceeds `min(W - 3, 96)` cells at any width;
  `A1` — `ansi.Strip` of the truecolor and of the mono colour frame are byte-identical; `A2` — each failure
  frame's status line contains that state's literal state word; `A3` — in the mono rung the muted fields are
  still delimited by column position and by two-cell separators.
- **Arms, so the corpus cannot shrink into vacuity**: assert the stored corpus holds at least the number of
  files this table generates (a deleted frame fails); assert each audited case was found in a frame named in
  the failure message; assert the strip comparison runs over a frame that contains at least one selected block,
  so "no colour" cannot pass trivially; and assert that the `narrow_79` frame's pane holds the narrow-pane
  line while its status line still renders.

Avoid: regenerating frames inside an assertion (every comparison reads the stored file), comparing a frame to
itself by recomputing it with the same call, and letting any test depend on the ambient `TERM`, `TMUX`,
`NO_COLOR` or the wall clock.

  <action>
Write the in-tmux half of the environment specification.

For each size `W ∈ {80, 120}` (H = 24): create a detached session of exactly that size
(`tmux new-session -d -s <unique name> -x <W> -y 24`), write the stored `<name>_tmux` frame into its pane
without a trailing newline (a trailing newline on the last row would scroll the pane and change what the
capture returns), read it back with `tmux capture-pane -p -t <session>`, then kill the session in a deferred
cleanup so a failing assertion cannot leave a session behind.

Compare the capture with the stored frame after stripping escape sequences from both sides with
`ansi.Strip`. Record why in the test's comment: tmux re-synthesises SGR runs when it captures a pane, so
byte-equality of escape sequences is not achievable, while the *text* is exactly what the width model governs —
and it is the text, the row count and the wrap points that this capture exists to check. The colour half of the
specification is covered by the model frames' rungs and by `A1` over the corpus.

Assert, with the same `internal/text` used by the renderer and never with a byte or rune count:
- the capture has exactly 24 rows and every row measures exactly `W` cells (this is what catches a wrap, a
  width-dispatch disagreement, or a frame that did not fill the pane);
- the captured text equals the stored frame's text for the same environment (line by line);
- the selected block's rows carry the selection mark in the captured text, so the selection is legible on a
  terminal that dropped every attribute;
- the status line is the capture's last row.

Skip with a printed reason only when `tmux` is not on `PATH`; never skip silently and never treat a missing
`capture-pane` result as a pass. The comparator's self-test arm: a deliberately perturbed copy of the frame
(one cell changed, and separately one row removed) must fail the comparison.

Avoid: capturing the pane the test itself runs in, leaving sessions alive on failure, comparing raw escape
bytes, and any sleep longer than the one needed for the pane to paint.
  </action>
