Build the render engine: the plain grammar, the post-block layout, the status line and the frame composer, with
every user-visible string in one file and the colour ladder behind one rung value.

decorations) and REND-04 (the colour ladder, `NO_COLOR`, `TERM=dumb`, no meaning by colour alone) are properties

the one transport fact the status line needs: the upstream's rate-limit reset instant.

through older posts and refreshing deliberately — and the pane never lies about what it is showing."

  <action>
Write the presentation vocabulary and the block layout. Package doc: this package owns every character the user
sees; it reads `domain` values and measures through `internal/text` only.

`copy.go` — every user-visible string in the phase as a named constant, so the phase's whole visible output can
be read in one file. No call site builds a sentence by concatenation except through a template with a
documented placeholder. Constants, in the order of the UI-SPEC's Copywriting Contract:
- the two empty-state headings (one per feed) and the empty-state body;
- the two loading lines (first page, one per feed);
- the narrow-pane line;
- the truncation mark (`~`) and the selection mark (`>`);
- the marker templates: repost provenance `reposted by {handle}`, `limited`, `continued`, `post unavailable`,
  `post text missing`, the attachment line `attachment: {n} {noun}[, {n} {noun}]` with the nouns
  `image`/`images`, `video`/`videos`, `gif`/`gifs` in that fixed order, and the quote prefix `> `;
- the status-line templates: the budget line `{n} request, {m} rate-limited` with its `requests` plural, the
  list words `following` / `for you`, the position format `{selected}/{loaded}` with the conditional `+`, and
  the notices `{n} new post` / `{n} new posts` / `no new posts` / `loading older posts` /
  `no older posts (cursor stalled)`;
- the state column and the terse remedy column, as two tables keyed by `domain.FailureKind`, one row per row of
  both state tables in the UI-SPEC, plus the rate-limit state composed as `rate limited` with the suffix
  `until 14:32` (local `HH:MM` when the reset is today) or `until Jan 02 15:04` (otherwise); a zero reset adds
  no suffix;
- the pane's failure body line is NOT a constant here: it is `domain.Failure.Detail`, the classifier's own
  sentence, printed verbatim.

The state words must be the classifier's own: `auth rejected` → `session expired`, `unknown operation` →
`operation id stale`, `proxy reached but upstream blocked` → `upstream blocked`, `session not configured` →
`no session file`, and every other row verbatim from `xweb.Outcome.Error()` / `netcheck.Outcome`. Write them as
literals here (copy is prose) and let task 3's `state_test.go` pin each one to the constant it came from. Where
the UI-SPEC's table and the classifier's constant are spelled differently (`signer or auth rejected`), the
classifier's spelling wins: the UI-SPEC's own rule is that the state field prints the classifier verbatim
except for the documented renames.

`grammar.go` — `type Grammar struct` with `Name string`, `HandleCols int`, `Stamp StampFormat`,
`BodyIndent int`, `MeasureCap int`, `Separator bool`, `Markers MarkerSet`,
`Identity func(domain.User) string`, `ShowCounts bool`, and `var Plain Grammar` with
`Name: "plain"`, `HandleCols: 16`, `BodyIndent: 2`, `MeasureCap: 96`, `Separator: true`,
`Identity: func(u domain.User) string { return u.ScreenName }`, `ShowCounts: false`, and the marker set from
`copy.go`. `StampFormat` holds the two absolute forms as constants and a `func (f StampFormat) Stamp(t time.Time) string`
returning exactly 12 cells: `Jan 02 15:04` for the stamp's own year (the injected `now`'s year) and
`Jan 02  2006` otherwise — never a relative word, so a frame is reproducible. `MarkerSet` holds every marker
literal, `QuotePrefix`, `QuoteDepthCap` (2) and `Truncation`.

`block.go` — the layout, with the widths exact:
- `type Block struct{ PostID domain.PostID; Rows []string }`.
- `func Blocks(posts []domain.Post, g Grammar, w int, selected domain.PostID, now time.Time) []Block` builds
  every block in list order. Content starts at column 2 (column 1 is always the selection column, so a row's
  first cell is the selection mark when the row belongs to the selected block and a space otherwise).
- Head row: `text.Pad(g.Identity(p.Author), g.HandleCols)` + one space + the 12-cell stamp, then each marker
  preceded by exactly two spaces, in the fixed order repost, limited, continued. A value wider than the handle
  column is truncated at a cluster boundary with the truncation mark in its last cell.
- Body row: `g.BodyIndent` spaces then the text wrapped to `measure = min(w - 3 - 2*depth, g.MeasureCap)`.
  The text is wrapped at render time from the unwrapped content value — nothing is wrapped in the model.
- Attachment row: the indent then the attachment template with the kinds counted and the nouns chosen by
  count, in the documented noun order. The media URLs are content and are never printed.
- Quote: prefix `g.Markers.QuotePrefix` repeated `min(depth, QuoteDepthCap)` times at the content origin, then
  the quoted post's own head/body/attachment rows at that prefix's origin, and so on. Nothing is omitted at
  depth 2; the prefix simply stops growing.
- Continuation: when a post's `ReplyTo` equals the id of the post immediately above it in the same author's
  list, the separator row between them is dropped and the lower post's head row carries the continuation
  marker. The rule is directional: a reply that appears above its parent gets no marker.
- Placeholders: a post with no text, no media and no quote whose visibility is fine renders the missing-text
  line as its only body row; an unavailable post renders the unavailable line as its only body row; a limited
  post renders its text and carries the limited marker.
- Selection never rides on colour: the mark is in the row itself.
- One entirely blank row separates blocks: `Blocks` emits it between two blocks and never after the last one,
  and it is dropped between a post and the continuation that follows it.

`block_test.go`: transcribe from the UI-SPEC's worked example (A) and from the 80-column frame the block rows
for: a plain post, a repost, a post with a depth-1 quote, a depth-2 quote, a continuation pair, a tombstone,
an attachment singular and plural, a 15-cell handle, and a selected block whose first row is not row 1. Every
expectation is a literal string with the leading selection cell included. Assert that the rendered block
carries none of the fields the list grammar must not print: the fixture post carries a non-zero
`Counts` and a `Media[0].URL`, and no number from `Counts` and no media URL appears anywhere in its rows.

Avoid: `fmt` (the frame is built by concatenation and `text.Pad`), any measurement other than through
`internal/text`, any emoji, box-drawing character or bold attribute, and any header, title, rule or footer.

`status.go` — the status line, one row, always present, never wrapped.
- `type NoticeKind uint8` with `NoticeNone`, `NoticeNewPosts`, `NoticeNoNewPosts`, `NoticeLoadingOlder`,
  `NoticeStalled`; `type StatusFields struct{ Failure domain.Failure; Notice NoticeKind; NoticeCount int; List domain.HomeKind; Selected, Loaded int; HasMore bool; Used, Limited int }`.
- `func StatusLine(f StatusFields, w int) string`: fields in the fixed order
  `{state}  {remedy}  {notice}  {list}  {position}  {budget}`, separated by exactly two spaces; an empty field
  is omitted together with its separator so no two adjacent gaps ever appear and no field moves to fill
  another's place. One left-aligned run: no right-aligned segment.
- Drop order when the line does not fit `w`: notice, then position, then list. The state, remedy and budget
  fields are never dropped — the budget is visible in every frame, including every failure frame. After all
  three droppable fields are gone, truncate the remainder at `w` with the truncation mark in the last cell.
- The state field is the state word from the copy tables, composed with the rate-limit reset suffix when the
  failure is the rate-limited row and its reset is non-zero; the remedy field is the terse column.

`frame.go` — `func Frame(blocks []Block, status StatusFields, w, h int) string` and its one narrow case:
- exactly `h` rows of exactly `w` cells, joined by `\n` with no trailing newline (so a frame can be written
  into a pane of exactly `h` rows without scrolling);
- the pane occupies rows 1..h-1, the status line is row `h`;
- column 1 of every row is the selection column, and every row is padded to `w` cells with spaces;
- blocks are laid out top to bottom, the first block at row 1, no leading separator; rows below the last block
  are blank but still emitted;
- below 60 columns the pane renders the single narrow-pane line and the status line still renders, with its
  fields dropped by the rule above;
- `Frame` never truncates a content row: a row wider than `w` is a bug in the block builder, and the test in
  task 3 of plan 05 asserts no stored frame needs truncation. (The status line is the one place truncation is
  legal.)

`internal/xweb` — the reset instant. The state line prints the upstream's own reset time, and nothing below
currently reads it:
- read `x-rate-limit-reset` (Unix seconds) alongside the existing `x-rate-limit-remaining`, as
  `func rateLimitReset(headers http.Header) (time.Time, bool)`;
- add `Reset time.Time` to `APIError` (zero when the header was absent) and populate it wherever an `APIError`
  is built on the classified path. Include it in the error's text as the instant, e.g.
  `reset 2026-10-14T14:32:00Z`, never as a countdown: a relative form would be a second clock in a program
  that has exactly one, and `doctor` prints the same instant without a second parse.
- extend `classify_test.go`: a 429 carrying `x-rate-limit-reset` yields an `*APIError` whose `Reset` equals
  that instant; a 429 without the header yields a zero `Reset`; the existing soft-ban and rate-limit rows are
  unchanged.

`status_test.go`:
- the six worked lines at 80 columns from the UI-SPEC, byte for byte, with `used = 200` and `limited = 12`;
- the drop order: shrink `w` from 120 to 40 and assert the fields disappear in the order notice, position,
  list and that state, remedy and budget survive at every width;
- never wrapped: `StatusLine(f, w)` returns one row for every `w` in 30..200, and its width is `<= w`;
- the rate-limited rows: with a reset later today, with a reset on another day, and with no reset, each
  renders a distinct line, and the two remedies differ;
- a state that is active with posts loaded prints a status line but no different pane (the pane is
  `Frame`'s business: assert the pane rows are those of the same list without the failure).

Avoid: any width measured outside `internal/text`, any right-aligned segment, wrapping the status line, and
any field order other than the one above.
  </action>

`palette.go` — the roles and the ladder.
- `type Rung uint8` with `RungTrueColor`, `Rung256`, `Rung16`, `RungMono`, and
  `func RungFromEnv() Rung` choosing once, from the environment only, never from config, never mid-session and
  never from a terminal query. Check order, and say in the comment why it is this order: `NO_COLOR` set and
  non-empty, or `TERM` empty or `dumb`, forces `RungMono` first — the opt-outs are opt-outs and must win;
  then `COLORTERM` containing `truecolor` or `24bit` gives `RungTrueColor`; then `TERM` containing `256color`
  gives `Rung256`; anything else with `TERM` set gives `Rung16`.
- `type Role uint8` with `RoleDominant` (no escape at all: the terminal's own foreground), `RoleMuted`,
  `RoleState`, `RoleStateStop`, `RoleSelection` (reverse video).
- `type Palette struct` holding the rung; `func (p Palette) SGR(role Role) string` returns the escape prefix
  for the role and `func (p Palette) Reset() string` the reset; in `RungMono` every role except
  `RoleSelection` returns the empty string, and when `TERM` is `dumb` even `RoleSelection` does (the `>`
  margin alone marks the selection).
- Values per rung, exactly as the UI-SPEC's table: muted `#8a8a8a` / 245 / `90`; state `#d7af00` / 178 / `33`;
  state-stop `#d75f5f` / 167 / `31`. The accent is for the state word of the status line and nothing else.

`help.go` — `type HelpRow struct{ Keys, Text, Group string }` and
`func Help(rows []HelpRow, w int) []string`: the rows in the order given, the keys column exactly 16 cells then
the help text, no heading, no border, no rule. `internal/render` does not import the keymap package; the shell
maps its table into `HelpRow`.

`palette_test.go`:
- the ladder: `COLORTERM=truecolor` gives truecolor; `TERM=xterm-256color` gives 256; `TERM=xterm` gives 16;
  `TERM=dumb` gives mono; `NO_COLOR=1` with `COLORTERM=truecolor` still gives mono; an empty `TERM` with no
  `NO_COLOR` gives mono. Use `t.Setenv` for each case and never inherit the ambient environment (this host's
  non-interactive shells export `TERM=dumb` and `NO_COLOR=1`).
- no meaning by colour alone, at the unit level: for each role and each of the four rungs, `ansi.Strip(painted)`
  equals the plain text, and the mono and truecolor strips of the same string are byte-identical;
- the mono rung emits no escape sequence at all except the selection's reverse video, and none at all with
  `TERM=dumb`.

`help_test.go`: the overlay has one row per input row, in order; the keys column is 16 cells (`text.Width`);
no heading, no border character; the overlay's rows are not wider than `w` at `w` in 60, 80, 120.

`state_test.go` — the pin that stops the screen's words drifting from the classifier's:
- assert every `domain.FailureKind` constant has exactly one state row and one remedy row in the copy tables,
  and that the number of rows equals the number of kind constants (a new kind without a row fails);
- for every kind whose row comes from `xweb.Outcome`, assert the copy table's state word equals that
  outcome's `Error()` — except the documented renames, each of which is asserted to differ from its source
  constant (so a missing rename fails too);
- for every kind whose row comes from `netcheck.Outcome`, the same, including the renamed row;
- assert the three remedy-bearing rows the phase promises are distinct from one another, and that the
  budget-spent row is keyed to `xweb.ErrRequestCap` in the doc comment;
- arm: assert the comparison table it iterates is non-empty and covers the four named states, so a table that
  lost a row cannot pass by iterating nothing.

This test imports `internal/xweb` and `internal/netcheck`; that is allowed here because it is a test file, and
the shell plan's boundary test scans non-test files only.

Avoid: any second colour table, any glyph other than the ASCII literals in `copy.go`, and any state word that
is not traceable to a classifier constant.
