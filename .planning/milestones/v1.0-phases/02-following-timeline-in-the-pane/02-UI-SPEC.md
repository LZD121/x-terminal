# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | `none` — no CSS design system; a Go terminal program |
| Preset | not applicable |
| Component library | `charm.land/bubbletea/v2` v2.1.0 (runtime only) + `charmbracelet/x/ansi` v0.11.9 (SGR, width) — no widget library, see notes |
| Icon library | `none` — ASCII glyphs only; no emoji, no Nerd Font, no box-drawing characters |
| Font | the terminal's own monospace cell; the program sets no font, size, weight or line height |

**Notes.**

- **No widget library for the pane.** `bubbles/v2`'s `viewport` and `list` are *not* used for the
  timeline, the status line or the help overlay. Reason: this design scrolls by *block* and
  anchors on a post id (see `## Keymap Contract`), and its text column is *capped* at a maximum
  measure — both are outside what a line-based viewport expresses. The pane, the status line and the
  help table are rendered by `internal/render` from the model. This is a deliberate deviation from
  the package sketch in `.planning/research/ARCHITECTURE.md` ("L0 bubbletea Model/Update/View,
  keys, golden frames"), which did not fix a layout; the layering it does fix is preserved.
- **Package split this phase adds.** `internal/text`, `internal/render`, `internal/keys` and
  `internal/screen` are pure: no I/O, no `tea`, no `context.Context`. The last three are not:
  - `internal/text` — `Width`, `Wrap`, `Pad`, `Truncate`; the only string measurement in the program.
  - `internal/render` — `Grammar`, the marker/copy constants, block/status/help rendering.
  - `internal/keys` — the keymap table (consumed by input handling, the help overlay and the
    `keys` subcommand's output).
  - `internal/screen` — reducers (timeline list state, page cache, dedupe, stall detection).
  - `internal/tui` — the Bubble Tea `Model`/`Update`/`View`, frame composition, golden frames.
  - `internal/domain`, `internal/xsource` — assigned to this phase by the roadmap; `domain`
    declares the `Source` port (which does take a `context.Context`) and `xsource` implements it.
    Neither may import `tea`, and neither may hold a user-visible string.
- **No registry, no third-party design assets.** Nothing in this phase is fetched, installed or
  themed at runtime; the surface is text the program emits.
- **Every user-visible string is a named constant in `internal/render/copy.go`.** No renderer site
  builds a sentence by concatenation except through a grammar template with a documented
  placeholder. A reviewer must be able to read the phase's entire visible output in one file.

## Spacing Scale

**Declared exception (the medium has no pixel grid).** The template's scale is in CSS pixels. A
terminal has no pixel grid the program can see, and the program never sets a font, so a
pixel value here would be a fabricated claim about the user's font size. The unit of this design
is the **cell** (1 column) and the **row**. The values below are the 4-multiple anchors of the
standard scale, with the cell values this layout actually uses.

| Token | Value | Used as | Usage |
|-------|-------|---------|-------|
| xs | 4 | 1 cell | the selection column (column 1); the handle-to-stamp separator |
| sm | 8 | 2 cells | the body indent; the quote prefix per nesting level; the field separator in the status line |
| md | 16 | 16 cells | the identity column (the handle field); the help overlay's key column |
| lg | 24 | 1 blank row | the block separator — the only separator between posts |
| xl | 32 | — | reserved; unused in Phase 2 |
| 2xl | 48 | — | reserved; unused in Phase 2 |
| 3xl | 64 | — | reserved; unused in Phase 2 |

Exceptions: `xs` renders as **1** cell and `sm` as **2** cells — both below the 4-multiple of their
anchor, because a terminal row of 80 cells cannot afford 8-cell gutters and the reading width is
the scarce resource. Every other value in the layout is one of the five above. No layout value is
fractional, computed from a percentage, or derived from the content's length.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | the terminal cell (not settable) | regular | 1 row (1.0) |
| Label | same cell | regular | 1 row |
| Heading | n/a — Phase 2 renders no heading; a heading is a banner (`REND-01`) | — | — |
| Display | n/a | — | — |

- **Zero font sizes and zero font families are declared**, because the program cannot set them;
  there is exactly **one** text attribute in the whole surface: **reverse video (SGR 7)**, used
  only for the selected block. The program never emits bold (SGR 1), underline or blink: bold is
  rendered as a colour change by many terminal themes and would add a third weight.
- Emphasis is carried by **column position and literal marks**, never by a heavier or larger glyph.
- The body line height is exactly one row; the only vertical rhythm is the block separator row
  defined in `## Spacing Scale` (token `lg`).
- Line length is capped (see `## Width Model`): a 120-column pane does **not** produce 120-cell
  lines. The cap is the typographic measure, not a layout accident.

## Color

**60 / 30 / 10 split, in cells of screen area:** 60% is body text and handles at the terminal's own
default foreground on its own background (the program paints no background at all); 30% is muted
metadata (stamps, markers, the status line, the attachment line, the help overlay's key column);
10% is the single accent, reserved for one element.

| Role | Share | Value per rung (see ladder below) | Usage |
|------|-------|-----------------------------------|-------|
| Dominant | 60% | terminal default foreground | post text, handles |
| Secondary (`muted`) | 30% | `#8a8a8a` / 245 / `90` | stamps, markers, status line, attachment line, help key column |
| Accent (`state`) | ≤10% | `#d7af00` / 178 / `33` | **only** the state word of the status line while a recoverable failure state is active |
| Accent (`state-stop`) | ≤10% | `#d75f5f` / 167 / `31` | **only** the state word of the status line when the session is stopped (`session expired`, `soft ban`, `budget spent`) |
| Selection | n/a | SGR 7 (reverse) | the selected block, all of its rows |

**Accent reserved for:** the state word of the status line, and nothing else. Not the selected
row, not links, not the list name, not the budget, not the help overlay, not any body text. Two
accent values exist as one role with two semantic values — `state` (recoverable: wait, retry,
re-check) and `state-stop` (the session is over: re-authenticate or restart) — because those two
cases call for different human actions. **The copy states the difference in words**; colour only
repeats it (see the no-colour-alone assertion below), which is why this is one role and not a
decorative pair.

**Degradation ladder.** Chosen once at start-up, from the environment, in this order:

| Rung | Selected when | Rendering |
|------|---------------|-----------|
| truecolor | `COLORTERM` contains `truecolor` or `24bit` | the hex values above |
| 256 | `TERM` contains `256color` | the 256-column values above |
| 16 | `TERM` is set, is not `dumb`, and matches neither of the above | the ANSI values above (`33`, `31`, `90`) |
| mono | `NO_COLOR` is set and non-empty, or `TERM` is `dumb` or empty | no SGR for any role; the selection keeps SGR 7 unless `TERM=dumb`, in which case the `>` margin alone marks it |

`NO_COLOR` is honoured when *set and non-empty* (`https://no-color.org/`). The rung is chosen from
the environment only — never from a config setting, never re-evaluated mid-session, never from a
terminal query (a query would add a round trip to the first frame).

**Testable assertions.**

- **A1 — no meaning is carried by colour alone.** Strip every SGR sequence from a rendered frame
  and the frame must still be unambiguous: the state word, the remedy, the `>` selection mark,
  every marker literal and the list name are all present as characters. Test: render every golden
  frame with the rung forced to `truecolor` and to `mono`, `ansi.Strip` both, and compare — the
  two stripped frames must be byte-identical.
- **A2 — the state is a literal.** For each row of the state table in `## Copywriting Contract`,
  the rendered status line contains that row's `state` string as literal text, and the frame
  contains no SGR before it other than the one colour role.
- **A3 — mono is readable, not merely legal.** In rung `mono`, every muted field is still
  delimited by punctuation or column position: the stamp is separated from the handle by two
  cells, markers are separated from the stamp by two cells, and the status fields by two cells.

## Copywriting Contract

Every string below is a constant in `internal/render/copy.go` and is English only (no i18n layer).
Chrome (markers, states, remedies, hints) is **ASCII only**; post text and handles are rendered
verbatim in whatever script they arrive in.

| Element | Copy |
|---------|------|
| Primary action (the phase's one new user action) | `r` — `fetch newer posts, keep the place` |
| Empty state heading | `no posts in following` / `no posts in for you` |
| Empty state body | `this is an empty read that succeeded - press r to refresh` |
| Loading, first page | `loading following...` / `loading for you...` |
| Error state (status line, see the state table) | `{state}  {remedy}` — a distinct remedy per state, never a bare "failed" |
| Error state (pane, when there is nothing to show) | the state word as a head row, and `xweb.Outcome.Remedy()` verbatim as its body line |
| Destructive confirmation | none — this phase performs no destructive action. `ctrl+c` is immediate and destroys nothing on disk (the timeline is never persisted); the only loss is the in-memory list |
| Pane too narrow | `widen the pane to at least 60 columns` |
| Truncation mark | `~` in the last cell a truncated field may occupy |

**Marker literals (the plain grammar).** Order on the head row is fixed: repost, then limited, then continued.

| Marker | Literal | Place |
|--------|---------|-------|
| repost provenance | `reposted by {handle}` | head row, after the stamp |
| limited visibility | `limited` | head row |
| thread continuation | `continued` | head row, last |
| post unavailable | `post unavailable` | body, as the only line |
| body missing upstream | `post text missing` | body, as the only line (text empty, no media, no quote, visibility OK) |
| attachment | `attachment: {n} {noun}[, {n} {noun}]` | body; nouns `image`/`images`, `video`/`videos`, `gif`/`gifs`, in that fixed order |
| quote prefix | `> ` per nesting level, capped at 2 levels | every row of the quoted block |
| selection | `>` in column 1 | every row of the selected block |

**Status-line vocabulary** (fields separated by exactly two spaces; see `## The Status Line` for
the field order and the drop rule).

| Field | Copy |
|-------|------|
| `budget` | `{n} request, {m} rate-limited` / `{n} requests, {m} rate-limited` (singular at `n == 1`) |
| `list` | `following` / `for you` |
| `position` | `{selected}/{loaded}` plus `+` when a next cursor is stored, e.g. `12/240+` |
| `notice` | `{n} new post` / `{n} new posts` / `no new posts` / `loading older posts` / `no older posts (cursor stalled)` |

**The four named failure states** (`OPS-01`), each with its exact copy. `state` and `remedy` are the
status line's first two fields; the pane's body line, when the pane has no posts to show, is the
`xweb.Outcome.Remedy()` sentence verbatim (Phase 1's own words, `internal/xweb/classify.go`).

| # | Named state | `state` field | `remedy` field | Pane body line (verbatim) |
|---|-------------|---------------|----------------|---------------------------|
| 1 | expired session | `session expired` | `copy the cookie again` | `session missing or expired - re-copy the cookie` |
| 2 | rate limited | `rate limited until 14:32` (computed reset, local `HH:MM`; `until Jan 02 15:04` when the reset is not today; `rate limited` when no reset header was sent) | `no retry` (with a time) / `no retry; reset unknown` (without) | `wait until the reset time from x-rate-limit-reset` |
| 3 | offline / no route | `no route to x.com` | `check the proxy` | the failing `netcheck.Result.Detail` sentence |
| 4 | upstream shape change | `operation id stale` (404 with an empty body) / `bad request` (400, 422) / `empty response body` (2xx, zero bytes) / `unauthorized` (200 carrying `errors[]`) | `doctor --refresh-ids` / `do not retry` / `re-check the route` / `see doctor for the message` | `the operation id is stale or unknown - refresh the registry or pin it` / `the request shape was rejected - fix the variables or features it names; do not retry` / `the upstream answered with no body at all; that is not an empty timeline - re-check the route and do not render it as data` / `print the API's own message from the errors[] body` |

**The rest of the state vocabulary** (the taxonomy is closed; every state the classifier can
return has a row here, so no failure can render as nothing). The `state` field prints
`xweb.Outcome.Error()` verbatim except for the four documented renames marked `*`.

| `state` | `remedy` |
|---------|----------|
| `session expired` * (was `auth rejected`) | `copy the cookie again` |
| `signer or auth rejected` | `add a transaction id` |
| `operation id stale` * (was `unknown operation`) | `doctor --refresh-ids` |
| `endpoint retired` | `do not retry` |
| `rate limited until 14:32` / `rate limited` | `no retry` / `no retry; reset unknown` |
| `soft ban` | `stop for the session` |
| `load shed` | `backoff, then retry` |
| `bad request` | `do not retry` |
| `empty response body` | `re-check the route` |
| `edge challenge` | `an edge page, not the API` |
| `unauthorized` | `see doctor for the message` |
| `unclassified` | `record this shape first` |
| `budget spent` (`xweb.ErrRequestCap`) | `restart to reset the budget` |
| `no route to x.com` | `check the proxy` |
| `proxy refused` | `start the proxy` |
| `upstream blocked` * (was `proxy reached but upstream blocked`) | `check the proxy` |
| `TLS/Cloudflare challenge` | `check the proxy` |
| `transport unusable` | `fix the proxy setting` |
| `no session file` * (was `session not configured`) | `write the session file` |

Rename justification, all four: the outcome name describes the *mechanism* and would misinform a
user about their account (`auth rejected` reads as "my account is bad", `unknown operation` reads
as "I typed something wrong", `proxy reached but upstream blocked` reads as a proxy success,
`session not configured` reads as a setting the user got wrong when the file merely is not there).
The short remedy is a second, deliberately terser column; `Outcome.Remedy()` remains the sentence
both the pane and `doctor` print, and a totality test asserts every `Outcome` has a row here.

**Worked status lines at 80 columns** (`used = 200`, `limited = 12`; the widest realistic line):

```
3 new posts  following  12/240+  200 requests, 12 rate-limited
session expired  copy the cookie again  following  200 requests, 12 rate-limited
rate limited until 14:32  no retry  following  200 requests, 12 rate-limited
no route to x.com  check the proxy  following  200 requests, 12 rate-limited
operation id stale  doctor --refresh-ids  200 requests, 12 rate-limited
soft ban  stop for the session  following  200 requests, 12 rate-limited
```

All six fit 80 cells: `notice` and `position` are the first fields dropped where they do not fit,
and the fifth line drops `list` as well — with `following` it would be 82 cells, two more than the
pane. At 60 columns a failure line has lost `notice`, `position` and `list`, and the remainder is
cut at the pane with `~` in its last cell. (The fifth line was corrected against the implementation;
see the correction note at the end of `## Screen Grammar`.)

## Screen Grammar

### The grid

The frame is exactly `H` rows of exactly `W` cells, always (a full-height repaint; no partial
region is ever left stale). Two regions, no others:

```
row 1        .. row H-1 : the pane (list, help overlay, or a state block)
row H                   : the status line
```

Column 1 of **every** row is the selection column: `>` when the row belongs to the selected
block, a space otherwise. Content therefore starts at column 2. There is no title row, no header,
no footer, no box, no rule, no border, no margin, no logo, no version string, no hint line.

### The post block

A block is one contiguous group of rows. Rows, in order, with widths exact:

| Row | Layout | Width |
|-----|--------|-------|
| head | `{handle:16} {stamp:12}` then each marker preceded by two spaces | 32 cells before markers |
| body | two spaces, then the post text wrapped to the measure (below) | 2 + measure |
| attachment | two spaces, then `attachment: ...` | content |
| quote | `> ` × depth, then the quoted post's own head/body/attachment rows at that prefix's origin | 2 × depth + its own layout |
| separator | one entirely blank row, between blocks only | W |

- **Identity.** The head row's first field is the author's **handle without `@`**, left-aligned and
  padded with spaces to exactly 16 cells. A legal x.com handle is at most 15 cells, so the column
  fits every legal handle with one cell to spare; a wider value (an over-long handle, a Phase 3
  alias, a handle containing a wide cluster) is truncated at a cluster boundary and its last cell
  becomes `~`. **Display names are deliberately absent from the list view** — they are the main
  carrier of decoration, emoji and impersonation on this upstream, and the handle identifies a
  followed account without them. They appear in the post-detail header (Phase 4).
- **Time.** Absolute, local, fixed width 12 cells, never relative, never a relative word
  ("2h ago"): `Jan 02 15:04` for the current year, `Jan 02  2006` for any other year (both exactly
  12 cells, so the column never moves). The clock is injected, so a frame is deterministic.
- **Body.** The text is stored **unwrapped** and wrapped at render time to
  `measure = min(W - 3 - 2*depth, 96)` cells. Break on the last space that fits; a token wider
  than the measure (a URL, a CJK run) is broken at a cluster boundary with no hyphen inserted (a
  hyphen is a claim about the text). A line never ends with a trailing space.
- **What is deliberately absent.** No avatars, no display names, no `@` sigils on the identity
  column, no engagement counts (`REND-01`; the detail view is where `Counts` may be printed as
  plain text), no icons or emoji decorations, no separators that draw attention (no rules, no
  boxes, no alternating background), no inline images, no URLs printed as text (Phase 7 adds
  links), no reply marker (the conversation belongs to the detail view), no "thread" affordance
  word beyond `continued`, and no numbering of posts.

### The four relationships, told apart by words, not by colour

| Case | How it renders | Why it cannot be confused with the others |
|------|----------------|-------------------------------------------|
| plain post | head + body | — |
| repost (`Repost != nil`) | the head row names the **original** author and carries `reposted by {handle}` | a repost is *provenance*: the same text, attributed to who wrote it and to who surfaced it |
| quote (`Quote != nil`) | the post's own head + body, then a nested block prefixed `> ` per level | a quote is *content inside another post*: a new post that embeds one, not a re-attribution |
| continuation (`A.ID == B.ReplyTo && A.AuthorID == B.AuthorID`, A directly above B) | no separator row between A and B, and B's head row carries `continued` | the marker says the reply is a reply *to the block above it*; the rule is directional, so a newest-first payload that puts a reply above its parent marks nothing rather than marking the wrong block. `[INFERENCE]` that upstream's thread module is what produces the parent-above-reply adjacency |

Quote nesting prefix is capped at depth 2 (4 cells): deeper content is rendered with the same
prefix and the same text, so the measure cannot collapse; nothing is omitted. `[INFERENCE]` this
cap; a third-level quote is pathological in a Following timeline.

### The pane

- Blocks are laid out top to bottom in list order; the first block starts at row 1 (no leading
  separator), and the last block's last row may be the pane's last row.
- Rows below the last block are blank; they are still emitted (the frame is full height).
- The selected block's rows are marked with `>` in column 1 and with reverse video (SGR 7) when the
  rung allows SGR; the marker is what carries the meaning (`A1`).
- The selection is a **post id**, never a row index.
- Empty, loading and failure states are rendered **in the same block shape**, so the pane never
  looks like a different kind of screen:
  - loading: `loading following...` as a head-row-shaped line, then nothing;
  - successful-but-empty: the empty heading as the head line and the empty body as the body line;
  - failure with nothing to show: the state word as the head line and the remedy sentence as the
    body;
  - failure with posts already loaded: **the posts stay exactly where they were**; nothing is
    cleared or replaced; the status line carries the state (`FEED-05`).

**Visual hierarchy (the focal point).** First, the selected block: the `>` in column 1 plus the
reverse-video bar, at a fixed screen row as the list scrolls. Second, the identity column, whose
fixed 16-cell field makes the author a scannable column rather than a per-post banner. Third, the
status line, whose only emphasised element is the accent-coloured state word. Nothing else in the
frame is emphasised: no bold, no background, no second accent, no rule, no box, no glyph louder
than a handle.

## The Status Line

One row, always the last row, always present, never wrapped. Fields in this fixed order,
separated by exactly two spaces:

```
{state}  {remedy}  {notice}  {list}  {position}  {budget}
```

- An empty field is omitted entirely, together with its separator: nothing renders as two
  adjacent gaps, and no field moves to fill another's place.
- **Drop order when the line does not fit `W`: `notice`, then `position`, then `list`.**
  `state`, `remedy` and `budget` are **never** dropped — the budget is visible in every frame
  (`OPS-02`), including the frames of every failure state. After all three droppable fields are
  gone, the remainder is truncated at `W` with `~` in the last cell.
- One left-aligned run: no right-aligned segment, so dropping a field never moves another.

**Behaviour of the failure states.**

- A state is **sticky**: it stays in the status line until the next action succeeds (a refresh or
  a page fetch that returns data). No timer clears it, no frame count clears it.
- While a state is active, `r` and the pagination trigger are disabled for the states whose remedy
  is "do not retry" (`rate limited` before its reset, `soft ban`, `budget spent`, `bad request`,
  `endpoint retired`) and enabled after `session expired` (so a re-copied cookie takes effect
  without a restart).
- **`soft ban` stops the session** (`OPS-04`): the pane stops appending, the state line renders
  `soft ban  stop for the session`, the state colour is `state-stop`, and no request is issued
  again for the life of the process. The state word is rendered *because* the budget line next to
  it shows a non-zero remaining budget — that combination is the evidence the user sees that this
  is not an ordinary rate limit.
- **An empty list is never rendered for a failure.** The empty-state copy renders only when the
  last fetch returned `OutcomeOK` with zero posts. Testable: for every row of the state table,
  the rendered frame must not contain `no posts in following`.
- A fetch that fails partway keeps every post it did receive (`FEED-05`) and appends no partial
  block: a page that fails decodes to nothing at all, and the failure goes to the status line.
- The position's `+`: present while a next cursor is stored, absent at end-of-list, so the pane
  never implies there is more than the cursor says. A stalled cursor ends the walk, prints
  `no older posts (cursor stalled)` in `notice`, and never retries the same cursor (`FEED-03`).

**Named compromise.** At 80 columns, a failure state plus the budget can consume the whole line,
and `list` is the third field dropped — so at 80 columns with a three-digit request count and the
widest state names (`signer or auth rejected`, `edge challenge`), the words `following` / `for you`
are not on screen. The widest such line, `signer or auth rejected  add a transaction id  following
200 requests, 12 rate-limited`, is 87 cells, so above 87 columns the list name stays too and only
`notice` and `position` are still dropped when they do not fit. The alternative (shortening the
budget to `200 req / 12` or the state names further) was rejected: the budget copy is the
requirement's own wording, and the state names are the classifier's.

## Width Model

One measurement, four functions, one package: `internal/text`.

| Function | Signature | Contract |
|----------|-----------|----------|
| `Width` | `func Width(s string) int` | the **only** string measurement in the program. Dispatches on `$TMUX`: set → `ansi.StringWidthWc` (codepoint/`wcwidth` semantics, which is what a multiplexer's grid models), unset → `ansi.StringWidth` (grapheme-cluster semantics, which is what Ghostty implements). Both are verified present in `charmbracelet/x/ansi` v0.11.9 (2026-10-14). The dispatch is one function with this comment; nothing else in the program may branch on `$TMUX` for width. |
| `Wrap` | `func Wrap(s string, w int) []string` | greedy wrap on spaces; a token wider than `w` breaks at a cluster boundary; no hyphen is ever inserted; `Width(line) <= w` for every returned line; the concatenation of the returned lines preserves the input's non-space characters in order (no loss, no duplication); `w < 1` is treated as 1. |
| `Pad` | `func Pad(s string, w int) string` | `Width(Pad(s, w)) == w` exactly; if `Width(s) > w` it returns `Truncate(s, w)` rather than a too-wide string. |
| `Truncate` | `func Truncate(s string, w int) string` | the longest prefix with `Width <= w`, cut at a cluster boundary; appends nothing (the `~` mark is the *caller's* literal, so a truncated field can be told from a naturally short one). Not `ansi.Truncate`, which hardcodes grapheme semantics. |

Cluster iteration inside `Wrap`/`Truncate` must come from the same module as the measurement
(`charmbracelet/x/ansi`, which segments with `rivo/uniseg`); the planner confirms the exact
iterator symbol against the pinned version, and that iterator is the only one used. There is no
third width library.

**Agreement, as testable properties.**

- **A4 — the functions agree with each other and with the environment.** For every fixture string
  (including the adversarial set below) and every `w` in `{1, 2, 3, 5, 8, 57, 77, 96}`:
  `Width(Pad(s, w)) == w`; `Width(Truncate(s, w)) <= w`; every `Wrap` line has `Width <= w`;
  `Truncate(s, w)` is a prefix of `s` at a cluster boundary. Run once with `TMUX` unset and once
  with it set, and assert **both** hold — the properties are environment-independent, only the
  wrap points move.
- **A5 — the frame is a pure function of (state, W, H).** Rendering the same state at a new size
  after a resize produces the same bytes as rendering that state at that size directly: no cached
  wrapped text, no sticky column widths, no `len()` anywhere. Test: drive the model through a
  resize and compare with a cold render at the target size.
- **A6 — no second measurement.** An AST test asserts that `internal/tui`, `internal/screen`,
  `internal/render` and `internal/keys` do not import `unicode/utf8`, do not call `len()` on a
  `string`, and do not use `fmt` width verbs (`%*s`, `%-*s`, `%.*s`). `internal/text` is the only
  package that may measure, and `internal/text` itself must not call `fmt` at all.
- **A7 — the measure is capped.** No rendered row of any golden frame exceeds
  `min(W - 3, 96)` cells of text, at any width, including 200.

### Golden Frames (`REND-08`)

The golden frames are the view specification. Two kinds:

1. **Model frames (checked in, byte-compared in CI).** `Render(model, W, H) string` for each state
   below at `W ∈ {60, 80, 120, 200}` and `H = 24`, with an injected clock (`2026-10-14T09:12:00Z`,
   `TZ=UTC`) and a fake `Source` that returns fixed pages:
   `timeline_80.txt`, `timeline_120.txt`, `timeline_200.txt`, `timeline_60.txt`,
   `empty_80.txt`, `empty_120.txt`, `loading_80.txt`, `help_80.txt`, `help_120.txt`,
   `expired_80.txt`, `expired_120.txt`, `offline_80.txt`, `offline_120.txt`,
   `schemachange_80.txt`, `schemachange_120.txt`, `stalled_80.txt`, `narrow_79.txt`,
   and one frame per colour rung (`color_{truecolor,256,16,mono}.txt`).
2. **Terminal captures (the environment half of the specification).** The same fixtures captured
   inside tmux (`tmux capture-pane -p`, 80×24 and 120×24 panes) and outside tmux in Ghostty (the
   frame written to a fixed-size PTY, with the cursor position read back via DSR to prove the
   terminal agreed with the row count). Both captures must equal the stored model frame for their
   environment **byte for byte**; a pair that differs is the bug report, not an expected
   difference. Because the measure switches with `$TMUX` (see `Width`), a frame containing a ZWJ
   cluster legitimately wraps differently in the two environments — that difference is exactly
   what the switch models, and each side must match *its own* stored frame. `[INFERENCE]` the
   capture harness shape (PTY + DSR read-back outside tmux, `capture-pane` inside); the planner
   validates it is reachable before planning it as a step.

**Every stored frame must contain**, so that a width bug cannot hide:

- a 15-cell handle (`longhandle_name`) and a 3-cell handle, proving the fixed identity column;
- a CJK run (wide clusters), a single emoji, and a ZWJ family (one cluster by grapheme semantics,
  six cells by `wcwidth`), so a `len()`- or rune-based measure is wrong in one environment or the
  other;
- a URL longer than the measure, so the break-long-token path is exercised;
- a line that exactly fills the measure and a line one cell shorter, so an off-by-one is visible;
- a quote at depth 1 and at depth 2, and a post whose body contains a quote below a longer body;
- a continuation pair (no separator row between the two, `continued` on the second);
- a repost marker, a `limited` marker and a tombstone block;
- an attachment line with a singular noun and one with a plural;
- a selected block whose first row is **not** the pane's first row, and, in a second frame, a
  selection whose block is the pane's last visible row;
- a status line with a failure state, a reset time, and a three-digit budget.

## Keymap Contract

One table, in `internal/keys`, is the single source for input handling, the `?` help overlay and
the shell completion output (`REND-05`). Adding a key is one row.

| Keys | Action | Help text (rendered verbatim) | Group |
|------|--------|-------------------------------|-------|
| `j` `down` | `next` | `next post` | navigate |
| `k` `up` | `prev` | `previous post` | navigate |
| `ctrl+d` | `half-down` | `half a pane down` | navigate |
| `ctrl+u` | `half-up` | `half a pane up` | navigate |
| `pgdown` | `page-down` | `one pane down` | navigate |
| `pgup` | `page-up` | `one pane up` | navigate |
| `g` `home` | `first` | `first loaded post` | navigate |
| `G` `end` | `last` | `last loaded post` | navigate |
| `r` | `refresh` | `fetch newer posts, keep the place` | feed |
| `t` | `toggle-feed` | `switch between following and for you` | feed |
| `?` | `help` | `show or hide this list` | view |
| `q` `esc` | `back` | `back, or quit at the start` | app |
| `ctrl+c` | `quit` | `quit now` | app |

**Nothing else is bound in Phase 2.** Opening a post is Phase 4's row; opening media and copying
a link are Phase 7's rows. This phase adds no row for them, so no key is documented that does not
work.

- **Pagination has no key of its own.** `j`, `ctrl+d`, `pgdown` and `G` at the last loaded post
  trigger the next page (single-flight: further presses are no-ops, not a queue), and the
  selection does not move until the page arrives, so a slow or failed page never moves what the
  user is reading. This is the keymap's only implicit binding, and the help text above is what
  documents it. (`FEED-02`)
- **`refresh`** re-requests the first page with the ids currently rendered and prepends only
  unseen ids (`FEED-04`): the selected post id is unchanged, the anchor holds, and the notice
  field announces `{n} new posts` or `no new posts`. Pressing `r` while a page is in flight is a
  no-op (the key is debounced, so key-repeat cannot burst requests).
- **Help is a modal overlay, not a stack frame.** While it is open it replaces the pane with the
  table (keys column 16 cells, then the help text, in table order, no heading, no border) and the
  status line stays as it is. In this mode `help` and `back` close it and every other action is
  ignored — no key reaches the list. No new key exists for closing it; that is what shadowing
  means here.
- **`q`/`esc` pop the frame stack; at the bottom frame they quit.** `ctrl+c` always quits
  immediately. The stack is one frame per screen state, and this phase's only producer of a
  second frame is `toggle-feed` (`t` pushes the other feed's frame; `t` again pops it, so the key
  is a true toggle). Phases 4–7 push post, thread, profile and search frames through the same
  mechanism (`REND-06`).
- **The frame is `{list kind, the pages loaded in it, the opaque cursor, the selected post id,
  the anchor}`.** Non-top frames are frozen: a refresh applies only to the top frame.
- **`restore the previous list, selection and scroll` means, observably:**
  1. the same post ids in the same order, with **zero new requests** — the fake `Source` counts
     calls, and the count at pop equals the count at push;
  2. the same **post id** selected, not the same row index (so a prepended refresh on the top
     frame cannot silently re-point the selection);
  3. the selected block's head row back at the same pane row as when the frame was pushed (the
     anchor is that row distance, clamped to the pane) — so the frame the user returns to is
     pixel-identical to the frame they left;
  4. nothing else restored: notices, the in-flight latch and the failure state are per-process,
     not per-frame, and a failure raised while a frame is stacked is still on the status line
     when it is popped.
  Golden test: `list@position -> t -> t` must byte-compare equal to `list@position`.
- **Mouse input is never enabled** (no mouse reporting option is set), so the terminal keeps its
  own text selection and middle-click paste. The program emits no `BEL` and does not set the
  window title in this phase (the title belongs to Phase 3's cover).
- **Keymap is code, not configuration, in Phase 2.** The config file's keymap seed stays empty:
  rebinding is not a requirement, and a second source for the table would break the "one table"
  property the help and the completion depend on. `[INFERENCE]` recorded because Phase 1's
  research notes mentioned a keymap seed.
- **Shell completion.** A `keys` subcommand is added to `internal/cli`'s command table and prints
  the table as one row per binding, tab-separated: `keys<TAB>action<TAB>help`, in table order. The
  shipped bash/zsh/fish completion scripts read it. No string in the completion output is written
  by hand.

## Content / Presentation Split

The split exists so that Phase 3 can wear the same views as a work-software cover and so that a
cover is a renderer mode, not a rewrite. The rule: **content owns what is true about a post;
presentation owns every character the user sees.** No `domain` value ever contains a rendered
string, and no renderer ever reads upstream JSON.

### Content (`internal/domain`, produced by `internal/xsource`, never a string the renderer prints)

| Field | Owner | Notes |
|-------|-------|-------|
| `Post.ID` (`PostID`) | content | identity for dedupe, selection, refresh diffing, the anchor |
| `Post.Author` → `User{ID, ScreenName, Name, AvatarURL, BannerURL}` | content | `ScreenName` is the identity token the plain grammar prints; `Name` and the profile URLs are content that the list grammar does not print |
| `Post.Text` (a single string, entity-expanded) | content | **unwrapped**, no escape, no width baked in |
| `Post.CreatedAt` (`time.Time`), `Post.Lang` | content | the instant; formatting is presentation |
| `Post.ConversationID`, `Post.ReplyTo`, `Post.RepostedBy *User`, `Post.Quote *Post` | content | the relationships; the *words* for them are presentation |
| `Post.Media []MediaRef{Kind, URL, AltText}` | content | refs only, no bytes; the noun and the count grammar are presentation |
| `Post.Counts` | content | parsed and retained; the *list* grammar must not print them (`REND-01`) |
| `Post.Visibility` | content | `Visible`/`Limited`/`Unavailable`/`Withheld`; the placeholder literal is presentation |
| list order, page boundaries, cursors, dedupe, stall detection, which ids are new after a refresh | content | the pane never reorders or re-derives these |

### Presentation (`internal/render`, one `Grammar` value per display style)

```go
// internal/render/grammar.go
type Grammar struct {
    Name        string       // "plain" in Phase 2; Phase 3 adds "servicelog", "gitlog", "ci", "internal"
    HandleCols  int          // 16
    Stamp       StampFormat  // the two absolute forms, 12 cells each
    BodyIndent  int          // 2
    MeasureCap  int          // 96
    Separator   bool         // one blank row between blocks
    Markers     MarkerSet    // every literal in the table above, as templates
    Identity    func(domain.User) string // the ONE seam Phase 3 replaces with the alias function
    ShowCounts  bool         // false in every Phase 2 grammar
}

type MarkerSet struct {
    Repost, Continued, Limited, Unavailable, MissingText, Attachment string
    QuotePrefix    string // "> "
    QuoteDepthCap  int    // 2
    Truncation     string // "~"
}
```

Owned by presentation and by no other layer: the identity string and its column, the stamp
format, the indents, the measure and its cap, the separator, every marker literal, the quote
prefix, the truncation mark, the selection mark, the colour role of every run, the pluralisation
of the attachment line and of the budget line, and the field order of the status line. Phase 3
changes **only** `Name`, `Markers`, `Stamp`, `Identity`, `ShowCounts` and the palette: the block
layout, the width model, the keymap, the reducers and the domain types are untouched.

### The same post, two grammars (the proof that the split is real)

The content is one `domain.Post`: author `aergon`, `CreatedAt` 2026-10-14T09:12:00Z, text "cursor
in, cursor out: the render layer never does arithmetic on a cursor. if the upstream hands back one
you have seen, that is the end of the walk.", quoting `lzd` (09:00) "the page cache is keyed by the
cursor, not by an index.".

(A) the plain reader grammar (Phase 2, `W = 80`):

```
 aergon           Oct 14 09:12
   cursor in, cursor out: the render layer never does arithmetic on a cursor. if
   the upstream hands back one you have seen, that is the end of the walk.
 > lzd              Oct 14 09:00
 >   the page cache is keyed by the cursor, not by an index.
```

(B) a timestamped service-log cover. **This is not a Phase 3 specification** — Phase 3 owns the
cover grammars and their literals. It is here to show that the same content value renders under a
second grammar with no content change, and to fix the two seams the cover needs.

```
 2026-10-14T09:12:00Z INFO svc=timeline seq=1812041 actor=a3f19c
   msg="cursor in, cursor out: the render layer never does arithmetic on a cursor. if the
   upstream hands back one you have seen, that is the end of the walk."
 2026-10-14T09:00:00Z INFO svc=timeline seq=1811998 actor=c71b02 rel=quote_of:1812041
   msg="the page cache is keyed by the cursor, not by an index."
```

What changed between (A) and (B), and what did not:

| Difference | Where it lives |
|------------|----------------|
| `aergon` → `a3f19c` | `Grammar.Identity` — the aliasing function (`DSGT-06`/`DSGT-07`), a presentation seam |
| `Oct 14 09:12` → `2026-10-14T09:12:00Z` | `Grammar.Stamp` — a stamp format, never a stored string |
| head row + indented body → `key=value` prefix + quoted body | `Grammar` layout fields (`HandleCols`, `BodyIndent`, `Separator`, markers) |
| the quote block → a second record carrying `rel=quote_of:{id}` | `Markers` plus the relationship field on the content value — the *relationship* is content, its spelling is not |
| the `>` selection margin and SGR roles | the frame composer and the palette — outside the grammar |
| the post id, the text, the instant, the relationship, the media kinds, the order | untouched content |

**Properties that make the split testable.**

- **P1 — grammar invariance of content.** For any post P and any two grammars g1, g2: after
  removing the union of g1's and g2's literal marker strings, the surviving characters are the
  same sequence (post text, both handles, the instant rendered by each grammar's stamp, the quoted
  text). Test: render the fixture list under both `plain` and a test-only second grammar and
  compare the extracted content stream.
- **P2 — no chrome leaks into content.** The only fields the renderer can read are those in the
  content table; `Counts` is rendered only when `Grammar.ShowCounts` is true, and a test asserts it
  is `false` for every grammar this phase ships, and that no golden frame contains an engagement
  number.
- **P3 — the cover cannot change what is true.** A grammar change may never change the set or
  order of posts, the selection, the anchor, the request count or the status line's state: after
  `t`, `t` the frame is byte-identical (the same test as the stack restore).
