**The permalink (`internal/render/link.go`).** `func Permalink(p domain.Post) string`: `https://x.com/{handle}/status/{id}` when the post's author handle is known (as stored, without a doubling of any leading `@`), `https://x.com/i/status/{id}` otherwise — the tombstone and withheld case, which still resolves. A presentation template built at the call site from content's `Post.ID` and `Post.Author.Handle`, never stored in a content value. One function, both forms; document that a post with no handle builds the handle-free form rather than refusing, and that both forms are what `y` and `o` act on.

**The clipboard chain (`internal/media/clipboard.go`).**

- `type ClipboardOutcome uint8` with `Copied`, `CopiedWithWLCopy`, `NoClipboard` and a `String()` naming each in lowercase words. `type Clipboard struct { Out io.Writer; Env func(string) string; LookPath func(string) (string, error); Run func(ctx context.Context, name string, args []string, stdin string) error }` with `func (c Clipboard) Copy(ctx context.Context, url string) ClipboardOutcome`.
- The chain, in order, with the rule for each link:
  1. **OSC 52 always**, unless `$TERM` is empty or `dumb` — the same condition under which this program emits no other escape, and deliberately **not** `NO_COLOR`, which is honoured for exactly what it names. The escape is `\x1b]52;c;{base64 of the URL}\x1b\\`, written with one `Write` to `Out` (the program's own output file, the same writer `internal/term`'s sink uses). A terminal that ignores the escape is indistinguishable from one that honours it, so no detection is attempted and none is claimed.
  2. **`wl-copy` additionally** when `$WAYLAND_DISPLAY` is set and `LookPath` resolves `wl-copy`: one run with the URL on stdin. Its exit status is the only half of the chain that can be observed, and a non-zero exit means it did not copy.
  3. **Nothing else, ever.** No `xclip`, no `xsel`, no clipboard command from the configuration — this phase adds no configuration key, and a command key would be configuration surface for one user's convenience.
- The outcome reports what ran: `CopiedWithWLCopy` when both links ran, `Copied` when only the escape was written, `NoClipboard` when neither could. `Copy` returns no error: there is nothing a caller could do with one, and the third outcome is the honest report.
- **Only a permalink ever reaches the clipboard**, and the sink's doc comment says so: no post body, no handle list, no session material. A clipboard manager may keep what this writes; the "no trace" promise covers the timeline, not the user's own clipboard — say that in one sentence, because it is the sentence a reader will ask for.

**The seam's second entry point.** `internal/media/renderer.go`: `Renderer` gains `OpenURL(ctx context.Context, url string) (Result, error)` — a URL that is not an attachment (today the post's permalink) handed to the same configured opener with the same one-argument, no-shell rule. `External` implements it with `e.Opener` and the URL as its argument; document that the v1.x in-terminal renderer answers it with its own honest outcome (a renderer that draws in the terminal cannot open a browser, so the pane prints the URL — the same behaviour a missing opener has).

**The two key rows and their actions.**

- `internal/keys`: two rows, `copy-link` (`y`, help `copy the post's link`) and `open-post` (`o`, help `open the post in the browser`), group `media`. Add the `HelpCovered` field to `Row` here if task 2 has not landed it; task 2 fills the three covered literals. Never a second string table — the help overlay's covered wording is a field of the one row, exactly as Phase 3 designed it.
- `y`: one `tea.Cmd` that builds the permalink and calls `Deps.Clip.Copy`; the answer becomes a notice (`link copied`, `link copied with wl-copy`, or `no clipboard`) and, in the third case, the post's permalink joins the frame's fallbacks — plan 02's `url ` row — so the URL is on screen even though nothing was copied. `y` has no "does not apply" case: a post without a handle still builds a permalink.
- `o`: one `tea.Cmd` that builds the permalink and calls `Deps.Media.OpenURL`; the answer becomes `opened in browser`, or `no opener - URL shown` plus the permalink row when the program is missing or the spawn failed.

- The composition root: `Deps` gains `Clip media.Clipboard`, built in `internal/cli/feed.go` with `Out` the program's own output file (`internal/term`'s sink writes to the same one), `Env: os.Getenv`, `LookPath: exec.LookPath` and the run wrapper, behind package-level vars of that file so the verb's tests drive recorders.

**Notices** (`copy.go`/`status.go`): `opened in browser`, `link copied`, `link copied with wl-copy`, `no clipboard`, with their `NoticeKind` rows and the file's totality arm extended.

**Tests.** `clipboard_test.go`, recorders only and nothing spawned: a copy under a colour-capable `TERM` writes exactly one escape whose base64 payload decodes back to the permalink; under a `dumb` or empty `TERM` nothing is written to the sink; with `$WAYLAND_DISPLAY` set and `wl-copy` resolvable the recorder sees the URL on stdin and the outcome is the two-link one; with a non-zero exit from the recorder the outcome is the escape-only one; with neither link available the outcome is `NoClipboard`. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
