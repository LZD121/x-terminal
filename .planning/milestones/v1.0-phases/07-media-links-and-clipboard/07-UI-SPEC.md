# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This document is an extension of `.planning/phases/02-following-timeline-in-the-pane/02-UI-SPEC.md`.** The
block layout, the width model and `A4`–`A7`, the colour ladder and `A1`–`A3`, the status line's field
mechanics and drop order, the keymap table, the help overlay, the frame stack and the golden-frame discipline
are inherited and binding. This file states only what Phase 7 changes, adds, or must amend. A convention that
is not restated is inherited, not re-opened.

**Authority above this file:** `07-CONTEXT.md` (the phase's implementation decisions, written after this
contract was first drafted and reconciled against it on 2026-10-14), `03-CONTEXT.md` (the cover seam) and
`.planning/research/TERMINAL-MEDIA-PROBE.md` (the measurement that settles v1's no-inline-images decision).
Where this contract deviates from `07-CONTEXT.md`, the deviation is named inline; there is one, in
`## Screen Grammar` (the `o` fallback), and it adds a case the peer decision does not cover.

## Design System

| Property | Value |
|----------|-------|
| Tool | `none` — inherited; no CSS design system, a Go terminal program |
| Preset | not applicable |
| Component library | unchanged: Bubble Tea v2 + `charmbracelet/x/ansi`. **New this phase:** `internal/media` — the renderer seam (`renderer.go`) and v1's external-program implementation (`external.go`). It is I/O: it runs behind the same effect/`Cmd` boundary as every other side effect, and it becomes the named `os/exec` exception in the boundary test; `internal/tui` still may not import `os/exec` |
| Icon library | `none` — and this phase adds none, which is a decision and not an omission: media is marked by words in the attachment line, never by a glyph, a thumbnail placeholder, a camera symbol, an arrow or a box-drawing frame |
| Font | the terminal's own monospace cell; the program sets no font, size, weight or line height |

**Notes.**

- **v1 ships no in-terminal image code, and this is measured, not assumed.** `TERMINAL-MEDIA-PROBE.md`
  (2026-10-14) records: the Kitty graphics protocol works in a bare Ghostty 1.3.1; inside tmux 3.7c a bare
  APC sequence is consumed by the multiplexer and does nothing, while a DCS-wrapped sequence renders — *and*
  the text printed afterwards is drawn **across** the image, because tmux does not model image cells. That
  kills an in-pane implementation in the configuration this tool lives in: the pane scrolls, and a scrolled
  image smears. Media therefore opens **outside** the process.
- **The seam is shaped for the renderer that comes later, not for the one that ships now.**
  `internal/media.Renderer` is `Open(ctx, ref domain.MediaRef) (Result, error)`: one attachment per call, and
  the result carries a notice **and optionally rows for the pane to print in a detail frame**. That rows half
  is why the interface has this shape — a renderer that draws inside the terminal cannot be expressed as
  "spawn a program with a URL", and if v1 defined the seam that way the v1.x Kitty renderer (`IMG-01`) would
  need new pane code, which is exactly what `MEDIA-02` forbids. Rows are printed **only in a detail frame,
  never while a scrollable list is on screen** — the probe's hazard, avoided by construction rather than by
  discipline. The v1.x addition is one file (`kitty.go`), one config value and one wiring line.
- **The words stay in one file.** `Result` carries an outcome *value*; the sentence for it is a constant in
  `internal/render/copy.go`, exactly as `domain.FailureKind` is content and its words are presentation. The
  seam never hands a sentence up. `[INFERENCE]` whether that value is an enum or a `Result{Notice string}`,
  since `07-CONTEXT.md` describes the field rather than its type; the planner picks one and keeps every
  string in the copy file either way.
- **The pane never blocks and never waits for the child.** The call is a `tea.Cmd` — the frame stays
  responsive — and a goroutine reaps the process so no zombie accumulates.
- **No shell, ever.** A program name from config plus one argument, spawned directly: nothing in a post's
  text can become part of a command line. This is a security property that happens to be visible (the pane
  never shows a command line either — no string that reaches a program is ever echoed as a shell fragment).
- **The client never fetches media bytes.** The URL handed to the opener is the one the payload carried; the
  whole media path is one spawn and one line of output.

## Spacing Scale

Phase 2's table stands (`xs` = 1 cell, `sm` = 2, `md` = 16, `lg` = 1 blank row; `xl`/`2xl`/`3xl` reserved).
This phase adds **one** declared value and one derived column, as further exceptions:

| Token | Value | Used as | Usage |
|-------|-------|---------|-------|
| `ent-col` | 4 cells | 4 cells | the attachment entry's prefix at the body indent: `[n] ` (bracket, one digit, bracket, space). The digit is the key that opens that attachment, so the prefix is the affordance |
| `url-col` | 6 cells | 6 cells (derived: `sm` + `ent-col`) | where a printed URL continues after wrapping: the body indent plus the entry prefix, which puts the continuation in the same column as the URL it continues — for an attachment entry (`  [2] https://…` → continues at column 7) and for the permalink fallback (`  url https://…` → the same column, because `url ` is also 4 cells) |

Exceptions: `xs` = 1 and `sm` = 2 (Phase 2's), plus `ent-col` = 4 and `url-col` = 6. They are not multiples
of 4 for the same reason the first two are not: an 80-cell row cannot afford 8-cell gutters, and the prefix
must be exactly as wide as `[9] ` so that single- and double-digit-free entries align in one column.

## Typography

- One text attribute in the whole surface (SGR 7 on the selected block) — unchanged. The `[n] ` digits are
  **muted** (part of the marker, like the nouns); the fallback URL is **body colour**, because it is the one
  string in that situation the user has to read and act on. Nothing is underlined, bolded or recoloured: the
  OSC 8 hyperlink the URL carries adds no styling, so Phase 2's "exactly one text attribute" still holds and
  a URL never looks like a link.
- Emphasis by column position and literal marks only.

## Color

Roles and the degradation ladder are unchanged. This phase assigns no new colour role:

| Element | Role |
|---------|------|
| all media, link and clipboard notices (`opened image`, `no opener - URL shown`, `link copied`, …) | **muted**, like every other `notice` field |
| the `[n] ` prefix and the attachment nouns | muted (Phase 2's attachment line was already muted) |
| a printed URL | body (dominant) — see `## Typography` |
| the covered refusal literal | the cover's own palette (`DSGT-05`, Phase 3) |

- **`A1` is amended.** Frames can now carry an escape that is not SGR — the OSC 8 wrapper on a fallback URL
  — so the mono/truecolor byte-identity test strips **all** escape sequences, SGR and OSC. OSC 8 is emitted
  under the same "this terminal understands escapes" condition as colour, so stripping SGR alone would report
  a difference that is not a difference in meaning.
- **`A2` extends:** every notice row below renders literally; the covered refusal renders its cover's literal.
- **`A3` unchanged:** in rung `mono` the URL keeps its column and its entry prefix, so the fallback is still
  unambiguous — that is the whole point of printing it.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary actions (this phase's four new user actions; help literals) | `i` — `open the first attachment`; `1`–`9` — `open the numbered attachment`; `y` — `copy the post's link`; `o` — `open the post in the browser` |
| Attachment line, numbered (replaces Phase 2's template; see `## Screen Grammar`) | `[1] image` / `[1] image, [2] video` / `[1] image, [2] image, [3] image, [4] image` — nouns `image`, `video`, `gif`, in that fixed order, every entry singular because every entry is one attachment |
| Attachment entry whose opener failed (**`MEDIA-03`**) | the URL replaces the noun: `[2] https://video.twimg.com/…`, wrapped at the one width model, never truncated |
| Permalink printed after a failed `o` | `url https://x.com/{handle}/status/{id}` |
| Permalink, no handle (tombstone, withheld, unavailable) | `https://x.com/i/status/{id}` — still resolves |
| Media outcome, spawn succeeded | `opened image` / `opened video` / `opened gif` |
| Media or link outcome, nothing could take it | `no opener - URL shown` |
| `o` succeeded | `opened in browser` |
| `y` succeeded, OSC 52 only | `link copied` |
| `y` succeeded, OSC 52 and `wl-copy` | `link copied with wl-copy` |
| The action does not apply | `no media in this post` |
| Covered refusal (DSGT-10) (**not yours to word**) | the active grammar's marker for it; Phase 3 owns the words. In the plain grammar the field is empty and unreachable |
| Destructive confirmation | none — nothing here is destructive. None of the three actions can change the account (`SEC-03`), and a copy overwrites the clipboard, which the terminal has already made the user's own business |

**Every outcome is a notice.** The status line's `state`/`remedy` slots are the classifier's and Phase 6's
capability states'; a failed opener is neither a network state nor a capability state, it is the answer to an
action the user just took, so it goes where Phase 2 put the answers to actions: `notice`. The consequence is
named in `## The Status Line` (a notice is the first field dropped), and it is why the URL must be printed in
the pane and not only on the line — a URL cut to the pane's width, or dropped with a field, is unreachable.

**What the confirmations claim, and what they do not.** `opened image` reports that a program was started
with that URL, not that a window appeared. `link copied` reports that the OSC 52 escape was written — and
`with wl-copy` additionally that a clipboard client ran and exited zero. An OSC 52 write has no reply (a
terminal may take the escape and do nothing, and there is no observable difference), so the words say what
this program did, which is the most it can know. Where it knows less, it says less and prints more: that is
`MEDIA-03` in one sentence.

**The clipboard chain, in order (`REND-07`).** `y` builds the permalink and hands it to the chain:

1. **OSC 52 is always emitted**, unconditionally — including under tmux, and including when `wl-copy` is
   absent. A terminal that ignores it is indistinguishable from one that honours it, so detection would buy
   nothing; the escape is written to the tty behind the same effect/`Cmd` boundary as every other escape this
   program emits, never from `Update`.
2. **`wl-copy` additionally**, when `$WAYLAND_DISPLAY` is set and the program is on `PATH`. It is a
   subprocess, so it is an effect too, and it is the half that can be verified: its exit status.
3. **Nothing else, ever.** `xclip`/`xsel` are not used (X11-only, absent on this host), there is no
   clipboard command in the config, and no post body, handle list or session material is ever written to the
   clipboard — only the permalink of the post the user asked about. A clipboard manager may keep it; the
   "no trace" promise covers the timeline, not the user's own clipboard.
4. **The notice distinguishes the mechanisms that ran** — `link copied` when only the escape was written,
   `link copied with wl-copy` when both ran — because "copied" with an unchanged clipboard is the failure
   mode the pitfalls research names. There is no failure case to report: step 1 cannot fail, so `y` never
   produces an empty answer, and that is a property of the design rather than of the terminal.

**The permalink forms.** `https://x.com/{handle}/status/{id}` when the handle is known;
`https://x.com/i/status/{id}` otherwise, which is the tombstone and withheld case and still resolves. Built
at the call site from content's `Post.ID` and `Post.Author.Handle` — a presentation template, never a string
stored in a content value. Both forms are handle-bearing in the sense that matters for `DSGT-10`: any post
link points at the post, so the gate applies to both (`07-CONTEXT.md`), and an exception for the handle-free
form would be a loophole rather than a rule.

## Screen Grammar

### The numbered attachment line

Phase 2's `attachment: {n} {noun}[, {n} {noun}]` template is **replaced** by a numbered form:

```
   [1] image
   [1] image, [2] video
   [1] image, [2] image, [3] image, [4] image
```

- The prefix is `[n] ` at the body indent: 4 cells, the digit being **the key that opens that attachment**.
  That is the whole affordance, and it is why the line carries no icon and no arrow: it states what is there
  and, in the same characters, which key reaches it.
- **The `attachment: ` prefix is dropped.** A named marker would have to be repeated on every row of the
  split form below, or aligned away from the entries it labels; and with the digits in place the nouns are a
  list, not a sentence. The nouns, their order and the singular/plural rule are unchanged from Phase 2 — with
  one simplification: every numbered entry is exactly one attachment, so the plural nouns (`images`,
  `videos`, `gifs`) no longer occur in this line at all. `[INFERENCE]` that x.com carries at most four
  attachments per post; the line numbers up to nine, and beyond that the surplus entries keep their nouns
  (so nothing is silently unreachable) while the digit keys stay 1–9.
- **Phase 2's golden frames are regenerated** where they contain an attachment line, and Phase 6's too: the
  in-pane line changes, and nothing else about those frames does. That is the honest cost of the digits.
- A post with no attachments renders no attachment line (`Post.Media` nil-versus-empty, so "no attachment"
  and "attachments that did not parse" stay distinguishable), and `i` on it answers `no media in this post`.

### The fallback: a URL where the noun was (`MEDIA-03`)

When the opener for an attachment is missing — the program is not on `PATH`, the spawn fails, or it exits
non-zero — that attachment's **noun is replaced by the URL** it needed, in place, in the same entry:

```
   [1] image
   [2] https://video.twimg.com/ext_tw_video/1812041/pu/vid/1280x720/9nQ4kLm3xT8a
      BcD.mp4
```

The rules, all of them binding:

- **The line splits into one entry per row when any entry is a URL.** The digit stays, the URL takes the
  noun's place, and the entry wraps at the one width model — `measure - 4` cells of URL per row (73 at 80
  columns, 92 at 120), continuations on the `url-col` (6 cells), so a row never exceeds `W` (79 cells at 80)
  and the continuation sits in the column the URL started in. **Never truncated**: a URL cut to the pane's
  width is an unreachable URL, which is the requirement's own point.
- **The notice says why**: `no opener - URL shown`. It is one quiet line in the established shape — never a
  modal, never a spinner, never a silent no-op.
- **The URL carries an OSC 8 hyperlink, and only this URL does** (one more case is named below). That is the
  one situation where a click is the only remaining way to reach the thing; keeping hyperlinks out of the
  ordinary frames keeps every golden frame free of an escape that carries no visible meaning, and it carries
  no styling, so a URL never looks clickable even when it is.
- **A URL row renders only in normal mode.** Entering a cover drops it from the rendering — a
  `pbs.twimg.com` or `x.com` URL on a covered screen is a direct `DSGT-09` violation, and under a cover the
  action that produces one is refused anyway. The state keeps the row, so leaving the cover restores the same
  frame (`P3`: the cover never changes what is true, only what is drawn).
- **A URL row is never removed by anything but the next successful action on that post.** It is not a
  transient: it is the only route to that media until an opener exists.
- One more case prints a URL, on the same terms (this contract's own decision — `MEDIA-03` names media, and
  `o` would otherwise be the one silent no-op left in the phase): **`o` with no link opener prints the
  permalink in the block**, as a `url `-prefixed row at the body indent with the same wrap rule and the same
  OSC 8 wrapper, and the same `no opener - URL shown` notice:

```
   [1] image, [2] video
   url https://x.com/aergon/status/1812041
```

  Both row kinds share one prefix width (4 cells: `[n] `, `url `) so their continuations share one column.

**No media, and the actions that always apply.** `i` on a post with no attachments writes `no media in this
post` and spawns nothing; `y` and `o` always have a permalink to act on, whether the handle is known or not;
none of the three needs a session or a request. One honest line, no request, no spawn — the same rule Phase 4
set for keys whose action does not apply.

### The gate (`DSGT-10`), in one place

In the immersive state the three cover-breaking actions — opening in the browser, opening media, copying a
post link — are **bound but refuse**. An action is cover-breaking if it hands a string that identifies the
real upstream (a post's media URL, a post permalink in either form) to a program outside this process or to
the terminal's clipboard; copying is gated even in the handle-free `/i/status/` form, because the rule is
about what the action reveals.

- **One gate, in the action dispatcher** — not three checks in three key handlers and not a column of flags
  in the keymap table: the dispatcher is where an action is chosen, so it is where one state check covers all
  three. The frame's observable diff is exactly one field.
- **Nothing happens**: no request, no process, no escape, no clipboard write. The refusal is a **notice**
  written with the **cover's own marker literal**, so a covered pane never names the product or the purpose
  it is declining to reveal, and the frame differs from the pre-keypress frame only in that field.
- **Refusing rather than unbinding is deliberate** (`07-CONTEXT.md`): `DSGT-08` requires the whole read
  surface to work with unchanged keys under the cover, and a key that vanishes in immersive mode is a screen
  that behaves differently.
- **The help overlay keeps all four rows under a cover**, with the wording the cover's own grammar supplies
  (Phase 3 owns it, one entry per row). Phase 2's rule "no key is documented that does not work" is satisfied
  by the refusal being a working behaviour, not by hiding the key; and a cover whose help named
  `open the post in the browser` would be its own leak.
- **Panic needs nothing new.** Panic is not interactive: only the key that leaves it is honoured, so
  everything is unavailable until the user deliberately leaves — `DSGT-10` in its strongest form.
- **The gate is evaluated per action, against the active display state**, so leaving the cover makes the keys
  work again immediately and changes nothing else about the frame (`P3`).

**After a copy** (status line only; the pane is unchanged and draws nothing for a copy):

## The Status Line

**No new field. No drop-order change.** The field order stays exactly Phase 2's (with Phase 6's `synced`
inserted after `list` if that phase has landed):

```
{state}  {remedy}  {notice}  {list}  [ {synced} ]  {position}  {budget}
```

- Every outcome this phase produces is a `notice` value: `opened image`, `no opener - URL shown`,
  `link copied`, `link copied with wl-copy`, `opened in browser`, `no media in this post`, and the covered
  refusal. They are therefore the **first** field dropped under width pressure — Phase 2's order, unchanged,
  and the reason is Phase 2's: news is the cheapest thing to lose.
- **Named compromise.** The two longest notices (`link copied with wl-copy`, `no opener - URL shown`) plus a
  failure state do not fit 80 columns: `rate limited  no retry  no opener - URL shown  following  12/20+
  12 requests, 0 rate-limited` is 93 cells, so the notice drops and the pane's printed URL carries the whole
  story. The alternative — moving these into the never-dropped `state` slot — was rejected because that slot
  is the classifier's and Phase 6's capability states', and because Phase 2's never-dropped set exists for
  facts that change what the user must do, while a media outcome is the answer to an action the user already
  took. With no failure state on the line (the normal case after `y` or `o`) the notice is visible at every
  width — 51 and 64 cells.
- No timer, no spinner, no modal, and no second line: every outcome is one notice, and the frame stays
  responsive while a child process runs.

## Width Model

Phase 2's model (`internal/text` only, `$TMUX` dispatch, `measure = min(W-3-2*depth, 96)`, `A4`–`A6`) is
inherited unchanged. Two amendments, both forced by the printed URL:

- **`A7` (amended).** No rendered row exceeds `W` cells, and no row of post text or of a marker exceeds
  `min(W-3, 96)` cells of text. A URL row may use up to `measure + 2` cells (79 at 80 columns, 98 at 120),
  because its text column is `measure - 4` and its prefix is 4. Rationale: a URL is the one string whose
  value is its byte-for-byte completeness, so it is wrapped to the widest column the frame allows rather than
  to the reading measure — and it is still bounded by `W`, so a width bug is still visible.
- **Escapes are applied after layout.** The OSC 8 wrapper is added when the row is emitted, never before
  measurement, padding, wrapping or truncation, so no measurement in the program ever sees an escaped string
  (`A6` holds as written).
- The attachment line's own width: four entries at one attachment each are 45 cells plus the 2-cell indent —
  47, well inside even the 60-column floor's 57-cell measure. A URL entry is the only case that can approach
  the frame's edge, and it is bounded as above.

- a `mono` frame whose stripped bytes equal the `truecolor` frame's stripped bytes, escapes and all;
- four covered frames that contain no URL, no handle, no `x.com`, no program name and no product name, and
  whose refusal literal is the cover's own;
- the assertion, over the whole corpus, that a URL appears in **no** frame that has not had a failed action:
  the ordinary timeline, search, profile and detail frames contain no `http` at all.

## Keymap Contract

Phase 2's table, its one-source rule (`REND-05`), the help overlay and the `keys` subcommand are unchanged.
This phase adds **four rows and no others**:

| Keys | Action | Help text (rendered verbatim) | Group |
|------|--------|-------------------------------|-------|
| `i` | `media` | `open the first attachment` | media |
| `1`–`9` | `media-numbered` | `open the numbered attachment` | media |
| `y` | `copy-link` | `copy the post's link` | media |
| `o` | `open-post` | `open the post in the browser` | media |

- **Nine digits are one row**, rendered `1-9` in the help overlay's key column (which is 16 cells wide and
  holds `1 2 3 … 9` only at the cost of wrapping): one binding class, one help line, one action. `[INFERENCE]`
  this is the shape `07-CONTEXT.md` leaves to discretion; nine rows would satisfy the table too and would
  make the help nine lines longer.
- **The keys collide with nothing here and are resolved in the cover's favour if a cover wants them**
  (`07-CONTEXT.md`, Phase 4's rule): the cover lands first, and this phase reads the display state rather
  than adding state.
- **No key reveals a URL on demand.** `MEDIA-03` asks for the URL when no opener exists; a "show me the URLs"
  key would print them when one does, which is a URL on screen for no reason — the thing Phase 2 removed.
- **No key is added for the in-terminal renderer** (`IMG-01`): when it lands it is a second `Renderer`, not a
  second key. That is what makes the seam's shape load-bearing rather than decorative.

## Content / Presentation Split

Phase 2's split and `P1`–`P3` stand. This phase adds nothing to the content model and a great deal to
presentation.

### Content (`internal/domain`, never a string the renderer prints)

| Item | Owner | Notes |
|------|-------|------|
| `MediaRef{Kind, URL, AltText}`, `MediaKind{Image, Video, GIF}` | content | already parsed and carried by the timeline and thread decoders, and deliberately unrendered until now. Nothing new is needed in this package |
| `Post.Media` nil-versus-empty | content | how the screen tells "no attachment" from "attachments that did not parse"; the numbered line renders from the slice as it stands |
| `Post.ID`, `Post.Author.Handle` | content | the permalink is *built* from them, never stored as a string in a content value |
| the URL an action hands over | content | exactly one `MediaRef.URL` per action, taken from the ref the user's key selected, so the URL that is handed over and the URL that is printed on failure are the same value and cannot disagree |

`[INFERENCE]` and a task for the planner: `domain.MediaRef.URL` is documented as a video's **poster frame,
not its stream**. If the recorded fixtures carry `video_info.variants`, this phase extends the decoder so a
video or gif has a playable URL for `mpv`; if they do not, the poster frame is the whole of `MEDIA-01` for
video in v1 and the plan says so — under either answer the seam, the keys, the fallback and the frames above
are unchanged.

### Presentation (`internal/render`)

| Element | Owner | Notes |
|---------|-------|------|
| the numbered attachment template and its `ent-col` | presentation | the marker's template changes (Phase 2's `attachment: {n} {noun}` is replaced); the nouns and their order are the ones Phase 2 defined |
| the URL fallback: the noun's replacement, the split rule, the wrap rule, the `url-col`, the `url ` prefix, the OSC 8 wrapper | presentation | all layout, none of it content |
| the permalink templates (with and without handle) | presentation | built at the call site |
| the opener dispatch by `MediaKind` | presentation | `Image` → `config.MediaOpener`; `Video`/`GIF` → `config.VideoOpener` with its fixed `--no-terminal`; the program name comes from config, the URL is one argument, no shell |
| the notices and the covered refusal marker | presentation + grammar | notices are `render/copy.go` constants; the refusal and the four covered help literals are the cover grammar's (Phase 3 owns their words) |

### The seam, as the screen sees it

`internal/media.Renderer.Open(ctx, ref)` returns an outcome value and, optionally, rows for a detail frame.
The screen's contract with it is three sentences long: **the screen renders the outcome's word from
`copy.go`, it prints exactly the rows the seam supplies and only in a detail frame, and on any failure it
prints the URL it asked the seam to carry.** That last clause is what makes `MEDIA-03` structural: the
screen already holds the ref, so the fallback is not an error path the seam has to describe but the screen's
own copy of the value it handed over. When the Kitty renderer lands, "could not take it" stays the only error
the screen understands.

**Configuration.** `media_opener` (default `xdg-open`) now demonstrably opens images and links, and one key is
added: `video_opener` (default `mpv`), read by the existing `KEY = "value"` parser with its
warning-and-keep-the-default behaviour. Nothing else: no clipboard command, no player flags beyond the fixed
`--no-terminal`, no image mode, no auto-open-on-select, no per-terminal overrides. `--no-terminal` is fixed
because a player that seizes the pane would fight Bubble Tea for the terminal, and offering the user that
foot-gun is not a feature. `doctor` (Phase 8) reports both openers as presence facts.

### The cover seam (`03-CONTEXT.md`, Phase 3)

**Expressible, with three items on the cover's side and one on this phase's.**

1. The refusal is one marker literal per grammar, rendered in the `notice` field (Phase 3 owns the words).
2. The four rows' help literals under a cover are the cover grammar's own (`07-CONTEXT.md`: "one entry per
   row, in Phase 3's grammar, not a second table here"), so the covered help never names a browser or a
   player.
3. The fallback URL rows are normal-mode-only, dropped by the composer under a cover (the state keeps them,
   so `P3` holds).
4. This phase's own contribution is the gate's position: one check in the action dispatcher.

If the seam could not carry (1) and (2), the cost would be three `if` statements in the input handling — a
second source of truth for the same bindings, which is the drift `REND-05` exists to prevent — plus a
covered help frame that either hides a working key or prints a leak. If it could not carry (3), the cost
would be a real upstream URL rendered on a covered screen: a direct `DSGT-09` failure. Nothing else about the
phase touches the seam.
