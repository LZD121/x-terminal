**The question the phase's own contract flags, settled against the recorded fixture.** `07-UI-SPEC.md`'s `## Content / Presentation Split` states: `domain.MediaRef.URL` is documented as a video's **poster frame**, and if the recorded fixtures carry `video_info.variants` this phase extends the decoder so a video or gif has a playable URL for `mpv`; if they do not, the poster frame is the whole of MEDIA-01 for video. **They do carry it.** `internal/xsource/testdata/fixture-usertweets.json` holds a `type: "video"` attachment with `video_info.variants` listing an `application/x-mpegURL` manifest and several `video/mp4` entries with bitrates. So the decoder is extended, and that is the whole of this task's first half.

**`internal/domain/domain.go`:** `MediaRef` gains `Playable string` — the URL a player can take, empty when the response carried no variant. Write the doc comments so the split is unambiguous: `URL` stays the media's own URL as the payload carried it (for a video, the poster frame) and is what a printer can always show; `Playable`, when non-empty, is what a player is handed. Nothing in `domain` chooses a variant: the choice is the decoder's, and the domain value carries the answer.

**`internal/xsource/tweets.go`:** `mediaOf` reads `video_info.variants` for a video and for an animated gif and fills `Playable` by one documented rule, implemented as one function so the rule is testable in isolation:
- among variants with content type `video/mp4`, take the one with the highest `bitrate` (a variant with no bitrate is ranked last and is still eligible when it is the only one);
- else take the first `application/x-mpegURL` variant;
- else leave `Playable` empty.
State the reason for the order in the comment: `mp4` needs no demuxer beyond what `mpv` ships with, and the manifest is the fallback because it is a stream this program does not otherwise reason about. An image's `Playable` stays empty — an image's `URL` *is* the image.
Ties are broken by the response's own order (the first variant at the winning bitrate wins), so the parse is deterministic and a re-parse of the same body gives the same bytes.
