# Requirements: x-terminal

**Defined:** 2026-10-14
**Core Value:** Browse x.com from inside a terminal pane — timelines, threads, search, profiles, bookmarks — with no browser, no algorithm-driven app shell, and nothing on screen that looks like social media.

Scope decisions and their provenance live in `.planning/PROJECT.md`; the evidence base is
`.planning/research/SUMMARY.md` (with `STACK.md`, `FEATURES.md`, `ARCHITECTURE.md`,
`PITFALLS.md` and the empirical `TERMINAL-MEDIA-PROBE.md`).

## v1 Requirements

### Authentication (AUTH)

- [x] **AUTH-01**: User can authenticate by placing the x.com session cookie (`auth_token` + `ct0`) in a `0600` file at `$XDG_CONFIG_HOME/x-terminal/session`; the app refuses a file with looser permissions and refuses a symlink
- [x] **AUTH-02**: User can override the session file path and the cookie pair through environment variables, which take precedence over the file
- [x] **AUTH-03**: User can see which account the loaded session belongs to (`whoami`: handle and session status) before blaming the app for wrong content
- [x] **AUTH-04**: User can delete the local session copy with an explicit command, and the app never writes the cookie back to any other file

### Network (NET)

- [x] **NET-01**: User can route every upstream request through a proxy configured in the config file or `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`/`NO_PROXY`, over both HTTP(S) and SOCKS5
- [x] **NET-02**: On startup the app runs a connectivity self-check that reports a distinct named outcome for each failure: no route to x.com, proxy refused, proxy reached but upstream blocked, TLS/Cloudflare challenge, authenticated read OK
- [x] **NET-03**: When the upstream is unreachable the app fails loudly with that named state, and never renders an empty list as if the timeline were simply empty

### Upstream access (XAPI)

- [x] **XAPI-01**: User can read the Following timeline from x.com's internal web GraphQL using the session cookie — no API key, no paid tier
- [x] **XAPI-02**: Operation IDs (`queryId`) are data, never code: one machine-writable registry file holds them and no `queryId` string literal exists anywhere else in the repository
- [x] **XAPI-03**: The app carries a pinned, authoritative snapshot of operation IDs and the features/fieldToggles bag; a refresh may only add or update entries, never silently drop one
- [x] **XAPI-04**: User can pin an operation ID manually per operation, for the operations bundle-scraping cannot see (notably bookmarks and likes)
- [x] **XAPI-05**: The transaction-ID signer is isolated behind one interface with a startup self-test; a broken signer reports as its own error class rather than appearing as "no posts"
- [x] **XAPI-06**: The app classifies `404`-with-empty-body, `422`, `200`-with-`errors[]`, `429` and load-shedding as distinct outcomes instead of one generic failure
- [x] **XAPI-07**: Every request goes through one choke point enforcing single-flight, an inter-request floor of ≥1.5 s, no timers, no retry on `429`, and a session request cap

### Feed (FEED)

- [x] **FEED-01**: User can read the Following timeline as the default screen, and can reach the algorithmic feed only through an explicit toggle
- [x] **FEED-02**: User can load older posts with keyset pagination, and the viewport never jumps when a late page arrives
- [x] **FEED-03**: Pagination never shows duplicate posts (id-keyed dedupe) and detects a stalled cursor instead of looping
- [x] **FEED-04**: User can refresh with an explicit key; refresh preserves selection and scroll, and announces "N new posts" instead of silently replacing what is on screen
- [x] **FEED-05**: When a fetch fails partway, the screen still renders what was received, with the failure stated in one quiet status line

### Threads (THRD)

- [x] **THRD-01**: User can open a post and read its reply thread, paginated page by page rather than expanded in one unbounded burst
- [x] **THRD-02**: User can read inline quoted posts, and can open a quote as its own conversation
- [x] **THRD-03**: User can see tombstones and limited-visibility placeholders, and an honest "partial thread" label where replies are structurally unreachable

### Discovery (DISC)

- [x] **DISC-01**: User can search posts by keyword, with an explicit Latest/Top toggle
- [x] **DISC-02**: User can find users by handle or display name
- [x] **DISC-03**: User can open a profile (bio, counts, join date) and page through that account's recent posts

### Saved (SAVE)

- [x] **SAVE-01**: User can read their own bookmarks list from the active session
- [x] **SAVE-02**: User can read their own likes list; if that endpoint is unavailable the screen degrades to an honest message and nothing else breaks
- [x] **SAVE-03**: Bookmarks and likes are mirrored into a local SQLite database (`saved.db`) that can be opened and read with the network down
- [x] **SAVE-04**: Sync is incremental — it stops at the first page containing no unknown ids, and a full re-list marks rows `present = 0` instead of deleting them
- [x] **SAVE-05**: `saved.db` can only ever hold bookmarks and likes; the store's write API accepts nothing but a saved-item type

### Rendering and keys (REND)

- [x] **REND-01**: List and detail screens render borderless, unbranded and low-colour: no logo, no banner, no avatars, no engagement counts, no emoji or icon decorations
- [x] **REND-02**: Post text wraps to the window using one width model shared by wrap, pad and truncate, correct for CJK, emoji and grapheme clusters
- [x] **REND-03**: The layout reflows correctly on terminal resize
- [x] **REND-04**: Colour degrades truecolor → 256 → 16 → mono, honours `NO_COLOR` and `TERM=dumb`, and never carries meaning by colour alone
- [x] **REND-05**: Keys, the `?` help overlay and shell completion all derive from one keymap table, so a new key is one row
- [x] **REND-06**: User can navigate with a vim-ish grammar and a real back stack — returning from a post, profile or search restores the previous list, selection and scroll
- [x] **REND-07**: User can copy a post's link (OSC 52, falling back to `wl-copy`) and open it in a browser
- [x] **REND-08**: Golden frames at 80 and 120 columns, captured both inside and outside tmux, are the view specification

### Media (MEDIA)

- [x] **MEDIA-01**: User can open a post's media in an external program (`xdg-open` for links and images, `mpv` for video and animated media)
- [x] **MEDIA-02**: Media opening sits behind a renderer interface, so an in-terminal implementation is a one-file addition and never a rewrite of the feed
- [x] **MEDIA-03**: When no opener is available the raw URL is printed instead, so media is never silently unreachable

### Privacy and safety (SEC)

- [x] **SEC-01**: The session cookie never appears in logs, error messages, `doctor` output, request dumps or crash output — verified by a test that greps captured output for a fixture cookie
- [x] **SEC-02**: The timeline is structurally unrepresentable on disk: the store's insert path accepts only saved items, and an import-boundary test proves the timeline model never reaches it
- [x] **SEC-03**: No code path mutates the account: there is no post, reply, like, repost, follow or bookmark write call anywhere in the build

### Operations (OPS)

- [x] **OPS-01**: The UI surfaces four named failure states with distinct remedies — expired session, rate limited (with the computed reset time), offline/no route, upstream shape change
- [x] **OPS-02**: User can see the session's request budget, in one line ("12 requests, 0 rate-limited")
- [x] **OPS-03**: User can run `doctor` and see presence facts only — proxy reachability, session validity, signer self-test, snapshot age, store schema version, request budget — and never a token value
- [x] **OPS-04**: A soft ban (`code 88` while budget remains) is detected, stops the session and says so, rather than being retried
- [x] **OPS-05**: The account-risk statement is shown on first run and recorded in the repository
- [x] **OPS-06**: A runbook covers operation-ID rotation, features-blob drift, signer break, session expiry, `429`, soft ban, and accidental distribution

### Disguise (DSGT)

Three display states: **normal** (the plain reader), **immersive** (the same feed rendered
through a work-software cover, so it stays readable while looking like an internal tool),
and **panic** (a static innocuous frame that replaces everything instantly).
User decision: all cover styles are supported and switchable, identity is disguised along
with the layout, and the mode model is the full three states.

- [x] **DSGT-01**: User can switch between normal, immersive and panic states with single keys; panic renders in one frame, and the same key restores the exact previous screen, selection and scroll without a network request
- [x] **DSGT-02**: Panic clears what came before — the terminal scrollback is cleared and repainted, and under tmux the multiplexer's own history buffer is cleared too, so scrolling up cannot reveal feed content
- [x] **DSGT-03**: Panic sets the terminal title, and the tmux window name where applicable, to the cover's own name, and restores the previous title on exit
- [x] **DSGT-04**: Losing window focus enters panic automatically; regaining focus does not restore by itself, because un-covering is only safe as a deliberate act
- [x] **DSGT-05**: User can pick among at least four immersive cover styles and switch between them at runtime — timestamped service-log lines, git-log/commit entries, CI/build pipeline output, and a generic internal-tool layout
- [x] **DSGT-06**: The immersive cover extends to identity: author names and handles are replaced throughout by cover-appropriate aliases, and no real handle or display name is rendered anywhere on screen
- [x] **DSGT-07**: Alias mapping is deterministic, so an account keeps the same alias across screens, sessions and restarts, and no alias table is written to disk
- [x] **DSGT-08**: Immersive mode keeps the entire read surface usable with unchanged keys — timeline, pagination, threads, search, profiles and bookmarks all work under the cover
- [x] **DSGT-09**: Nothing in immersive or panic mode reveals the real product or its purpose: no product name, no status line, no hint text, no engagement counts, avatars or icons
- [x] **DSGT-10**: Actions that would break cover — opening a post in the browser, opening media, copying a handle-bearing URL — are unavailable in immersive mode unless the user deliberately leaves the cover first
- [x] **DSGT-11**: The active display state and cover style persist in the config file, and the user can choose which state the app starts in

## v1.x Requirements

Deferred until after v1 is validated in daily use, with a named trigger.

- **IMG-01**: User can render images inline in the terminal via the Kitty graphics protocol — trigger: media is opened often enough to care. Must detect capability via `TERM_PROGRAM`/`TERM` (never `KITTY_WINDOW_ID`), use Unicode placeholders plus DCS passthrough under tmux, request an explicit placement size, reserve the cells it occupies and force a repaint, and live only in a dedicated non-scrolling pane
- **CFG-01**: User can set reply/thread page depth from configuration — trigger: one-page replies feel too shallow or too slow
- **IMG-02**: User can manage a media cache with eviction — trigger: the Kitty renderer lands and the cache becomes a real directory

## Out of Scope

| Feature | Reason |
|---------|--------|
| Write actions (post, reply, like, repost, follow, bookmark) | Requires write-scope auth and irreversible side effects from a terminal tool, plus the largest step up in ToS exposure. Read-only is the deliberate posture; anything that mutates the account opens in the browser instead |
| Official X API | Pay-per-usage (~$0.005/post read) makes read-heavy browsing uneconomic; the free tier cannot support reading |
| Background polling, streaming or tailing | Unbounded requests with no human trigger, maximum bot-detection surface, and it silently rewrites what you are reading. Manual refresh plus an "N new posts" banner is the replacement |
| Direct messages and notifications | Turns a quiet reader into an attention machine; a bell or a flashing title is visible to everyone around the desk. Not part of "read the feed quietly" |
| In-terminal video or audio playback | Pulls in decoders, animation timing and audio in a shared office; `mpv` already does it better |
| Inline images in the timeline by default | Breaks the plain-text promise and is conspicuous in exactly the setting this tool exists for. v1 opens media externally; see v1.x `IMG-01` |
| Notification badges, unread counts, terminal bell | Attention machinery, and visible to the room |
| Algorithmic feed as default, infinite scroll | The exact behaviour this project exists to escape, and it maximises upstream traffic. Following by default; every paginator is keyed and finite-feeling |
| Multi-account switching or an account pool | Single-user tool; rotation exists to dodge rate limits at scale, which is the opposite of the promised restraint, and it multiplies the secret-handling problem |
| Timeline cache, read-state or history on disk | Leaves a browsing trace, explicitly rejected. Disk is for bookmarks/likes only, and that must stay testable |
| Engagement metrics as first-class UI | The social-app signal. Counts are dropped in the list view; in detail they print as plain text with no glyph and no colour |
| Mouse-first interaction | Hit-testing and selection artefacts compete with "this is just text you can copy"; the user is keyboard-first in a tmux pane. OSC 8 hyperlinks keep click-to-open for free |
| Browser-cookie extraction (keyring/DPAPI) and browser-extension bridges | A per-platform, per-browser decryption matrix, or an install step plus a native host — large surfaces for a personal tool. A `0600` file plus an env override is the documented mechanism |
| Themes, skins, plugin systems, live palette watching | Unbounded configuration surface for one user, and theme-following is the "looks like a social app" failure mode |
| AI summarisation, read-aloud or translation | Exfiltrates post text to third parties, contradicting the privacy posture, and adds a network dependency inside the feed path |
| Desktop notifications / terminal title flashing | Conspicuous in a shared office |
| In-app media download manager (thumbnails, cache, GIF animation) | Storage management and animation timing for a feature that is delegated; the external opener can save a file when needed |
| Distribution as a packaged app, image or hosted instance | Internal-endpoint usage is against X's terms; personal, single-user, local only |
